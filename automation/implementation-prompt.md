# Implementation

共通契約に従い、監査指摘を計画へ反映してから、確定した対象を実装・検証してください。対象機能のソース・テスト・必要な設定とSPEC/STATUS/計画/指摘台帳を編集できます。

## 実装前

1. 実行slotと引継ぎを確認する。slot 1はPlan Auditの指摘対応から始め、slot 2はslot 1の残実装・検証を優先して継続する。
2. 指摘ごとに採否と理由を台帳へ記録し、採用した対応を計画へ反映する。計画上の穴は計画修正の検証でresolved、製品の修正が必要な指摘はplannedのまま実装へ進める。
3. 対象範囲のblockingを解消してから、選択ID・完了条件・検証方法をSTATUSに確定する。言語仕様の決定は創作せず、必要なら独立項目へ切り替える。
4. 重大な計画破綻があり局所修正では進められない場合は、理由と指摘を保存してreplanを返す。通常の難しさや修正可能なテスト失敗で計画作業へ逃げない。

## 実装・検証

- 必要な解析、Binding、型・Origin・所有権、lowering、ABI、生成、runtime、診断を接続する。独立した基盤項目は限定された完了条件で判定し、全機能の一括実装へ膨らませない。
- 既存の責務に沿って根本原因を修正し、不要な割り当てと保持参照を抑える。性能が重要な変更は代表入力で測定する。
- ハードコード、stub、例外の握り潰し、必要処理の省略で完成を装わない。テスト削除・skip化・条件緩和・警告抑制で成功を作らない。
- 正常系・不正入力・境界・回帰を検証する。近傍から始め、共通経路への影響に応じて全managed suiteへ広げる。コード生成・runtimeの変更は現行コンパイラーでfixtureを生成し、必要なIR検証とO0/O2通常native実行を行う。
- 今回の回帰は修正して再検証する。計画の検証条件を満たせなければ[x]にしない。未解決の懸念や変更がない限り成功済み検証を繰り返さない。
- 一つが完成し合理的に続けられるなら次の関連IDへ進む。終了前に検証・引継ぎの時間を確保し、部分変更と残作業を隠さず保存する。

## 完了と引継ぎ

全条件達成のIDだけ[x]にし、指摘の解消条件を検証してresolvedにする。SPEC/STATUSは必要な説明と実装状況を同期し、未実装を隠す規範変更はしない。STATUSに差分、検証、次の具体的操作を残す。

最終status:
- continue: 実装・検証に進める必須作業が残る。
- complete: 全必須ID・共通条件・必要な最新検証を満たし、未解消の必須指摘がない。Completion Auditへの提出であり完成認定ではない。
- replan: 重大な漏れ・依存誤り等のためPlanから見直す必要がある。具体的な指摘と次の計画修正を保存する。
- blocked: 全候補が外部情報・権限・仕様決定待ちで、有益な独立作業もない。

progressは今回の新しい実装・検証・原因究明を証拠付きで判定する。計画の整形や同じ試行の反復でtrueにしない。進展がない場合は次回変える仮説・操作を記載する。
