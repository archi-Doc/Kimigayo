# Completion Audit

共通契約に従い、必須範囲の実装が本当に完成したか検証してください。編集対象はAUDIT_FINDINGS.mdと必要なSTATUS.mdだけです。計画・製品コードを修正して監査を通してはいけません。

## 未完了の確認

1. 計画の必須[ ]、台帳の未解消指摘、最新ログの失敗を現行ソースで確認する。チェックが古いだけでもnot_completeとし、根拠を台帳へ記録してImplementationに同期を渡す。実装済みを再実装させない。指摘の解消済み化は証拠を確認して行ってよい。
2. 具体的な必須不足を確認したら、関連範囲の調査と再現・記録を行いnot_completeにしてよい。否定のためだけに高価な全検証を完走しない。未検証を成功や全体監査済みと報告しない。
3. 不足は根拠・再現条件・必要な修正・解消条件を台帳へ記録し、次のPlanへ渡す。未実装と検証不足を区別し、既存指摘の重複を避ける。

## 完成認定に必要な確認

- 全必須SPEC規則 → 計画ID → 実装 → 検証を照合する。全必須IDと共通完了条件を確認し、計画外の実装漏れも探す。
- 宣言・Binding・テストhelperだけでなく、必要な解析・所有権・生成・link・runtime・診断まで実パイプラインが接続していることを確認する。
- 正常系、不正使用の拒否と診断、境界、機能の組合せ、評価・cleanup順、失敗後再実行を確認する。CLI/LSP/拡張、backend、cache、CI・配布・examples、性能の必須条件も照合する。
- 現行ソースで全SolutionのDebug/Release buildと対応する全managed suite、必要なIR検証・O0/O2通常native・統合検証を実行する。必須のclean再現性は隔離した入力で検証し、未コミット変更も反映する。元の作業ツリーは消さない。
- fixtureと実行入力の対応、テスト件数・失敗・skip・警告抑制を確認する。過去ログや「後続の外部検証が通るはず」で代用しない。
- 必須指摘の解消を証拠で確認し、STATUSへ対象ソース・範囲・結果・対象外を保存する。重要な未実装・未接続・不一致・回帰・未検証・未決定要件が残れば認定しない。

最終status:
- verified_complete: 上記の全必須条件を実装と最新検証で確認した。next_task=null、finding_ids=[]とし、evidenceに具体的な検証結果とログを示す。
- not_complete: 修正・実装・検証追加が必要な具体的不足を確認した。finding_idsへ未解消IDを列挙し、next_taskで次のPlanが反映する内容を示す。
- blocked: 具体的不足を確定できる前に、外部条件で必須の監査・検証を実行できない。

具体的不足と外部制約が併存する場合はnot_completeを優先して両方を記録する。「反証が見つからなかった」「大半が成功した」だけで完成認定しない。
