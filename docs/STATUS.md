# Kimigayo Implementation Status

Implemented support and limits, by area. [SPEC.md](SPEC.md) defines required behavior; limits listed here never narrow it. The plan and milestone order are in [PLAN.md](dev/PLAN.md). Earlier dated records are in git (`git show 32324537:STATUS.md`).

## Summary

- **Asynchronous tasks (SPEC Chapter 24, §22.1.3, IMPL §21.6; 2026-10-04):** specified, not implemented. The tokenizer still reports every `;` as `SemicolonNotAllowed_Kd`, so the task slot and task argument `task;` are not parsed; task calls, the `Kimi.Async` group, the internal `Kimi.TaskBoundary` group and the coroutine lowering do not exist, and `TaskSlotPosition_Kd`, `TaskArgumentMismatch_Kd` and `TaskSlotShapeMismatch_Kd` are not reported. `open` is still a reserved keyword in the tokenizer, although SPEC §2.5.1 makes it contextual, so it cannot yet be a Name.

- **Complete object payload Copy reads (2026-10-04):** a bare `@follow` of an eligible obj/rc handle or object borrow reads through the same checked payload projection as an explicit borrow. Direct, stored and temporary handles, aggregate snapshots and generic Copy-constrained borrowed views execute; snapshots outlive the owner while exclusive Loans still reject conflicts. Non-Copy payloads require a borrow and receive no Transfer repair because payloads offer no Take. Fixed warm ownership and IR emission allocate zero bytes (`ObjectPayloadReadTest`).

- **Fixed Closure result Origins (2026-10-04):** concrete calls may return Copy results retaining fixed external Origins carried only by Copy captures, including references stored in fixed arrays, Tuple/Option results and shared object views. Result Loans survive the environment's last use or destruction, while unrelated argument/slot Loans end normally (`ClosureResultOriginTest`). Fixed warm binding, ownership and emission allocate zero bytes. Receiver-dependent results are described below; equal lifetime names never substitute for a capture's authority.
- **Receiver-dependent Closure results (2026-10-05):** a Shared or Exclusive call's result over the closure's environment depends on the call receiver, the closure Place the call lends (SPEC §15.8.2, §15.6.4, §7.6.3): a borrow of an environment binding (`func [n] () => n@ref`) becomes a borrow of that Place, also through a reference receiver (`g = f@ref`, then `g()`) and for a call on the closure literal itself, and an external Origin reached through a Non-Copy capture or kept by a Non-Copy result, such as a Reborrow of a captured exclusive reference (`func [view] () => view`, `view@follow@ref`), is met with that Place; a Copy of a captured shared reference keeps its external Origin, results over per-call inputs substitute the arguments as before, and a Consuming call that moves a captured reference out returns it with its own Origin. The result keeps the receiver lent while it lives, so a Move of the closure, a temporary closure's destruction, a write of the captured referent and a second Exclusive call while the first result lives are `ComparisonLoanConflict_Kd`; these calls were `UnsupportedBinding_Kd` (G65; `ClosureResultOriginTest`, native O0/O2, zero-allocation warm phases). The erasure of a closure whose result borrows its environment is one `UnprovenOriginContract_Kd` at the converted value whose longer end is the `closure` display `call receiver`, related at the anonymous function's header, with a Note that a common Function value cannot return a borrow of its hidden environment receiver (SPEC §7.6.4, §23.3.6.5); it was displayed as a borrow of the closure's source text. An environment Origin carried by no capture that is not a fixed Origin of an enclosing function, and a receiver that is no closure Place, stay a located `UnsupportedBinding_Kd` at the call.
- **Origin relations (SPEC §15.6.1, §15.6.5, §23.3.6.5; 2026-10-05):** a fit that holds structurally but not in an Origin part is no Type mismatch. At returns, block results, `if`/`match` arms, assignments and local annotations it is reported at the value that supplies the longer end: Refuted as `UnsatisfiedOriginRelation_Kd` (Language) when a body-local Borrow must outlive a fixed Origin, and Unknown as `UnprovenOriginRelation_Kd` (Proof) between fixed Origins; `static` outlives every finite Origin and inferred region of the body. Any other chain with a finite Origin or an inferred region at one end, which the spec proves and leaves to region inference, is a located `UnsupportedOwnership_Kd` at the value (2026-10-05), including a fixed input over a local Borrow (`let h: ref/i32 during r = x@follow@ref`, which would lose the Loan on `*x`): ownership keeps Loans only through the Origins written in a holder's Type, and accepting the chain let a use after a Move pass (`let r: ref/string during h.s = w@ref` then `eat(w@move)`). The Reason holds `relation`, `longer` and `shorter` as Origin displays (an Origin expression, `p.a` for the omitted slot of a parameter's Type, the borrow `local@ref` with its related location, or an omitted slot's Type occurrence), `source` (`fit`, `declared` or `wellFormed`) and, for a fit only, `destination` (2026-10-05: `declared` and `wellFormed` records carried a placeholder `during` text), and JSON values carry the display kind. A local annotation's slot is judged by the slot's variance, `==` at an invariant one, at the initializer (`let h: H{x} = h0@move` with `origin x.s == b` and `h0: H` over `a` requires a outlives b; it was a fact-less `UnprovenConstraint_Kd`), and so is every slot nested in a Type argument, by the generic slot's variance composed with its position (`W<H{x}>` with `W` storing `uniq/T` requires `==`, and `R<H{x}>` with `R` storing `(T) -> i32` reverses the relation), at local annotations and value-call arguments alike (`k(h0@move)` for `k: (H{q}) -> i32` was a fact-less `UnprovenConstraint_Kd`; the invariant and contravariant forms were accepted, and a write of a shorter borrow through `W` failed only at generation), and also where an exclusive target under a Type argument leaves the fit to one Binding record (`R<uniq/H{x} during q>` from `R<uniq/H{hw} during p>` requires `a == b`; it named the covariant `p outlives q`, which the position does not need). A clause of a local, Field or Case that does not hold is a `declared` record relating the clause (role `relation`), at the initializer when that supplies one of its ends and otherwise at the clause (it was `InvalidOriginBinding_Kd`); a Case's clauses bind its payloads' sets (`One(V<i32>{v})` with `origin v.source == a` was `MissingOriginBinding_Kd`), a payload Type that fails leaves the Case's clauses unbound, as a Field's does (they added a Language `InvalidOriginBinding_Kd` beside the unresolved name), and a struct's or enum's own clause (`origin a outlives b`) is accepted in a program without another Error (it was a fallback `PrerequisiteUnavailable_Kd` at the clause) and stays a premise that each formation of the Type must prove: a local annotation proves it substituted with the Origins its Type binds, also for a Type nested in a Type argument, and each substituted clause that does not hold is a `declared` record at the Type occurrence relating the Type's clause, whose Advice is the enclosing function's premise or other Origins for the Type (`let s2: S{w} = s@move` with `w.a == r`, `w.b == q` and no `r outlives q` was accepted), an independent problem beside a failed fit into that Type; an omitted covariant slot is the meet of the initializer's Origin and its clauses' upper bounds, so `origin b outlives x.s` is accepted and keeps `b`'s Loans (2026-10-05, `LocalOriginClauseTest`, native O0/O2). Advice offers a premise, a result bound only where the value is a result source (the inner result for an inner position), binding to `static` (as `x: ref/i32 during static`, never for an exclusive input), a set for an omitted Origin, and similar visible names for a misspelled signature Origin; for a declared relation it names the enclosing function's or Type's clauses with the clause's relation (`outlives` or `==`), and in an anonymous function, which has no clauses, the bound on its own input or the clauses of the named function whose Origins it captures; the §15.4.3 Note stays. A meet's body-local operand is shown by the Borrow that supplies it, also through the local the value reads or moves (`(a and a@ref) outlives static` after `let h0 = H.init(a@ref)`; it showed the text of the whole function binding the borrowed parameter). A relation that ownership analysis judges (a local annotation, well-formedness at a Type occurrence, a Type's clause at a local annotation) is one record per failed chain, and the Loan checks of the body continue, so an independent Loan conflict stays visible. A borrow of a slot that holds a reference (`r@ref` with `r: ref/T`, of a local, parameter or temporary) depends on that slot rather than on the stored reference, so returning it is Refuted; it was accepted and dangled. A result join waits for every source before choosing a borrow Type and takes the meet when no source Type fits all under the premises, so `if c => n@ref else => z` or a labeled block exiting with both is accepted with both dependencies (2026-10-05, `OwnershipJoinTest`). Limits: reassigning a borrow local to another body-local Borrow (`var r = z@ref` then `r = n@ref`) needs local-region inference (SPEC §15.4.4) and is a located `UnsupportedBinding_Kd`, as is any fit whose only unproven Origin part is a chain the relation judge accepts; `var r = z` with a fixed parameter `z` keeps that fixed Origin, so `r = n@ref` there is Refuted; a relation found by Binding still stops ownership analysis, so an independent Loan conflict in that body, and a relation that ownership judges anywhere, such as a local annotation's slot in another function, is reported only once the relation is fixed; a clause that bounds an inferred contravariant slot from below is a located `UnsupportedBinding_Kd`, since local inference does not choose the lower bound that outlives the others (SPEC §15.3.6); a Type's own clause that a call's result or a Field's Type does not prove is still `UnprovenConstraint_Kd` without facts (`S.init(p, q)`, a Field `inner: S{z}`), and a local annotation does not enter a Function Type, neither its inputs nor its result (a value call through such a Type whose argument fits only through a premise stays the located `UnsupportedBinding_Kd` of value calls); limits of these records (2026-10-05): an `obj` target is still judged covariantly, as in every fit until P33 makes `obj` invariant (SPEC §15.3.5), so a record at an `obj/H{x}` local names `outlives` and the premise its Advice offers is accepted although the position needs `==`; a closure whose input is bound by another input's Origin (`func (p: ref/i32, q: ref/i32 during p)`), which the Advice of a declared relation in an anonymous function may suggest, is a located `UnsupportedBinding_Kd` at each call; and one missing relation can give two independent records at one declaration, the Type-clause record and the slot fit, with different Advice; a meet at the longer end is one record, not one per failing operand (`(a and a@ref) outlives static`); the well-formedness record of a local annotation's nested borrow whose inner Origin is a set the local's clause binds shows that Origin as `the omitted Origin of Unbound` (`R<uniq/H{x} during q>` with `x.s == b` and no `b outlives q`); call arguments still judge Origin parts during applicability (`NoApplicableOverload_Kd`), and callers of a result-only signature Origin get `UnprovenConstraint_Kd` without facts; a signature's result-Type well-formedness is checked as a definition obligation instead of being a premise, so SPEC §15.6.5 `pickRelated` is rejected; borrows of mutable static storage are unsupported (`InvalidAssignment_Kd`, P36) (`OriginRelationDiagnosticTest`).
- **Escaped block-local borrows (SPEC §15.6.2, §15.6.5, §16.2.2; 2026-10-05):** a borrow of a block-local root that leaves its scope in the block's value or a closure capture (`exit to block n@ref`, `exit to block func [n@ref] () => n@follow`), or of a temporary kept past its statement (`let r = make()@ref`), is one `ComparisonLoanConflict_Kd` at the transfer or statement whose cleanup destroys the root. It relates the value keeping the Loan (`loan`) and, where it is found, the Borrow or capture entry that created the Loan (`borrow`): a conversion (`n@ref`, `n[0]@ref`, `make()@ref`), an implicit Borrow (the `arr` of `for x in arr`) or a capture entry (`[n@ref]`), reached from the escaping value through its operands, the one definition of a Place it reads (`let q = n@ref` then `exit to b q`, a nested block's value, a captured `[q]`, a `match` binding), a call result to the input its Origins name (`Holder.init(n@ref)`, a loop item) and a construction's payloads (`(n@ref, 1)`); a Place with several definitions ends that search, and the record then relates only `loan` and its Note says that a live value keeps "its Loan". The Note names the destroyed Place and, for a transfer, that cleanup precedes delivery; the Advice declares the root in a longer scope or keeps an owned value. The label's join, which precedes the destruction in operation order, added a second record before, and so did an exit that delivers another source's borrow while destroying the root (`if c => exit to block z@ref`), also in generic bodies with requirement results or conditional reborrow plans; neither does now, a second destruction for the same value adds none, and a destruction in code checked after a transfer is reported unless a reachable one is (`BlockEscapeLoanTest`). Limits: reassigning an outer local to a block-local borrow (`r = n@ref` inside a `do`) stops at the located `UnsupportedBinding_Kd` above; several roots destroyed by one exit share one record, which names the first; where the flow walk does not decide the holder (a holder whose Type has an abstract part, a conditional reborrow's Place or a requirement result's holder in such a generic body, a holder with a stored-borrow record, or one changed in a form the walk does not follow), every destruction the Loan reaches keeps a record relating only `loan`, as before 2026-10-05, so an exit delivering another source's borrow is reported there too; a borrow of a block-local slot that itself holds a reference (`let q = z@ref` then `exit to b q@ref`) still also records the label's join, as before, since the end of a reference slot is not a destruction of storage.
- **Specified by the P26 decisions, not yet implemented (2026-10-05):** a result through a stored exclusive reference is bounded by the receiver or parameter borrow it is reached through (SPEC §15.6.3), and since 2026-10-05 a method such as `get(self: ref/Self) -> ref/i32 during self.a => self.view@follow@ref` over `view: uniq/i32 during a`, or a `bad`-style exclusive form (§15.5), is rejected at its returned expression, while body-local paths keep their ownership ancestry and `preserves results` implementations stay independent (`StoredReferenceResultBoundTest`), as an Origin relation such as `(self.a and self) outlives self.a`; `UnprovenOriginContract_Kd` is reported for common Function conversions only, not yet for Contract conformance and specialization comparisons, and its `requirement` and `declaration` related locations (§15.6.1) are not yet added; an unsolved call slot is `UnprovenConstraint_Kd` rather than `UnboundTypeArgument_Kd` and blocks ranking instead of leaving its candidate rankable (§10.4, §10.6, §10.8); omitted nested Origins in local Function Type annotations and anonymous parameter Types are `MissingOriginBinding_Kd` rather than body inference variables (§15.3.4); `objref`/`objuniq` inputs of Function Types and anonymous functions are not quantified per call (§8.6); a call through an `F` with several distinct Callable signatures is one located `UnsupportedBinding_Kd` at the call rather than a selection among them (§8.6; it was `NotCallable_Kd` before 2026-10-05, `CallableSignatureSelectionTest`). A closure that fails its common Function conversion at a call argument or a default is shown by its signature with the conversion Note, as at a `let` annotation (it was `found closure ` without a Note; `ContextualClosureTest`). The `Owned` condition of that conversion is a Constraint failure (SPEC §15.2.3, 2026-10-05): a capture over a body-local Borrow (`func [text@ref] () => ()` at `() -> ()`, also at a default, a call argument or through a captured reference value) is `UnsatisfiedConstraint_Kd`, and a capture or bound Type argument not proven Owned (`identity` at `(T) -> T`) is `UnprovenConstraint_Kd`, at the converted value; the Reason names the `subject`, the `member` (the capture name or the n-th Type argument) and, when one is displayable, the `origin`, related at the capture entry or the Borrow; they were `TypeMismatch_Kd` with a Note (`ErasureOwnedDiagnosticTest`). A stored closure passed to a common Function parameter is still `NoApplicableOverload_Kd`, because the Owned condition takes part in applicability.
- **Published Function Places as callees (2026-10-05):** a common Function value published by a user-Indexable element (`m[k](5)` on a Dictionary) or by a Place result (`first(xs@ref)(5)`) is called through a shared borrow of that Place, which stays lent while the arguments run (SPEC §7.6.3, §7.1.1); these were `TransferRequired_Kd` before (`PlaceCalleeTest`). Exclusive calls through such Places remain unsupported.
- **Environment Places in closure bodies (2026-10-05):** an environment binding is a Place of its closure (SPEC §7.6.2, §15.8.2), so a closure body checks its Loans as an ordinary body checks its locals: a borrow of `[var n]` (`let r = n@ref` then `n = 1`), a call result over it, an exclusive slot borrow read early, a Reborrow through a captured exclusive reference (`let c = view` then `view@follow = 1`), shared borrows reached through it implicitly (`view[0]@ref` then `view.append(3)`), a write of its whole referent (`n@follow = 3` while `n@follow@ref` lives), a call result over its implicit Reborrow (`keep(view)` then `bump(view)`) and a nested closure's `[view]` entry are `ComparisonLoanConflict_Kd` or `CallActivationConflict_Kd`: an Origin that names no Place of the closure body is reached only through the environment bindings whose Types carry it, so its Loans fall on those bindings, which are roots like borrowed parameters. A result inferred from the body that borrows the call's own storage, a parameter or local of the closure or an environment binding of a Consuming call (`func [a@move, b@move] () => keep(a@move, b@ref)`, `func (x: i32) => x@ref`), is one `UnsatisfiedOriginRelation_Kd` at the returned value: the borrow outlives "the closure's call result", related at the Borrow and at the header (SPEC §15.8.2); it was accepted for Consuming closures and a Loan conflict at the closure otherwise. These were accepted, and the first observed the aliased write at run time. Loans end at the last use and stay per Field. A borrow of an environment binding's own slot (`func [n@ref] () => n@ref`) depends on that binding and is no fixed external result; it was accepted and outlived a Move of the closure, which is now a `ComparisonLoanConflict_Kd` at the Move, since the result borrows the receiver (`ClosureEnvironmentOriginTest`, native O0/O2, zero-allocation warm phases).
- **Collection and enum captures (2026-10-05):** environments hold bindings of every slot Type: enums such as `Option` and `Result`, Arrays, Dictionaries, Slices and raw pointers, captured by Copy, Move or a slot borrow (SPEC §7.6.2); they were `UnsupportedBinding_Kd` at the closure before. A borrowed Array keeps its Loan while the closure lives, and a user enum without `Self is Copy` is captured by an omitted list only by Copy (`CollectionCaptureTest`).
- **Closure receiver classification (2026-10-05):** only an explicit transfer of a capture (`b.items@move`, an owned receiver or by-value argument) makes a call Consuming (SPEC §7.6.3, §13.5.3). Bare `for` and `match` Subjects, shared receivers and borrowed arguments over a captured part only borrow it, so such closures are called repeatedly; a write, increment or exclusive receiver reached through a captured part's Fields or elements (`c.items[0] += 5`, `b.items.append(3)`) makes the call Exclusive. Before, these closures were classified Consuming and their calls needed `@move`. Ownership reports a Move out of a capture in a Shared or Exclusive call as `UnsupportedOwnership_Kd` (`ClosureReceiverClassificationTest`). `.length` and element reads through a Non-Copy part of a struct or Tuple (`b.items.length`) remain `UnsupportedOwnership_Kd` inside and outside closures.
- **Parenthesized callees (2026-10-05):** parentheses stay part of a referenced function name, so `(f)(1)`, `(Tools.inc)(1)`, `(c.add)(4)` and `(id<i32>)(2)` are ordinary calls under overload resolution (SPEC §12.4.2); they were `UnresolvedBinding_Kd` before. A parenthesized value is still called as a value (`ParenthesizedCalleeTest`).
- **Contextual captures (2026-10-05):** an anonymous function without a capture list never captures contextual `self` (of a method, accessor, constructor or destructor) or a setter's `value`; the use is `InvalidCaptureBinding_Kd` with the declaration related and Advice to name it in a capture list (SPEC §7.6.2). Such programs were accepted before, including a returned closure over `self`. An explicit `[self]`, `[self@move]` or `[self@ref]` in a constructor or destructor is the same code at the capture entry, because `self` is reached there only through its Fields; explicit captures elsewhere run (`ContextualCaptureTest`).
- **Value call activation (2026-10-05):** value calls activate their reserved exclusive arguments after the receiver's preparation, as ordinary calls do (SPEC §15.6.7), so a `ref/F`, `uniq/F` or owned Callable receiver, a borrowed common Function and a Consuming closure take bare or explicit `uniq` arguments; these passed `check` but failed generation before. The receiver and the Loans its environment holds stay protected through the call (SPEC §15.6.4): an argument that takes a Place the receiver's captures borrow is `CallActivationConflict_Kd`, which was accepted before (`ValueCallActivationTest`).
- **Results over borrowed inputs (2026-10-04):** a call result that names a borrowed argument's Origin, such as `h.get()` with `-> ref/i32 during self` while `h` holds `ref/i32 during a`, keeps the Loans that the argument's referent carries while the result lives (SPEC §15.6.1 well-formedness, §15.6.4). Writing the target of the stored reference then is `ComparisonLoanConflict_Kd`; such programs were accepted before and observed the write. A part borrow of a root keeps only its own referent's dependencies unless a call result in the same body names that root (`BorrowedInputResultTest`).
- **Input-dependent value call results (2026-10-04):** a value call whose result has no Origin, the static Origin or one over its fresh per-call inputs takes the arguments' Origins into that result, as an ordinary call does (SPEC §15.6.4): Item calls (`Box<i32>.get`), closures (`func (n: ref/i32) => n`), several inputs (an omitted result Origin over `a` and `b`), exclusive results (`uniq/i32`) and erased values whose result is over the inputs (`(ref/Box<i32>) -> ref/i32`, a stored closure erased to `(ref/i32) -> ref/i32`). Results retain the argument Loans, and an exclusive result reborrows its argument, so the parent may be used after the child's last use (`InputDependentValueCallTest`, native O0/O2). Warm binding, ownership and emission allocate zero bytes. Results whose Origins are all static (`() -> Option<ref/i32>`) substitute nothing and run through Items, erased values and Callable bounds (2026-10-05); a returned slot result shortened by variance keeps its storage. A contextual anonymous function at an Origin-bearing fixed signature (`let g: (ref/i32) -> ref/i32 = func (n) => n`, an assignment, a return, a payload, `if` arms or a common Function parameter) takes the fresh per-call inputs as its own inputs, also with `uniq` inputs and results over several inputs (`OriginContextualClosureTest`). A written header part that differs is one `TypeMismatch_Kd` with the expected and found signatures, and the omitted parameters no longer add an `UnresolvedBinding_Kd` cascade. Since 2026-10-05 a per-call input is one bound by the callee's own binder (its Item or closure declaration, or the Function Type itself; SPEC §8.6): an input or result written over a fixed Origin of the calling body, such as `func (n: ref/i32 during x)` inside `use(x: ref/i32)`, is fitted and kept as written, also inside Tuple and `Option` inputs and through a Function Type `(i32) -> ref/i32 during x`. Such inputs were taken for per-call inputs when their slot number matched the parameter's position, so `c(local@ref)` was accepted and its stored result dangled; it is now `UnsatisfiedOriginRelation_Kd` at `local@ref` (`InputDependentValueCallTest`, native O0/O2, zero-allocation warm phases). Callable proofs and common Function conversions apply the same rule to the implementation (SPEC §10.7): a closure or Function value whose input is written over a fixed Origin no longer satisfies `Callable<uniq, (ref/i32) -> ref/i32>` or converts to `(ref/i32) -> i32` (the Callable case read a dead stack slot); a per-call implementation still fits a required input over a fixed Origin (`CallableOriginForwardingTest`). The comparison instantiates each input that the implementation binds per call at the required input in the same position, per call or fixed, and compares every other input as written and the result under that instantiation, so signatures that mix fixed and per-call inputs (`(ref/i32 during x, ref/i32) -> i32`) convert, forward and satisfy Callable position by position, and a contextual anonymous function restates only the expected Type's own per-call inputs (a fixed `during y` input stays written). A common Function conversion of a Function value, a Function Item or an Owned Shared closure whose signature matches structurally and whose Origin contract fails is one `UnprovenOriginContract_Kd` (Proof) at the converted value (2026-10-05, SPEC §10.7, §15.6.1, §23.3.6.5): its Reason holds `comparison` (`conversion`), `member` (the n-th parameter or the result), `relation`, and `longer` and `shorter` under the call-time instantiation, so neither end is a call-time Origin of the implementation and a required per-call input is displayed as the omitted Origin of its Type occurrence, which is related; it was `TypeMismatch_Kd` with identical signatures, `UnprovenOriginRelation_Kd` over the implementation's own input, or an internal `CheckFaulted_Kd` for two failing inputs. A Callable proof still reports `NoApplicableOverload_Kd` at the call until the Constraint codes of §8.7 name the clause. A result is kept as written when each Origin is static, carried only by Copy captures of a Copy result (`func [rb] (n: ref/i32 during x) => rb`), or, carried by no capture, a fixed Origin of an enclosing function; a Non-Copy carrier makes the result depend on the receiver (see receiver-dependent Closure results). An argument at a body-local fixed Origin (`during r` for `let r = x@ref`) is the located chain limit at the argument, and one that fits a fixed-Origin input only through a premise (`c(z)` for `b: uniq/i32 during x` under `origin z outlives x`) is a located `UnsupportedBinding_Kd` at the argument, since ownership does not yet keep that argument's Loans for the fixed Origin's region (it was accepted, and a stashed or returned alias saw later writes); a call of a nested named function whose parameter is written over an input of the enclosing function is the same limit (`helper(z)` for `b: uniq/i32 during x`, 2026-10-05; it was accepted and printed the aliased write). A common Function value holds no Loan: the Origins of its signature constrain its calls only, so `f(x)` through `f: (uniq/i32 during x) -> uniq/i32 during x` is accepted (it was a false `CallActivationConflict_Kd`).

- **Local enum Origins (2026-10-04):** omitted borrow Origins in local enum annotations are inferred from acquired payloads, including nested aggregates and multiple payload bounds. The committed enum plan receives resolved Origins; explicit and published contracts remain fixed, and payloads retain owner Loans. Fixed warm rebinding allocates zero bytes (`EnumLocalOriginTest`). Shared object views read through safe reference layers, including borrowed enum payloads, preserve header identity and external owner Loans independently of the outer reference slot; fields and complete-payload member calls use the prepared receiver (`StoredObjectReferenceTest`, G66 resolved).

- **Owning object fields (2026-10-04):** `obj` handles read Copy fields and nested inline fields through a shared object view, and lend field storage for shared reads such as string arguments. Mutable owning paths also lend mutable fields exclusively; intermediate slot/object borrows share their argument's two-phase activation, while immutable/shared paths cannot gain exclusive authority (`ObjectExclusiveFieldBorrowTest`). Native tests verify header-relative addressing, single evaluation, complete cleanup and retained owner Loans; Tuple/struct/fixed-array slots, dynamic fixed-array indices, borrowed containers and concrete captures share protected slot-to-object views. Views prevent conflicting owner transfers/replacements. Direct and stored-field warm analysis/emission allocate zero bytes in the fixed workloads; physical emission records are rechecked on every pass (`StoredObjectViewTest`). Direct assignments, compound updates and increments now share the ordinary exclusive Field address and replacement plan (`ObjectFieldUpdateTest`); old Non-Copy Fields are destroyed exactly once. Owning roots must be mutable, and rc/shared paths retain read-only payload authority.
- **Strong object modes (2026-10-04):** Binding preserves obj/rc/arc modes in explicit base upcasts, accepts their shared base views, and diagnoses cross-mode conversions with the expected and actual Types (`ObjectHandleModeTest`). rc and arc creation/clone and final release execute through common object metadata/finalization, including concrete generic factories. arc updates the whole inline control with CAS, uses release ordering and a final acquire fence, and shares Sealed/dynamic cleanup. Count overflow reports the clone location before updating; clone allocates nothing. `SharedArcRuntimeTest` checks generated transitions, native lifetime/count boundaries and zero-allocation compiler reuse. Weak, side tables and cyclic factories remain unsupported; source threads are not introduced.

A returned borrow takes the declared result's Origin; any other result carries its own anchor Origin (2026-10-02), which fits every destination like `static` while ownership analysis resolves it to an external anchor Place, so accesses through the result, Reborrows from it and their children are checked under the anchor like those of a borrowed parameter's referent, and effect summaries compare its accesses with no earlier result (`RawPlaceAccessTest`, `EffectBoundImplementationTest`). `Kimi.Loan<T>` (SPEC §15.3.5, 2026-10-02) is the zero-sized dependency Field: it is formed only over a complete borrow Type (`InvalidTypeFormation_Kd` with a Note otherwise), a `Loan<T>` Field gives the slots it uses the borrow's Loan requirement and covariance instead of a Phantom Origin, and it is Copy exactly when `T` is Copy; a covariant view keeps a `raw/()` address beside it (`LoanFieldTest`). `Kimi.Raw.allocate`, `release`, `initialize` and `slice` (SPEC §5.6, 2026-10-02) execute natively: allocation Aborts on a negative or unrepresentable count, returns the nonnull substitute 4096 for zero bytes and rejects element alignment above 16, release ignores null and that substitute, and initialize moves scalar, string and aggregate values in without destroying anything; the Kimi library releases its buffers and places Dictionary values through them, replacing the internal `release` and `placeValue` primitives; slice writes the Slice record over the storage under a result-only universal Origin that the caller's expected Type fixes (`RawStorageTest`). Stored fields, Tuple elements and fixed-array elements of raw Places (`(*p).field`, `p[n][i]`) access only that part; computed array indices there are bounds-checked. String comparisons read raw strings in place. A zero stride displaces by zero, so `p ± n` is `p` and `p[n]` is `*p` (SPEC §5.3), including in generic `raw/T` bodies. Raw acquisition and replacement now preserve supported reference-containing pointees and their complete Origins, including generic reads and static scalar references; dependent Tuple/Case payloads use the same verified ownership and cleanup plans. Other non-consuming raw access of Non-Copy values remains unsupported.
- **C layout:** concrete C structs use written field order and ordinary LLVM structs; Kimigayo layout is alignment-sorted. Binding diagnoses `#Layout("C")` on open/derived/empty structs, direct concrete zero-sized fields and written generic applications that make a field zero-sized (`InvalidCLayout_Kd`); inferred instantiations reject at generation. C-exchangeability certification remains.
- **Composite generic values (Program 18):** owned Tuple/Case Patterns acquire complete array and struct payloads with user destructors; zero-sized values needing cleanup keep an aligned anchor.
- **Documentation comments:** the product uses the independent limited-profile Markdown parser, renderer and link resolution ([API](../src/Kimi/Compiler/Documentation/README.md)).
- **Reading through a reference (SPEC §3.3.6, §3.5.3, §10.2, §13.4):** implicitly, a reference chain ending in a read Type (a Scalar, position or range Type) is value-read where that Type is expected, and nested layers yield one shared reference at an expected `ref/U`; an Exact reference candidate outranks the read, a transferred reference (`r@move`) is never adapted afterwards, and a Non-Copy referent is never extracted. Aggregate referents are copied only with `@follow`: supported Copy structs, Tuples, fixed arrays and enums use fresh snapshots, including whole Copy fields and generic results. Nested reference Origins survive the Copy while the outer reference does not constrain an independent snapshot. `CopySnapshotTest` and `AssociatedForwardingTest` verify independent storage, comparison evaluation order, active enum payloads and retained Loans at O0/O2 (G11/G19 resolved).

### Aggregate and element coverage

The following subsections preserve the existing numbered entry points. These summaries describe the cumulative subset, rather than repeating old blanket struct/generic/borrow exclusions.

### 4.1. Aggregate Selection Results

Tuples/fixed arrays support if/do/loop/match results, local replacement, nested payloads and result transfer. Results are secured before cleanup and consumed only after the matching lifetime Join; no aggregate phi or result-specific flags are required. Abort/nonterminating cleanup prevents delivery. AggregateResultEmissionTest covers malformed plans, reload and measured warm reuse.

### 4.2. Tuple and Fixed-Array Function ABI

Ordinary owned tuple/array arguments and results use acquired argument/result slots, including nesting, Copy/Move, zero-size values, named calls and shallow recursion. Nonzero values pass by ptr; zero-size values retain semantic acquisition without physical storage. Arguments/results cannot alias; direct result-storage forwarding remains incomplete. Shared Loans end before result/parameter destruction under the checked plans.

### 4.3. Copy Element Reads from Tuples and Fixed Arrays

Numeric tuple selectors and isize fixed-array indices read supported Copy elements through checked addresses, including nested/static/dynamic paths, owners, parameters and temporaries. Receiver/index evaluate once; bounds and owner lifetime remain checked. Dynamic Non-Copy acquisition is not enabled.

### 4.4. Simple Assignment to Copy Elements of Tuples and Fixed Arrays

Initialized local var tuple/array elements support Copy assignment. The RHS is secured first, then location/bounds are resolved; an exclusive Loan covers old-value destruction and placement. Nested indices and zero-size elements retain evaluation and checks. Dynamic Array elements also support replacement through `uniq/Array<T>` parameters, locals and returned references. Fixed-array reference writes, other parameter/temporary mutation and initial construction through element writes remain unsupported.

### 4.5. Numeric Element Updates in Tuples and Fixed Arrays

Numeric compound assignments secure the RHS before locating the target once and reading the old value. Integer prefix/postfix inc/dec locate once and have no RHS. The exclusive target Loan protects the old-value read through writeback; aliases retained across that access must be compatible. Bounds/arithmetic checks and Abort/transfer cleanup remain independent of optimization. The earlier self-read allowance was corrected, not retained as valid behavior.

### 4.6. Loan Disjointness for Static Element Paths

Distinct tuple selectors/literal array paths permit independent operations under existing shared/exclusive Loans. Root protection remains during index evaluation; dynamic sibling paths use a conservative known prefix. Constant evaluation does not broaden the specified literal-only static Move/disjointness rule.

### 4.7. Non-Copy Element Replacement in Complete Owned Values

Complete initialized local var elements support replacement of strings/supported Non-Copy aggregates: secure RHS, locate under exclusive Loan, destroy exact old element, transfer responsibility and end Loan. No backup Copy/whole-parent cleanup is added. Noncompleting RHS skips location; bounds Abort does no destruction or placement. General user-drop/retained-reference element update plans remain incomplete.

### 4.8. Static Element Partial Moves, Reinitialization, and Destruction of Remaining Parts

Constructed owned tuple/array locals support static Non-Copy Move, sibling use, local var repair and whole acquisition after all missing parts are repaired. Construction and current completeness are separate. Sparse referenced paths and untracked remainders avoid array-length expansion; remaining parts destroy in reverse logical order with flags only where conditional. Unconstructed element writes, let repair, missing-part reads and dynamic accesses that may reach missing parts reject. Dynamic Non-Copy and temporary-element Moves remain unsupported.

Literal-only fixed-array paths also support in-place shared/exclusive borrows and
whole-value updates for supported scalar/aggregate referents. Nested inline paths
retain their actual Loan footprints; disjoint elements can be borrowed together,
and an initialized element can be updated while a sibling remains Moved. Storage
permission follows the containing Place, so an immutable element cannot be
silently copied into a mutable temporary for an exclusive update. Unknown index
relationships do not prove disjointness. Program 17 verifies the complete repaired
array's return and caller cleanup without extra element allocations.

### 4.9. Static String Element Comparisons and Shared Arguments

Static string elements of owned local tuples/arrays support all six comparisons and ref/string arguments without owned temporaries. BorrowStringElement protects the located path through later operands/arguments and cleanup; disjoint sibling operations remain possible. Constructed partially moved parents allow only initialized remaining elements. Dynamic Non-Copy shared-result paths and general retained-borrow dependencies remain incomplete.

### 4.10. Static String Element Borrowing from Owned Parameters and Temporaries

Static string borrowing also accepts owned parameters, construction/direct-call/selection results after their verified production/completion/Join. Owners live to the prescribed endpoint; ending the Loan does not destroy them early. Conditional production/cleanup and defer/loop lifetimes use validated flags. Temporary mutation/partial Move and unrestricted borrowed-receiver element paths remain unsupported.

### 4.11. Static Partial Moves from Owned Parameters

Owned tuple/array parameters support static Non-Copy element Move and use/borrow of remaining parts with actual argument storage. Parameters remain let-like: updates/reinitialization reject. Receipt initializes sparse-path flags; remaining parts destroy in reverse logical order after result acquisition. Dynamic Non-Copy acquisition and partial Moves from temporary/function/selection results remain unsupported.

## 7. Language Test Execution

`kimi test` accepts project/source/directory/solution inputs. It validates every selected body before filtering or listing, including ordinary startup bodies, without executing startup or requiring a product entry. TestSources and root TestDependencies participate only in test analysis; dependency tests are not discovered. `--list` creates no native artifacts. Solution execution builds all required project artifacts before launching cases and shares one jobs limit and total retention budgets.

`$expect` and `$require` use the existing ownership CFG: evaluate once, latch false before condition cleanup, evaluate the optional message lazily, clean up its temporary, then continue or send a distinct require-Abort. Concrete bodies and supported shared generic helpers lower these operations. Reports retain original scalar comparison bits, explicit nested-message identities and cleanup phases. Passing checks allocate no diagnostic storage in the child. `Kimi.Test.tempDirectory` returns an independently owned path captured before user code; TMP/TEMP name the same case directory.

Each case starts in a Windows Job Object with no breakaway, with EOF stdin and separately drained result/stdout/stderr channels. Deadlines, recovery grace, frame/detail/log budgets and whole-run limits are finite. JSON/text outcomes distinguish assertion failure, Abort, timeout, cancellation and management errors. Artifacts have canonical identities and executable hashes and remain pinned during execution. Result publication uses atomic rename; retention removes only recognized completed runs.

Debug/Release builds are warning-free and each full managed suite passes 9,144 tests. Native O0/O2 profile verification passes with deliberate failure cases checked against expected outcomes. `TestExecutionAnalysisTest`, `TestProtocolTest` and `TestProcessRecoveryTest` cover semantic isolation, malformed/stale records, zero retention, cancellation, missing completion and descendant recovery. `src/backend/windows-x64/test-testing.ps1` verifies O0/O2 execution, generic/integer/float snapshots, lazy/nested messages, cleanup, require-Abort, timeout, logs, temporary removal and solution barriers.

Existing compiler limits still apply to test bodies: general static storage/shutdown, full module/native input records and full generic resource-plan separation are unfinished (PLAN P36, T1 and T5). Supported source-module calls execute from root tests; dependency tests are excluded. Unsupported generation fails before case launch; listing may succeed for semantically valid code that the native backend cannot yet emit. Named execution profiles remain deferred by the specification. NativeAOT was not run.
