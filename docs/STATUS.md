# Kimigayo Implementation Status

Current supported subsets, known defects and remaining limits. [SPEC](SPEC.md) and [IMPL](IMPL.md) define required behavior; a limit here never narrows them. [PLAN](dev/PLAN.md) owns next actions and issue IDs, [CODEMAP](dev/CODEMAP.md) implementation navigation, and the [program catalog](../tests/milestones/README.md) individual milestone states. Update only changed boundaries under [AGENTS Documentation](../AGENTS.md#documentation).

**Conformance qualification:** the 2026-10-15 specification revision and follow-up changed language and implementation contracts. The recorded support below does not establish conformance to every revised rule; that audit remains PLAN S1015. The compiler still emits single-unit `kimi.check/2`, not the specified `kimi.check/3` command envelope. The 2026-10-17 and 2026-10-19 revisions of SPEC §15.6 (A5's simplifications and Loan identity by base; the Loan ending by exact Move-Path prefix; storage the body does not own following its holder; in §15.6.4, the widening of parameter-dependent effects on a projection with a recursive base, [INTEGRATED](../draft/INTEGRATED.md)) belong to A4 and A5, which decide acceptance since R6-check H5 (DECISIONS R5-M182, R5-M185) and are not complete (A4 widens since DECISIONS R4-M87; a recursive base G170 hides keeps its atom, and G170's false Copy at a two-step `CopyTree` projection rejects some valid callers in uninstantiable code).

Detailed historical descriptions and evidence references remain in [the pre-cleanup snapshot](https://github.com/archi-Doc/Kimigayo/blob/5287ae5058fbc355a8b39ee4685d83b5ebb857ad/docs/STATUS.md) and Git history. New unit evidence belongs in commits and `artifacts/verify/`, not in this document.
