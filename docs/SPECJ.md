## 1. 概要

### 1.1 目的

Kimigayoは、一貫性、速度、簡潔さ、安全性、使う楽しさを重視する言語である。旧版との互換性よりも、言語の一貫性と品質を優先する。

言語仕様はプログラムの正しさと意味を定める。実装仕様はビルド・実行・コード生成の契約、STATUSは検証済みの実装範囲を定める。実装上の制約で言語規則を狭めてはならない。

```kimi
alias Kimi.Console

group Geometry
    func area(width: i32, height: i32) -> i32
        let sides = [width, height]
        return sides[0] * sides[1]
```

### 1.2 表記

ユーザー定義の型・契約・宣言コンテナーは慣例としてPascalCase、関数・フィールド・プロパティ・変数・引数はcamelCaseを使う。組み込み型の綴りは固定する。

| 記号 | 用途 |
| --- | --- |
| `[]` | 配列・辞書、固定長配列型、添字、スライス、キャプチャー一覧 |
| `()` | 引数、タプル、Unit、関数型、条件、式のグループ化 |
| `<>` | 型引数、関数の長さ引数 |
| `{}` | struct/enumのOriginスキーマ、名前付き型の束縛集合。本文やコレクションには使わない |
| `=` | 初期化・既定引数・代入。値の取得にはCopy/Move規則を適用 |
| `@` | 明示的な適応、`@move`、`@copy`、`@follow` |
| `->` | 関数の結果型 |
| `=>` | 単一項目の本文、引数名の対応、コンテナー別名の対象 |
| `:` | 型注釈、名前付き引数、辞書要素、ラベル、基底・親契約、`: base(...)`。本文は導入しない |
| `#` | コンパイル時指示と属性 |
| `$` | 言語が提供するComposition Root操作。マクロではない |
| `;` | `task;`だけに使う |

型はSemantics、CoreまたはオブジェクトのView Target、および必要なOriginから成る。

### 1.3 規範性

完全な準拠実装は、有効なプログラムだけを受理し、規定どおりに実行する。部分実装は有効だが未実装の構文を`Unsupported`として拒否できる。無効なプログラムの受理、有効なプログラムへの別の意味の付与は許されない。付録Dの保留項目は構文や利用許可を与えない。

| 原文の表現 | 意味 |
| --- | --- |
| must / must not | 必須／禁止。違反時のコンパイルエラー・Abort・未定義動作は各規則に従う |
| may | 明示された条件内で許可 |
| should | 推奨。準拠の必須条件ではない |
| implementation-defined | 実装が許容範囲内で選び、その選択を文書化 |
| unspecified | 許容範囲内の任意の結果。文書化は不要。未定義動作とは異なる |
| undefined behavior | 以後の動作を規定しない。unsafeの約束への違反だけが原因となり、安全なコードだけでは起きない |

断りのない規則・要求は規範的である。例は新たな規則を追加しない。API例のシグネチャだけの記載は、本文なしの定義を許可しない。例は互いに独立し、アプリケーション固有の型・APIは定義済みとする。`// Error:`は意図的な違反例、`text`ブロックはKimigayo以外の表記を示す。

## 2. ソースと字句

### 2.1 ソースと行

ソースはUTF-8。不正なバイト列はコンパイルエラー。先頭のBOM（U+FEFF）は一つだけ許可し、本文には含めない。各ファイルはKotonohaのSourceDocumentである。改行はLF、CRLF、CRを認め、位置は1始まりの行・列で表す。列はUnicodeスカラー値単位。字下げ、継続行、本文の境界は付録Fに従う。

### 2.2 空白とコメント

リテラル・コメントの外で使える空白はU+0020と改行だけ。タブ、改行しない空白、その他の空白・制御文字はエラー。行末の空白は無視する。コメントはトークンを区切り、隣のトークンと連結しない。

- `//`は行末またはファイル末尾まで。
- `/* ... */`は最初の`*/`まで。入れ子にできず、閉じ忘れはエラー。
- リテラル内のコメント記号は文字列の内容。文字列補間内では通常の字句規則を使う。
- 同一行のブロックコメントはトークン間に置ける。字下げはコメント前の空白で決まる。改行を含むブロックコメントの終了行では、`*/`の後に空白とコメントしか置けない。

### 2.3 文書コメント

行頭の空白だけに続く`///`は文書行。ただし直後が`/`なら通常のコメント。`////`、コードの後の`///`、`/** ... */`も通常のコメントである。文書は意味・有効性に影響しない。

同じ字下げで連続する文書行が一つのブロックとなる。空行・通常コメントで終了する。宣言前の属性・空行・コメント列のうち、ヘッダーに最も近く、ヘッダー基準位置と同じ字下げのブロックだけがその宣言に付く。付かなければ以前のブロックへ戻らない。無関係な構文、指示、スコープを越えて探さない。推奨順序は文書、属性、宣言。

対象はコンテナー、名前付き関数・要件・特殊化、`init`、`drop`、プロパティ、局所を含む`let`/`var`、enumの各ケース、関連型。引数、ジェネリック・Originパラメーター、ペイロード、アクセサーの説明は親宣言に書く。各断片・オーバーロードは独自の文書を持ち、継承・override・要件実装・特殊化で文書を引き継がない。除外された構文には付かないため、条件付き宣言の文書はその条件領域の内側に置く。

内容はMarkdown。慣例として`- name: 説明`を使い、標準項目名は`return`、`abort`、`safety`、`note`、`warning`、`example`。対応Markdown、抽出、表示、文書診断は実装定義。

### 2.4 トークン

綴りは連続していなければならない。連結すると別のトークンになる箇所には区切りが必要。認識できるトークンでも、その位置で使えるとは限らない。いずれのトークンも始められない文字はエラー。最長一致、ジェネリックの`>`分割、記号一覧は付録Fに定める。論理演算は`and`/`or`であり、`&&`/`||`は常にエラー。

### 2.5 名前

名前の先頭は英字・`_`またはUnicode一般カテゴリLu/Ll/Lt/Lm/Lo/Nl、続きには数字とMn/Mc/Nd/Pcも使える。Unicode 15.0.0を基準とし、その版で未割当の文字、書式文字Cfは使えない。NFCでない綴りは自動正規化せずエラー。比較はスカラー列の完全一致で、大小文字を区別し、カルチャー・正規化・大文字小文字の折り畳みに依存しない。見た目が似た名前も別名。条件名にも同じ規則を適用する。

`_`単独は名前ではなく、次の場合だけ使える。

| 場所 | 意味 |
| --- | --- |
| 実行時パターン | ワイルドカード |
| 最後の`#case _` | その他の条件 |
| 初期値付き局所の`[_ of T]`、`[N of _]`、`[_ of _]` | 長さ・要素型の推論 |
| `_ = expression` | 明示的な破棄 |
| `for`の束縛またはそのタプル要素 | 名前を付けない反復値 |

`let _`、`var _`、引数名・参照としての`_`はエラー。`_value`などの長い名前は通常どおり使える。

### 2.6 数値リテラル

ASCII数字で始まり、型接尾辞はない。符号は演算子だが、リテラルに直接付いた符号は直接リテラルの型決定に含める。型は文脈または`123@i32`などから決まる。整数は10進、および`0b`・`0o`・`0x`（大文字も可）。区切りの`_`は値に影響しない。基数接頭辞直後の複数の`_`は許されるが、数字が一つ以上必要。

小数点の直後と指数の符号直後には10進数字が必要。`1.`は整数`1`と`.`、`1e_2`は不正。数値の直後に名前の継続文字があれば、不正な一つのトークンとして扱う（`123abc`、`0b102`など）。浮動小数点数は正確な10進値からf32/f64へ一度だけ最近接・偶数丸めを行う。無限大になる値はエラー。ゼロ・非正規数は許可する。その他は整数で、絶対値が2¹²⁸−1を超えるとエラー。

### 2.7 エスケープ

| 表記 | 値 |
| --- | --- |
| `\0` | NUL（U+0000） |
| `\\` | バックスラッシュ |
| `\e` | ESC（U+001B） |
| `\t`、`\n`、`\r` | タブ、LF、CR |
| `\"`、`\'` | 二重引用符、一重引用符 |
| `\u(H...)` | 1〜6桁の16進スカラー値 |

U+10FFFF超、サロゲートU+D800..U+DFFF、不明・未完のエスケープはエラー。二つのサロゲートエスケープを組み合わせることもできない。

### 2.8 文字

`'A'`のように単引用符で囲む。一つのUnicodeスカラー値を直接またはエスケープで書き、型は`char`。表示上の一文字とは限らず、結合文字単独は許可する。正規化しない。一重引用符、バックスラッシュ、U+0000..001F、U+007F..009F、U+2028、U+2029はエスケープ必須。補間はない。`''`、`'ab'`、`'e\u(301)'`、`'🇯🇵'`はいずれも一つのスカラー値ではないためエラー。

### 2.9 文字列

型は`string`で、内容はUTF-8。両形式とも複数行にまたがれる。

| 形式 | 区切り | エスケープ・補間 |
| --- | --- | --- |
| 通常文字列 | `"..."` | あり |
| 生文字列 | 同じ個数の3個以上の`"` | なし |

文字列には、終了区切りと通常文字列の未エスケープの`\`を除く任意のスカラー値を直接書ける。文字リテラルの制御文字制限は適用しない。各ソース改行は一つのLFとなる。字下げ、最初・最後の改行を除去せず、正規化もしない。CRには`\r`を使う。

通常文字列の`\(expression)`は値のテキストを挿入する。通常の字句解析で対応する`)`を探し、内側の文字列・コメント内の括弧は数えない。補間内の字下げは付録F、深さの上限は実装定義。

生文字列の開始位置では連続する`"`をすべて数える。1個は通常文字列、2個は空文字列、N≧3個は長さNの生文字列区切り。開始列を分割しないため、内容の先頭を`"`にはできない。後に初めて現れるM≧N個の引用符列で終了し、先頭M−N個は内容、末尾N個は区切りとなる。短い列は内容である。したがって`""""""`は空の生文字列ではなく未終了の開始区切り。隣接する文字列は連結しない。

```kimi
let text = "合計: \(price * quantity)"
let path = """C:\Users\name\file.txt"""
let tail = """text""""              // 内容は text"
```

## 3. 型と値

型は**Semantics（所有・借用などの意味）＋Core（値の種類・構造・同一性）＋Origin（借用の寿命）**で決まる。一層は`Semantics/Core during Origin`と書く。Coreの要素・型引数も完全な型であり、内部の借用やOriginを保持する。オブジェクトの対象には、Coreの代わりに実行時契約ビューを置く拡張もある（現版の制限は§8.12）。省略は明示された推論・省略規則だけで認める。

### 3.1 基本型

Scalarは通常整数12種、`f32`・`f64`、`bool`、`char`、ラッピング整数12種の閉じた集合。ソース上の型名ではない。`string`、Unit、NeverはScalarではない。「整数型」はownerの通常整数を指し、ラッピング整数を含める場合は明記する。

| 型 | 格納ビット数 |
| --- | --- |
| `i8`、`u8`、`bool` | 8 |
| `i16`、`u16` | 16 |
| `i32`、`u32`、`f32`、`char` | 32 |
| `i64`、`u64`、`f64` | 64 |
| `i128`、`u128` | 128 |
| `isize`、`usize` | 対象のポインター幅 |

`bool`の有効なビット列はfalseの`0x00`とtrueの`0x01`だけ。他の表現をboolとして読むと未定義動作になる。

**ラッピング整数。** `::Kimi.Wrapping<T>`はTと同じ表現・値解釈を持つ別のScalarであり、算術オーバーフローを2ᴺの剰余にする。Tは通常整数、ジェネリックなら`T is PrimitiveInteger`の証明が必要。float、参照、Wrappingの入れ子は不可。ローカルで同名の型を定義してもこの扱いにはならない。公開コンストラクターやメンバーはなく、リテラル・演算・変換で作る。Tや別のWrappingとの暗黙変換はなく、どちらにも適合するリテラルのオーバーロードは曖昧となる。

WrappingはCopy・Owned・Sealed・ObjectPayload・読み取り型であり、Tの比較・UTF-8書式・算術契約に適合する。符号なしでもNegatableに適合し、`&`・`|`・`^`を使える。一方PrimitiveInteger・Positionではなく、添字、範囲境界、前置`^`、配列長、定数添字、シフト量には使えない。

**文字と文字列。** `char`はU+0000..D7FFまたはU+E000..10FFFFの一つのスカラー値。未割当の値も有効。UTF-8の1バイトではなく、u32と同じ表現とも限らない。`string`はUTF-8テキストで、owner/stringはNon-Copy。レイアウトは実装定義。

**UnitとNever。** `()`は値が一つのUnit型。記憶領域が0バイトでも初期化状態と寿命を持つ。`::Kimi.Never`は値もコンストラクターもない型で、`return`・`exit`・`continue`・`yield`・`$abort`の式型である。各転送のオペランドは転送先へ結果を渡す。他の制御式がNeverになるかは、全結果源と構造的完了を検証して決める。実行時に到達しないだけでは結果を省略できない。Neverは完了状態ではなく型である。

NeverはCopy・Owned・Transferableだが、Sealed・ObjectPayload・PrimitiveInteger・Callableではなく、他の契約にも適合しない。型引数、フィールド、タプル・配列要素、enumペイロードに置けるが、Neverをインラインに格納する値やケースは構築不能。それでもmatchの網羅性ではそのケースを除外しない。`Result<i32, Never>`でもErrの分岐が必要となる。

### 3.2 複合型と呼び出し可能値

名前付きCoreは`A.B<T, U>`のように修飾できる。入れ子の型は、使っていないものも含め外側の正規化済み束縛を保持するが、外側インスタンスは暗黙に持たない。

`()`: Unit、`(T,)`: 1要素タプル、`(T,U)`: 2要素タプル、`(T)`: グループ化。関数型の引数列はタプル型とは別で、`(T)->U`と`(T,)->U`はTを一つ、`(())->U`はUnitを一つ、`((T,))->U`はタプルを一つ受け取る。`task;`は引数ではない。

| 呼び出し可能値のCore | 契約 |
| --- | --- |
| Function Item | 解決済みの関数宣言・実体化を一つ指す。キャプチャーなし、Copy、Shared呼び出し。束縛引数が条件を満たすとOwned |
| 具体的クロージャー | 匿名関数の式と実体化ごとに固有の型。同じ式・型引数なら評価ごとに同じCore。全キャプチャーがCopyならCopy。環境にユーザーのdropは定義できない |
| 共通関数型`(A...)->R` | Ownedな環境を型消去して所有するNon-Copy値。Shared呼び出しだけを公開し、環境に依存する借用結果は返せない。引数・結果自体はOwnedでなくてもよい |

具体型はCallableジェネリクスを通しても受信者・寿命の契約を保持する。共通関数型への変換はその契約を満たす場合だけで、変換結果が環境の後始末を所有する。taskスロットの有無は型同一性の一部で、相互変換できない。直接の借用入力で省略したOriginは呼び出しごとに束縛される。明記したOriginと既に束縛された内部依存は固定。空の環境は純粋性・無割当・並行安全性を意味しない。共通関数値へのrefはCopy、uniqはNon-Copyだが、呼び出し能力を追加しない。

**Weak。** `Kimi.Weak<s/T>`はsがrc/arcだけを許すコンパイラー管理のNon-Copy struct。対象はObject Targetで、外側はowner。ペイロードを所有せず、弱参照一つの責任を持つ。移動は`@move`、複製は`Kimi.Intrinsics.clone`。フィールド・dropは置き換えられない。空値はなく、不在にはOptionを使う。期限切れも存在するWeak値である。分散・Loan・OwnedOriginsの解析では常にSを格納したものとして扱う。対象へアクセスするにはupgradeが必要で、直接のメンバーアクセス、オブジェクト借用、`is`、cast、ビュー変換はない。

**Optional。** `T?`は名前探索に関係なく`::Kimi.Option<T>`。`??`は入れ子を保持し、平坦化しない。

| 表記 | 展開 |
| --- | --- |
| `ref/T?` | `Option<ref/T>` |
| `ref/(T?)` | `ref/Option<T>` |
| `[N of T?]` / `[N of T]?` | `[N of Option<T>]` / `Option<[N of T]>` |
| `(T)->U?` / `((T)->U)?` | `(T)->Option<U>` / `Option<(T)->U>` |
| `ref/T? during a` | `Option<ref/T during a>` |

Originの付着を決めてからOptionalを展開する。束縛集合は`View<T>{v}?`と書き、`View<T>?{v}`や重複接尾辞は不可。`(A)? -> B`も不可。名前専用の位置には使えず、`is Dog?`・`T?.Some`・`@ref?`は無効。`x@ref/T?`はOption型への適応であり、借用やSomeの生成ではない。暗黙のSome化、展開、既定値、引数省略はない。`raw/T?`のNoneとSome(null)も別の値。

### 3.3 Semantics

| 分類 | 表記 | 意味 |
| --- | --- | --- |
| value | `T`、`owner/T` | 値を直接所有 |
| valueborrow | `ref/T`、`uniq/T` | 値への共有借用／排他的な変更可能借用 |
| object | `obj/T`、`rc/T`、`arc/T` | 単独所有／非原子的参照計数／原子的参照計数のオブジェクト |
| objectborrow | `objref/T`、`objuniq/T` | オブジェクトへの共有／排他的借用 |
| 分類なし | `raw/T` | 生ポインター |

追加の分類はborrow＝ref/uniq/objref/objuniq、owning＝owner/obj/rc/arc、reference＝owner以外（rawを含む）。以上7分類だけを定義する。分類名はペア束縛子に対する要件では予約されるが、それ以外では通常の名前。分類自体は型や適応の略記にならない。

ジェネリックのSemantics位置を占められるのは`<s/T>`のペア束縛子sだけ。分類は外側一層を検査し、`owning`は再帰的なOwnedとは異なる。`reference`は安全な借用を保証しない。`s is owning or borrow`はrawだけを除く。

`ref/(rc/T)`はハンドルを置くスロットを借り、`objref/T`は対象オブジェクトを借りる。値借用は格納されたポインターを自動追跡しない。共有借用は複数共存できるが、排他的借用に競合する利用は共存できない。オブジェクトは動的ペイロード・型情報・所有責任を保持するが、ヒープ配置は必須ではない。rc/arcは強参照がある間生存する。原子的計数は並行変更を安全にはしない。

**ビューと同一性。** オブジェクトビュー型はSemantics、静的なView Target、借用なら外側Originを持つ。具体ペイロードにはObjectPayloadが必要。Sealedな対象はペイロード全体であることを証明する。動的型は構築したCoreで固定。実行時同一性はCoreからOriginだけを再帰的に消し、型引数中のSemanticsは残す。したがって`Box<ref/i32 during a>`とb版は同一だが、`Box<i32>`とは異なる。

ビュー変更や全体置換で動的型・同一性・破棄責任は変わらない。同じアドレスへの新規構築は別のオブジェクトである。Supports(D,V)は動的型D自身、その基底、対応する実行時契約ビューとの関係だけを示し、アクセス権・Owned・Loanの証明にはならない。値のスライシング、owner/ref/uniqの派生→基底変換、コンテナーの型引数共変はない。オブジェクトのupcastは明示する。

**入れ子とOrigin注釈。** ref/uniq/rawは完全な型を包む。`during`は同じ注釈型の最初の明示Semanticsへ、なければ直接書いた名前付き型の唯一のスキーマ欄へ付く。括弧・別名・型引数の内側を探さない。借用層またはペア層だけが対象で、一つのAnnotatedTypeへ一回だけ付ける。グループ化で再注釈はできない。正規化は別名、括弧、冗長なownerを除くが、参照層は残す。外側のCopyは内部の排他的権限を複製しない。

通常の取得は参照先を読まない。明示的な`@follow`、メンバー等の経路選択、限定された値読み取りを使う。安全な参照に`*`は使えず、参照経由でNon-Copy値を取り出せない。

### 3.4 Placeと記憶領域

**Place**は記憶場所とその完全型・経路・権限・依存を表す。値ではないため、格納・引数渡し・Option化はできない。Read、Write、Takeは別の権限。所有値のletはTakeできてもWriteできず、uniqの参照先はWriteできてもTakeできない。子Placeの型は親のSemanticsに置き換わらない。

アクセス指定はPlace、getter呼び出し、エラーのいずれかを一度だけ選ぶ。取得やLoanの検査に失敗しても別経路へ戻らない。外側が安全な借用ならBorrow value、その他のPlaceならOwned Place、残りならOwned temporaryとして扱う。ハンドルやrawのスロットもOwned Placeである。受信者式とはメソッド構文の受信者などを指し、`Type.method(self: ...)`の通常引数、代入先、match/forの対象には受信者の省略規則を適用しない。

**貸出点。** `P@ref`・`P@uniq`はP自身を借りる。Pが参照を格納していてもスロットを借りる。再借用は参照先、オブジェクト借用はオブジェクト、followした借用はペイロード、基底投影は基底部分を貸出点とする。寿命を守るために保護する所有者は、貸出点そのものではない。排他的借用にはその場所への排他的書き込み権限が必要。

**参照経路の選択。** メンバー・添字・メソッドは、要求する宣言を完全型が持つ最初の層で止まる。持たなければref/uniq、またはvalue/valueborrowだけを許すペア層をたどる。オブジェクト層はView Targetの宣言を持つためそこで止まる。各層の権限・Origin・Loanを保持し、選択は型だけで決める。制約で形が決まらないジェネリック型は終端であり、実体化後に探索し直さない。

bare取得、単名束縛、型推論は参照先を選択しない。更新要求は選択された経路だけをたどり、添字式内部や関数・getterの背後には伝わらない。子Placeの取得は子自身の値種別に従う。受信者式以外で所有Placeを排他的に貸すには、そのPlaceに`@uniq`/`@objuniq`を書く。`holder@uniq.items`はholderを借り、itemsを借りる表記ではない。

### 3.5 Copy・Move・再借用

Copyはユーザーコード・割当・参照計数変更・資源獲得を行わず、値を複製して元を初期化済みのまま残す。Moveは値と破棄責任または借用の権限を移し、元をMovedにする。ユーザーコードは実行しない。

| Place Pからの取得（上から適用） | 動作 |
| --- | --- |
| bare、型がCopyと証明済み | Copy |
| bare、外側が`uniq/U`または`objuniq/U` | 同じSemanticsで再借用 |
| bare、その他 | エラー。`@move`が必要 |
| `P@move` | Copy型でも移動し、PをMovedにする |
| `P@copy` | Copyの証明が必要。移動はしない |
| `P@ref`、`P@uniq` | P自体への借用 |
| 一時値のbareまたは`@move` | 値をそのまま移す。余分なCopy/Moveはない |

初期化・代入・引数・結果・集約要素・ペイロード・既定値・キャプチャー・破棄に同じ規則を使う。明示取得後の暗黙適応は最大一つ。Copyが証明できないからといって暗黙Moveや借用にはしない。`@owner/T`やオブジェクト作成・upcastもPlaceを暗黙Moveしない。Copy能力はlet/varやLoanとは独立だが、実際の操作は読み取り・移動の制限とLoanに従う。

**格納された排他的参照の再借用。** bare取得は、`P@follow@uniq`または`P@objuniq`に相当する子の借用を作り、Pは移動しない。子Originは親以内で、Loanの系譜、初期化、スロット保護、破棄依存を保持する。子が生きている間の競合する親利用は禁止し、最後の利用後に親を再利用できる。letや引数に格納したuniqでも可能だが、共有経路`ref/(uniq/U)`からは排他的に再借用できない。

外側の排他的参照だけを再借用する。Option・struct・配列全体には適用しないが、`[r]`は要素rを個別に取得する。格納する子は形成時から生存し、呼び出しの受信者・引数になる子は呼び出し予約を作る。`r@copy`は不可、`r@move`後の適応はrを復活させない。直接適合する明示移動済みの排他的参照は、再借用せず移す。

| 型 | Copy条件 |
| --- | --- |
| 整数・Wrapping・float・bool・char・Unit・Never | 常にCopy |
| ref・objref・raw・Slice・Function Item | 常にCopy |
| FromEnd・Start・End・Range・ClosedRange・ResolvedRange | 常にCopy |
| `Loan<T>` | TがCopy |
| クロージャー・タプル・固定長配列 | 全構成要素がCopy |
| uniq・objuniq・obj・rc・arc・UniqSlice・共通関数型・Weak | Non-Copy |
| Array・Dictionary・owner/string | Non-Copy |
| ユーザーstruct/enum | 明示的な適合宣言が必要 |

ユーザー型は`Self is Copy`または`Self is Copy when P`で適合を宣言する。structでは独自フィールドと直接基底、enumでは全ペイロードがCopyであり、ユーザーdropを持たないことを全許容束縛で証明する。派生型ごと、ペイロードなしenumでも宣言が必要。フィールドが全てCopyというだけでは適合せず、Copy実装本文も書けない。未知のCopyをNon-Copyと決め付けず、制約を勝手に補わない。rc/arc/Weakの複製はcloneを使う。

**値読み取り。** 読み取り型はScalarまたはPosition/PositionRange適合型。ジェネリックではPrimitiveInteger・Position・PositionRange、あるいは有効なWrappingの証明が必要。期待型が読み取り型の値位置、結果、組み込み演算、bool条件、所有受信者、数値変換などで、安全な値参照層の終端をCopyできる。オブジェクト、raw、フィールドは自動追跡しない。全層の初期化・権限・Loanを検査し、余計な変換や借用は加えない。代入先は参照先へ転送しない。読み取り型でないCopy値を参照から複製するには`@follow`を明示する。

### 3.6 一時値

一時値は永続Placeではない式結果。必要時の実体化は一時Placeを与えるだけで、再評価・Copy・割当・寿命延長を伴わず、失敗した消費を読み取りへ変えない。新たに所有した一時値は通常排他的に書き込めるが、getter結果などの制限は残る。

寿命は最外の式の終了まで。引数の一時値は呼び出し終了まで、match/forの対象評価中に作った一時値は構文全体の終了まで生き、対象の後に作成の逆順で破棄する。他の一時値も逆順に破棄し、途中の転送にも後始末を行う。部分Move後は残った部分だけを破棄する。各条件評価は寿命境界。借用・Slice形成で一時値の寿命は延びない。結果値はスコープ終了処理の前に確保する。

### 3.7 OriginとLoan

Originは借用が有効なプログラム点の集合（領域）、LoanはどのPlaceをどの権限で借りるかを記録する。`origin a outlives b`と`origin a == b`は領域間の関係であり、同じOriginだから同じLoanや権限を持つわけではない。シグネチャ・型宣言に記し、局所では推論する。

### 3.8 型関係

正規化された型同一性は構造、宣言、型引数、Semantics、Origin束縛を比べる。束縛Originパラメーターは対応する束縛子で比べる。名目的に別の宣言は同一型にならず、実行時オブジェクト同一性とも異なる。

唯一の部分型規則は、Origin以外が同一で、その各位置が分散を満たすこと。共変なら元Originが先Originより長く、反変なら逆、不変なら等しい。数値拡大、uniq→ref、派生→基底、Wrapping↔整数は部分型関係ではない。Neverも他型の部分型ではない。

Never式は、有効な任意の期待値型に値変換なしで適合できる。これは部分型関係ではなく、完了しない経路で外側の値操作も実行しない。関数型の結果Neverを別の結果型へ置き換えられるという意味ではない。型関係自体は借用・Copy・Moveを許可せず、寿命も延長しない。型が一致しても取得やLoanに違反すれば失敗し、名前探索やオーバーロードをやり直さない。
