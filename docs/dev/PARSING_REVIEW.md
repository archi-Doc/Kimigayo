# Lexing and parsing review — 2026-10-03

A review of `src/Kimi/Compiler/Lexing` and `src/Kimi/Compiler/Parsing` (≈21,000 lines: tokenizer, token reader, the static `Parser` and the Koto syntax tree) for responsibilities, defects, maintainability and measured cost. It follows the parsing review of 2026-10-02 (regions, function headers, `#switch` arms; PLAN_HISTORY). The SPEC is the authority, with Appendix F as its syntax summary and DIAGNOSTICS.md §4.4 for syntax records; tests and the current implementation were not. Five read-only reviewers covered the tokenizer, declarations and the reader, executable bodies and expressions, Types and Origins, and directives and the tree infrastructure; every defect below was reproduced through the CLI against the pre-change compiler (`c1284acf`) before it was accepted. The commits hold the reproducers and regression tests; DIAGNOSTICS.md §4.4 states the recovery rules the units established.

## Responsibilities and invariants

| Part | Responsibility | Invariants it keeps |
| --- | --- | --- |
| `Tokenizer` | Source text to tokens, including the layout tokens `Separator`, `StartBlock` and `EndBlock` (SPEC 2.2), the lexical records (encoding, characters, literals, comments, indentation, closers) and the decision whether `<` opens Type arguments (SPEC 2.4, 12.4.2). Documentation line ranges when collection is enabled (SPEC 2.3.6). | Tokens are in source order and span their text as written; layout tokens are empty. Every `StartBlock` has an `EndBlock`, and every opener has a written or synthesized (`IsMissing`) closer before what follows its grouping; a closer that closes nothing keeps its kind and is marked `ClosesNothing`. An unpaired surrogate stops tokenizing with one record. |
| `TokenHelper`, `TokenKind` | Spellings and keyword classification (SPEC 2.5.1). | Every kind below `Alias` is a reserved word and never a Name; `Alias` through `Identifier` can be Names (`IsIdentifierOrContextualKeyword`). |
| `TokenReader` | A cursor over one token sequence with lookahead; the syntax-record primitives (`Expect`, `Missing`, `Unexpected`, `ExpectLineEnd`, `ExpectCloser`) and skips (`SkipListItem`, `SkipCurrentBlock`, `SkipHeaderLine`); Name reading (`TryReadName`); the declaration prefix that crosses node construction (pending attributes, modifiers, exclusion) and the grammar restrictions of the current region. | A token is blamed once; the first form missing at an insertion point is the problem; passing a synthesized closer recalls the tokenizer's record; every skip stops at the end of its grouping or body. |
| `Parser` (static, partial) | Recursive descent for declarations, statements and Types, and a Pratt parser for expressions (SPEC 13.1), building Koto nodes with source spans and recording every recovery node with the key of the Error it stands for (`CodeContext.RecordRecovery`) and every dropped declaration (`OmitDeclaration`). | Valid source records no recovery. A node ends at its last written token. Excluded syntax (SPEC 19.5) is parsed with the selected grammar, under the same headers, and registers nothing. Each loop makes progress; the parser never throws for source errors. |
| Koto nodes | The syntax tree, which Binding later annotates; source text through `WriteTo`; children through `ChildNodes`, `VisitChildren` and `ReplaceChild`. | A child has its parent set. A node constructed with the reader takes the pending attribute chain; an attribute where the grammar takes none is recorded as a recovery before that. |

Callers: `Kotonoha.ParseSource` and `CodeContext.Parse` (source documents), `KimiLibrarySources` (cached library tokens and signature parsing), `KimiLibrary.CreateAbort` and `BoundIteration` (synthesized nodes through a reader), `Parser.ParseInterpolatedString` (a nested tokenizer over each interpolation), `StringLiteralHelper.GetStringLiteralValue` (literal values for Binding and emission).

## Structure

- **One decision per question.** Whether `<` opens Type arguments is decided once, by layout, in the tokenizer (`d87ea079`); the parser no longer rescans. Keyword classes follow SPEC 2.5.1 as plain ranges (`d9c5e46a`). Declaration Names are read by one rule (`TryReadName`, `ParseDeclarationName`; `92b6cb9b`), and whether a Container keyword starts a declaration by one predicate (`IsContainerDeclarationStart`; `de6b657b`).
- **Recovery helpers instead of ad hoc skips.** `ExpectCloser`, `SkipListItem` and `SkipOne` keep recovery inside the grouping that failed and skip nested groupings and bodies whole; `RecoverItem` states the list rule (the item before skipped text is the recovery, never the whole literal); `OmitDeclaration` drops a failed header with the body it would introduce and records the omission; `ReportPendingAttributes` and `HasWrittenAttribute` state the attribute rule once. Single-kind `SkipUntil`, `SkipUntilStartBlock`, `SkipUntilInLine` and the `RootGroup` stop of `SkipCurrentBlock` are gone (`55fa89a4`, `92b6cb9b`).
- **Directives.** A `#switch` is scanned once and reports every header, structure and Condition problem; its unselected marker is the recovery of that Error; excluded members are parsed under their container's header (`198c085a`, `8f88d85c`).
- **Dead code removed.** The lexer's unused lead-character entries and `KeywordToTokenKind` (`d9c5e46a`); `TokenKind.RawStringLiteral`, `SingleLineComment` and `MultiLineComment`, which no token has; `Token.IsValid`; `FunctionKoto.HasGenericDeclaringType`; `InvocationKoto.SetArgumentLabels`; a pass-through `ReplaceChildCore`; and the `Multiline*` string scan results, which no caller read and which rescanned every literal for line breaks (`6a6d88d2`).

## Performance

Measured with an interleaved, pinned A/B harness with tiering off over the 71 milestone and Kimi library sources (`artifacts/benchmarks/20261003-parsing-review`), against `c1284acf`: tokenizing takes 0.453 ms instead of 0.447 ms (median of four rounds, +1.3%, consistent across rounds and not attributed to a unit), and parsing about 2.08 ms instead of 2.02 ms (minimum 1.97 against 1.94 ms), close to the run-to-run spread. Parsing allocates 2,891,832 bytes per pass instead of 2,891,789. Bisecting that number across the units found one regression of the review itself: `ParseTypeConstraint` boxed a nullable error key for every Constraint parsed after an Error (+572 bytes per pass, `a4ec3678`), fixed in `3e6789d0`. The quadratic Type-argument lookahead of the old tokenizer is gone (`return a<b` 265 ms → 0.40 ms, `d87ea079`). Two non-terminating parses introduced within the review (`func f<!>` and `for (key, value}) in m`) were caught by the fuzz differential and fixed in `55fa89a4`; neither `c1284acf` nor the final front end hangs on any of the inputs. Removing the unread `Multiline*` scan results saves a rescan per string literal; that saving was not measured separately.

## Open findings

Reproduced, not repaired in this review; each needs its own unit or a decision.

- **Layout recovery (tokenizer).** Invalid indentation after a bare modifier outside a grouping still needs review. Outer-aligned chains, shared header delimiters, over-indented grouping content, wrong-kind closers and lexical causes for swallowed closers are repaired by the follow-ups below.
- **Types.** `?` after `(i32)`, `[2 of _]` and `v@move` needs rechecking against the later annotation grammar. Fixed-array lengths, Origin recovery and missing `is` in a conditional conformance are repaired by the follow-ups below.
- **Directives.** Diagnostics on a stacked `#if` prefix of a single-item target carry no `excludedBy` (`#if linux` / `#if missingName` / `func f()`), and an unavailable modifier in excluded syntax never enters an excluded region: the region starts after the prefixes; nested ranges per pending directive are needed. An invalid item in a `#switch` arm list is skipped unchecked.
- **Lexical details.** Nested interpolation problems are all an unterminated string; invalid characters are classified inconsistently and tabs cascade. Escape ranges, Tuple-index suffixes and generic-closer splitting are repaired by the follow-ups below.
- **Binding cascades from dropped syntax.** Names from a dropped declaration or list item (a parameter, a generic parameter, a capture, an enum member) are unresolved at their uses, and the children of a recovered node bind without the context of its form; a property with an unresolved Type and a setter `storage = value` overflows the stack (a separate task).
- **Structure not changed.** The declaration prefix still crosses node construction as reader state, and any Koto built with the reader takes the pending attribute chain; returning the prefix as a value would remove the remaining implicit attachments. `Parser.cs` (≈3,900 lines) was not split into feature files, to avoid moving code that parallel sessions edit. Interpolations are still scanned by the tokenizer and again by the parser, and `ParseInterpolatedString` allocates two lists per literal.

Escape-range follow-up (2026-10-08): the shared character-escape decoder records the consumed escape rather than its entire literal or interpolation segment. Equal errors at distinct positions remain distinct. `StringDiagnosticTest` covers repeated malformed escapes, Unicode syntax/scalars, physical line endings, interpolation segments, independent Binding errors, rebinding and CLI/LSP ranges; ordinary decoding and raw-string behavior remain covered by `StringLiteralHelperTest` and `CharLiteralParseTest`. Ranges come from the existing scan's remaining length, without another scan or substring allocation.

Layout follow-up (2026-10-08): an outer-aligned closer remains in its logical line through following comments/newlines and leading-dot continuations. Shared header delimiters close after their body, unless an aligned `else` joins it; a missing closer no longer captures the following statement. Extra indentation inside a grouping that starts no body reports the indentation without synthesizing a body. `LayoutRecoveryTest` covers retained scopes, independent errors, CLI/LSP output, native execution and zero-allocation pooled tokenization. Its allocation check exposed boxing in the runtime's generic Unicode range search (96 bytes per tested lexical pass before full optimization); a vectorized surrogate search removes it without changing warm-up policy. `SourceEncodingTest` checks vector boundaries, scalar tails and valid/invalid surrogate sequences; before/first-fixed allocation traces are retained under `artifacts/verify/g55-g60-baseline/`.

Lexical-boundary follow-up (2026-10-08): Tuple indices use the ordinary malformed Name-continuation rule, with one shared finish path. Generic closer splitting consults the immutable original token: only the remainder of a split shift-assignment can supply a second closer from its comparison-shaped remainder. This follows the existing SPEC 2.4 rule; the spec's Tuple examples clarify its existing 2.6 rule. Char decoding checks every escape, sharing the string decoder, and scalar-count checks depend on successful decoding. The old conformance test that expected one record for two invalid surrogate escapes now requires two separate ranges for both literal kinds. LexicalBoundaryTest and the existing literal/conformance tests cover valid/rejected forms, adapters, native execution and allocation-free lexical reuse.

Conditional-premise follow-up (2026-10-08): ParseTypeConstraint always retains its clause and reports a missing is through Syntax.IsKeyword, including in when lists that do not use prefix lookahead. Binding checks recovered Constraints at its common entry and records conditional-target prerequisites from failed premises. ConstraintRecoveryTest verifies that a malformed trailing premise cannot provide conformance evidence, while independent errors and the next declaration remain visible; the syntax corpus covers both insertion and found-token cases.

Unterminated-token follow-up (2026-10-08): chars and block comments now share the string path's invalid opening token and delimiter-prerequisite recording. An absent argument or closer caused by the failed scan cannot produce an independent overload/grammar failure. Char diagnostics use the opening quote rather than the swallowed line. LexicalRecoveryTest covers nested groupings, omitted operands, retained following declarations, physical line endings, source isolation, rebinding, adapters and native repaired counterparts.

Delimiter follow-up (2026-10-08): a written closer matching an outer grouping supplies the intermediate missing closers before ending its own grouping. A closer with no matching opener names the innermost required closer and relates its opening; that grouping remains available to a later correct token, and its eventual missing closer depends on the wrong-kind failure. The malformed path searches the stack and insertion point once. DelimiterRecoveryTest covers deep nesting, exact records and repairs, retained later declarations, rebinding, CLI/LSP output and native repaired counterparts.

Fixed-array follow-up (2026-10-08): array Types scan their complete arithmetic length once and share the compound-length grammar check with fill literals. Rejected length syntax cannot become length evidence. Missing array heads do not invent 'of'/element failures; a written element still binds as a Type independently of a malformed length. Recovered Type combinations keep their child contexts and establish no bound Type. ArrayTypeRecoveryTest covers exact causes, retained element/next-declaration failures, repeated Binding, adapters and a native parenthesized counterpart; existing length, fill and annotation-inference tests retain their semantic checks.

Origin follow-up (2026-10-08): malformed binding sets, borrow suffixes, grouped/projected Origin atoms and relation operators retain their syntax cause. A rejected annotation establishes no Type, while its payload still receives normal Type checking. Origin declarations retain a failed-clause cause, publish no partial premises and cannot default pending slots from an unavailable contract. Unknown Origin fits in that environment depend on the failed clause; refuted lifetimes and structural Type mismatches stay independent. OriginRecoveryTest directly checks that a misspelled operator never proves outlives, and covers calls, returned values, repeated Binding, CLI/LSP output and a native valid counterpart.
