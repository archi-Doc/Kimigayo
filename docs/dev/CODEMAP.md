# Compiler Code Map

Navigation for compiler changes, not a specification or support matrix. Required behavior is in [SPEC.md](../SPEC.md) and [IMPL.md](../IMPL.md); verified coverage is in [STATUS.md](../STATUS.md). Entries are starting points, not exhaustive change or test selections. Follow callers and shared data before editing.

## Implementation map

Compiler review obligations are in [COMPILER_ARCHITECTURE](COMPILER_ARCHITECTURE.md#code-rules); code size has no caps.
[ArchitectureRulesTest](../../tests/xUnitTest/Tests/ArchitectureRulesTest.cs) owns the retained structural ratchets.
The analyzer and CompilerSizeBudgetTest were retired (DECISIONS CR-R1); no live owner provides their former reports.
[`verify.ps1`](../../scripts/verify.ps1) owns build/test execution and input stability;
[`verification-selection.ps1`](../../scripts/verification-selection.ps1) owns selector normalization, discovery checks and the executed-test count;
[`verification-inputs.ps1`](../../scripts/verification-inputs.ps1) owns source/NuGet manifests and Git-normalized matching;
[verification-native.ps1](../../scripts/verification-native.ps1) reads native success evidence (VerificationNativeTest.ps1);
[`verify-commit.ps1`](../../scripts/verify-commit.ps1) associates successful evidence with exact committed inputs;
[`compare-fixtures.ps1`](../../scripts/compare-fixtures.ps1) compares two runs' fixture evidence (behavior-preserving commits).
The matching script regressions are VerificationSelectionTest.ps1, VerificationInputsTest.ps1 and FixtureComparisonTest.ps1.
[test-scalars.ps1](../../src/backend/windows-x64/test-scalars.ps1) owns native fixture selection and aggregation;
[test-scalar-fixture.ps1](../../src/backend/windows-x64/test-scalar-fixture.ps1) compiles each optimization level;
[test-scalar-process.ps1](../../src/backend/windows-x64/test-scalar-process.ps1) owns executable lifetime and oracle comparison
(NativeFixtureRunnerTest.ps1).
MirBuilder.Formatting owns formatting expansion with Test, Guard and Observe condition operations.

The main path is source input → Koto syntax → Binding → control-flow/ownership analysis → physical emission model → LLVM IR → native tools. Checking stops after the front end; generation and native execution have separate entry points.

`HirTables.HasCurrentBinding` owns whether a resolved node's Binding facts are current; SemanticQuery and Binding read
it directly. Koto's forwarding property (removed at R7, DECISIONS R5-M9) preserves syntax-side readers and the original lazy-initialization order.

Phase and dependency rules, the canonical component of each concern, structure limits and the compiler reduction stage ledger are in [COMPILER_ARCHITECTURE.md](COMPILER_ARCHITECTURE.md); the design decisions behind them are in [DECISIONS.md](DECISIONS.md).
Whole-value updates share `OwnershipAnalysis.Updates.WholeValueUpdate`; the distinct `OwnershipOperationKind`
`ReplaceBorrowed`/`ExchangeBorrowed`/`SwapBorrowed` entries feed initialization and `OwnershipBody.Updates`.
`WholeValueTest` checks storage-form agreement and source-independent initialization.
Call inputs and result-source rules are recorded by `OwnershipAnalysis.Calls` and retained in `OwnershipBody.Calls`;
`CallArgumentMappingTest` and `ReturnedBorrowAncestryTest` cover parameter order and source-independent queries.
`OwnershipFlow` supplies transfer correspondence to dependency/authority policies; `BorrowLiveness` owns live-holder
results. `OwnershipAnalysis.Cleanup` records cleanup observation, and `SharedEngineTotalityTest` covers the flow table
and runtime/checking edge distinction.

Paths below are relative to [src/Kimi](../../src/Kimi/).

Tokenizer layout transitions and surrogate scanning are covered by `LayoutRecoveryTest`, `HeaderDelimiterContinuationTest` and `SourceEncodingTest`; literal escape ranges by `StringDiagnosticTest`, shared unterminated-token recovery (`RecoverLexicalToken`) by `LexicalRecoveryTest`, and wrong-kind closers (`PopIndentSource`) by `DelimiterRecoveryTest`.
`Tokenizer.CountIndentation` shares physical-prefix and recovery-column measurement with lookahead; `IdentifierHelper` distinguishes a failed starting scalar from an invalid Name. `LexicalLayoutRecoveryTest` covers their recovery, public records and allocation behavior.
Fixed-array length grammar and Type/length recovery cross `Parser.Syntax`, `Binding.Types` and `Binding.Lengths`; see `ArrayTypeRecoveryTest` and `ConstantLengthBindingTest`.
Origin syntax recovery crosses `Parser.Origins`, `Binding.Origins.Annotations`, `Binding.OriginDeclarations` (pending slots) and `Binding.OriginDeclarations.Failures` (failed contract causes), with dependent fits in `Binding.Diagnostics.Prerequisites`; `OriginRecoveryTest` and `DeclaredOriginSlotTest` check the proof and diagnostic paths.

Constraint recovery enters through `Parser.ParseTypeConstraint`, then the shared `Binding.Constraints.BindConstraint` guard and conditional-conformance prerequisites; `ConstraintRecoveryTest` and the syntax corpus cover these paths.

## Use and maintenance

1. Read the owning specification and the relevant row, then trace callers and shared plans. Locate filenames with `rg --files src/Kimi/Compiler -g '*Comparison*.cs'`; find consumers with `rg -n 'BoundComparison' src/Kimi tests/xUnitTest`.
2. Select related tests from their source, including allocation/reuse tests for hot paths. Follow [VERIFICATION.md](VERIFICATION.md) and [milestone programs](../../tests/milestones/README.md) for completion evidence; the table is not a complete verification command.
3. Update affected entries in the same commit as changes to feature placement, phase responsibilities, entry points or listed source/test names. Add a row only for a distinct navigation need; retain representative entry points rather than cataloging every helper.
4. Verify changed links, file stems/globs and method names against the checkout. Keep requirements in SPEC/IMPL, support boundaries in STATUS and detailed diagnostic rules in DIAGNOSTICS; link to them instead of copying their content.
