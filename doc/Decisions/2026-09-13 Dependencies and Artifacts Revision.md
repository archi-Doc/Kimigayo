# 依存・成果物仕様の追加修正案の採否

2026-09-13。利用者の N1–N12、Q1–Q6 を検討し、採用部分を[設計書](../Design/2026-09-13%20Dependencies%20and%20Artifacts.md)へ反映した。本書は理由の記録であり、現行規則と例は設計書に集約する。SPEC.md と compiler 実装は変更しない。

## 1. 採否

「修正採用」は目的を採用し、表中の条件・代案へ変更したものを指す。

| 案 | 判定 | 反映先と理由 |
| --- | --- | --- |
| N1 同版の別内容を発行しない | 修正採用 | §4.4。既知の発行済み ID／Version → SourceId を永続管理し、pack・取得時に照合。編集可能な Project の identity まで Package と統合する部分は不採用 |
| N2 lock は構造と Package 内容だけ | 採用 | §3。ソース snapshot は入力記録、取得場所は現在の設定から求める。`--locked` で Project 編集を禁止しない |
| N3 native symbol の事前検査 | 修正採用 | §7.3。必要な archive の全 member と生成 object を検査。名前の重複だけで一律拒否せず、COFF の解決・統合規則を確認する |
| N4 restore を一本化 | 修正採用 | §3。両区分の結果を一括保存。テストだけの失敗を製品から隔離し、test は製品・テスト両方の成功と現在の構造を確認する |
| N5 空の依存に lock を要求しない | 修正採用 | §3.1。コマンドが必要とする区分の空グラフを暗黙の解決結果にする。テスト依存だけで通常 build に lock を要求しない |
| N6 ID に設定の実効値を使う | 修正採用 | §2.4、§3.3、§5.1。各 ID の対象範囲で実効値を確定する。利用側の target／compiler まで SourceId に入れて配布の独立性を失わせない |
| N7 ノードと宣言を二段で対応付ける | 修正採用 | §5.2。版を除くのは再利用候補のキーだけ。別版の型・symbol・Entry の identity と、現在の前提の検査は維持する |
| N8 pack で全 target・両 mode を必須検証 | 修正採用 | §4.1。全面検証の必須化は不採用。`pack --verify-all` で明示できる形にし、利用可能対象と検証済み環境を分ける |
| N9 パッケージ閉包をストアに揃える | 採用 | §2.3、§4。既存 Package もコピーし SourceId で重複排除。Store は既知 SourceId の直接取得に使い、版や内容を探索しない |
| N10 native 設定を要求と供給に統一 | 修正採用 | §7。供給は NativeLibraries の一表。直接 import のない要求の一律拒否は不採用。補助 native 依存を表現できるようにする |
| N11 パスの Unicode 規則を固定 | 採用 | §4.2。SPEC と同じ Unicode 15.0.0、NFC 必須、default simple case folding 後の NFC を衝突キーにする |
| N12 atomic 公開と記録の回収 | 修正採用 | §3.3、§4.4。上書き禁止の公開と pin による回収保護を採用。記録には再構築に必要な構造・設定も残し、発行済み版の対応表は回収しない |
| Q1 manifest から SourceId を計算 | 修正採用 | §4.3、§8.1。全 entry の完全性検証後に管理ストアで再利用。外部ファイルや read-only 属性だけを信頼して検証を省くことはしない |
| Q2 ソース位置を意味から分離 | 修正採用 | §5.5。製品の token 参照と現在の位置表を分ける。token 列だけを意味の証拠にせず、束縛・実効環境・依存を照合する |
| Q3 テスト到達分だけを出力 | 採用 | §6.2。計画と予算を先に確定し、initializer・cleanup・Provider 等の生成依存も含めて出力範囲を絞る |
| Q4 native staging の内容単位の共有 | 採用 | §7.2。検証済みの不変コピーを共有し、可変な元ファイルとの hard link は使わない |
| Q5 複数環境の字句共有・並列検証 | 採用 | §8.1。共通 snapshot の不変な字句情報を共有し、環境別状態を分離。同時実行数とメモリを制限する |
| Q6 fileId・サイズ・更新時刻による hash 省略 | 不採用 | §8.1。同じ属性のまま内容を変更できるため、変更を見落とす。確認方法を記録しても誤判定は防げない |

## 2. 元案から変えた主な点

### 2.1 対応付けと内容一致は別の役割

N1 の発行済み版の不変性は、編集中の Project の固定や ProjectSnapshotId と SourceId の同一視を意味しない。別ストアで未知の発行まで防ぐこともできない。確認済みの対応は保持し、競合が見えた段階で拒否する。子の更新が親の manifest を変えた場合は親も新しい版にする。

N7 の版を除くキーは比較候補を探すためのもの。版の異なる型や Composition Entry を統合すると、既存の複数版併存規則を壊す。現在の identity と全前提を照合してから意味計画を使い、対応が曖昧な場合は再検証する。Q2 の token 比較も同じ原則に従う。

### 2.2 native は名前だけでは判定しない

archive の一覧だけでは weak の別名解決、COMDAT の選択、import 補助情報を判定できない。member の情報まで確認し、解決先が一意かを判断する。同じサイズや任意選択可能という属性だけでは、実装が等価とはいえない。この形式上の区別は [Microsoft PE/COFF 仕様](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#comdat-sections-object-only)に基づく。未対応の統合は理由を示して拒否する。

N10 の要求集合を `#LibraryImport` と完全一致させると、native 内部から参照される補助ライブラリを指定できない。直接 import に対する要求の欠落を検査し、追加の明示要求は許す。NativeLibraries の既存 map は自分向け供給の短縮表記として維持するが、非予約 import の要求が未設定なら NativeRequirements への移行を案内する。

### 2.3 配布対象と検証実績を分ける

N8 を必須にすると、一つの環境だけを扱える compiler から他環境向けのソースを配布できず、pack が発行者の検証環境に制約される。今回はソースを利用側でも検証するため、manifest の対象宣言と、特定 compiler・環境での検証実績を分ける。

宣言した全環境を意味検証して発行したい場合は `--verify-all` を使い、未対応環境も失敗とする。通常 pack でも選択した環境の検証は必須であり、未検証の組合せを成功として表示しない。検証実績は SourceId の外に保存するので、確認環境の追加だけで配布内容を変更しない。

### 2.4 不変の保存と再利用を揃える

N9 に合わせ、設計段階の `pack --output` は個別ファイル名ではなく出力ディレクトリを指定する。ルートも子も `<SourceId>.kimipkg` に統一し、コピー例外をなくす。初回の直接依存は明示 Package パスを使い、ストア単独では未固定の ID／Version から内容を選ばない。

N12 の回収で版の対応表まで消すと、N1 の同版再発行を後から許してしまう。対応表は保持し、処理記録・内容の回収とは分ける。再現性を保存する指定では内容の閉包も保持する。単なる ID 一覧から失われた byte 列は復元できない。

Q1・Q4 の再利用は、検証済み内容を compiler が不変に管理する場合に限る。Q6 の属性一致はその代わりにならない。可変入力は実内容を読み、同じ snapshot を後続処理へ渡す。

## 3. 整合性と確認範囲

パス規則には [Unicode 15.0.0 の CaseFolding データ](https://www.unicode.org/Public/15.0.0/ucd/CaseFolding.txt)の C／S を使う。F／T や host の大小文字変換は使わず、言語の名前比較とも分ける。

Testing と generic 共有の参照を同期した。Composition Root のテスト接続が変わる場合は、Provider 非依存の意味を再利用し、影響する生成計画を現在の接続で確定してからテスト要求を追加する。元の製品実行対象と異なる接続を、同じ生成物として扱わない。

以上は設計への反映であり、compiler の実装・性能改善の実測ではない。性能確認は設計書 §8.3 の入力・検証・生成・link 別の指標で行う。文書のみの変更のため compiler／native／NativeAOT テストは実行しない。
