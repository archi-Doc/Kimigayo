# 動的コレクション修正案の採否

2026-09-13。[設計仕様](../Design/2026-09-13%20Dynamic%20Collection%20Mutation%20Contracts.md)に採用分を反映した。§1–4 は最初の修正案、§5 以降は追加レビューに対応する。現在の仕様は後の決定を優先する。SPEC.md と STATUS.md は変更していない。既存 SPEC と違うことだけを不採用理由にはせず、安全性・共通規則・実装可能性で判断した。

## 1. 操作・借用・失敗方針

| 案 | 判断 | 理由・反映内容 |
| --- | --- | --- |
| 1-1 共有予約から排他確定へ統一（R1） | 見送り | 利便性はあるが、通常の共有 Loan だけでは排他への切替権限を表せない。元の書込み権限、親 Reborrow の停止、予約と他の shared Loan の区別、明示的な uniq 引数・default・途中転送・複数対象の扱いが必要。「新しい借用モード不要」という説明ではこれらが未定義になる。コレクションだけの例外を設けず、現行の receiver 先行・即時排他を維持する |
| 1-2 Dictionary.tryGet | 採用 | shared receiver と検索キーから、常に値スロットの参照を Option で返す。不在を調べるための Move・削除を不要にする。結果の Loan と bool 化後の更新も定義した |
| 1-3 owner 一時値を ref 引数へ渡す（R2） | 範囲を限定して採用 | 通常の引数適合へ一行分の能力を追加する。既存の owner Place と同じ借用順位・literal fitting・寿命検査を使う。uniq や既存参照の外側への暗黙の層追加には広げない。一時値の既存の寿命を呼び出し終了へ短縮することもしない |
| 2-1 shrinkToFit の確保失敗（R4） | 採用 | 縮小は任意の最適化であり、確保不能なら完全な現状維持で正常終了する。追加・reserve の必須確保失敗は引き続き Abort。不変条件違反などの Abort は捕捉しない |
| 2-2 命名と失敗方針（R3） | 一部採用 | 前提違反・正常な不在・理由付き失敗の区別を明文化した。ただし `try` に同名の Abort 版を必須とする規則と、Dictionary.insert の追加は採用しない。tryGet 自体も添字との対応で説明でき、名前の対称性だけのために API を増やす必要はない |
| 2-3 live な uniq 値を独立とみなす | 見送り | live には権限が停止中の親参照も含まれる。また「Reborrow 関係が記録されていない」と「関係がないと証明した」は異なる。コレクションや generic 結果で借用元の候補をまとめた後に、型と変数の個数だけで独立性を補う規則は採らない。将来拡張するなら、各権限の独立した由来を転送後も証明する仕組みを別途設計する |
| 2-4 generic Core の effect | 条件付き採用 | 操作別の receiver／引数アクセスと、等値比較・再帰的な破棄の effect を公開要約として合成する。具体化は検証済みの式への代入に限り、定義時の検証は先送りしない。未知の effect や static への再入は許可せず、mutable static のコレクションが常に使えるという保証もしない |

R1 は不可能と判断したものではない。予約専用の状態と権限の切替を定義する、言語全体の独立した設計として再検討できる。今回の「共有 Loan に置き換えるだけ」という適用は行わない。したがって、引数で receiver を読む既存の拒否例を残し、入れ子の構造変更の拒否例も補った。

## 2. 性能

| 案 | 判断 | 理由・反映内容 |
| --- | --- | --- |
| 3-1 空の構築は無確保 | 採用 | 型付きの空リテラルは length = capacity = 0 で、コレクション内部の動的確保なし。管理値の初期化という固定コストまでゼロとはしない |
| 3-2 reserve と追加の共通成長則（R5） | 採用 | 容量拡張の準備・移送の償却上限を共通化し、小刻みな予約と追加の反復でも二次時間にならないことを保証。予約の公開形式は後述の追加レビューで追加数指定へ改訂した。倍率は固定せず、大きな予約要求の処理を O(1) とも扱わない |
| 3-3 Dictionary の検索と管理の分離 | 採用 | 検索は線形でもよいが、追加・削除・置換の管理は償却 O(1)。満容量での削除と再追加にも適用し、配置・順序管理を検索コストに隠さない。空き slot と連結情報などで無確保保証と両立できるため、tombstone と圧縮方式に限定しない |
| 3-3 Dictionary.clear の索引リセット | 採用 | O(capacity) のリセットを許すと明記。Array.clear と同じ上限を無理に課さない |
| 3-4 破棄対象数による評価 | 一部採用 | Array.clear は cleanup 省略を型から証明できれば O(1)。参照カウント解放や Case 検査の必要性を無視しない。順序保持の Array.remove は、返却値を破棄しなくても移動に O(n) が必要なため、破棄対象数だけでは評価しない |
| 3-5 次版の swapRemove | 今回は見送り | 現版の順序保持と分離する必要がある。将来の候補にはできるが、新たな位置・順序・返却契約を要するため今回の API には追加しない。通常の FIFO キューは先頭削除で順序を保つ必要があり、swapRemove では代替できない |

shrinkToFit は厳密な容量を指定する API ではないため、「ぴったりの容量が必要なら使う」という説明は採らない。要求下限と償却成長、任意の縮小を区別する。

## 3. 軽微な修正と統合

- 償却保証より弱い「追加ごとに全要素を移す方式は禁止」という重複文を削除した。
- owner のキー Place を remove に渡す例は、不要な `@ref` を省略した。
- 旧値の破棄中の失敗を Abort／非終了と明記した。
- tryGet の結果だけが返すスロット Loan と、更新操作が返す所有値の依存を区別した。
- 新しい保証の受け入れ条件を既存の表へ統合し、確保方針・effect・計算量はそれぞれ一か所に集約した。

## 5. 追加レビュー：相対指定・型推論・ハッシュ会計

| 案 | 判断 | 理由・反映内容 |
| --- | --- | --- |
| 1-a insert／remove に Index を追加 | 採用 | 既存の境界・要素解決を再利用し、全体排他を維持したまま末尾基準の操作を記述できる。insert は境界、remove は要素として検査し、空の ^0 挿入・^1 拒否・^0 削除拒否を明記した。Range は追加しない |
| 1-b 予約を追加数指定へ変更 | 採用 | 両型を `reserve(additional: isize)` に統一し、総量指定の reserveCapacity は提供しない。必要総容量 R は本体開始時の length + additional。負値・加算上限・予約の反復・0 の扱いを定義し、償却保証と例も更新した |
| 2 §5.3 の適用範囲 | 採用 | 冒頭で、採用時点から言語全体の引数適合に適用すると明記。文書への採用と compiler 実装完了は引き続き区別する |
| 3 generic 推論と既定型 | 採用・補足 | 型付き一時値は同型の owner Place と同じく、引数自身の型から T を推論できる。リテラルは通常の値渡しと同じ既定型規則に従う。ただし候補比較前の一律 i32 化は行わず、他の引数・結果の制約を先に処理する。`g(1)` と借用 overload の曖昧例を追加した |
| 4 ハッシュ再計算の会計 | 採用・補足 | キー内容の比較・内部ハッシュ計算は再索引時も検索コストへ数え、移送・索引書換えは管理コストへ残す。再索引のキー処理回数は操作列全体で O(m + C)。ハッシュ値の保存を強制しない |
| 5 一度の検索による確認・更新 | 記録のみ | 二度検索する例と、重複時にも値が生成済みになる点を明記。借用参照を通した書込みの構文・取得契約と合わせて設計し、今回は新規 API を追加しない |

再ハッシュについて「特定のキーごとに生涯 O(1) 回」という読み方は採らない。初期から存在するキーは複数回の容量拡張で再計算され得るため、回数は操作列全体で制限する。キーの長さに応じた実際の計算時間は検索コストとして別に数え、固定時間と仮定しない。

即時排他の借用規則と、既存の generic 検証・overload 順位は維持する。新 API の from-end 位置と追加数は本体で解決する値であり、予約 Loan や引数評価順の例外ではない。

確認事項の `.Some(_)`、検索キーの一時値に依存しない戻り値、空のゼロサイズ要素コレクション、操作別 effect は引き続き整合する。string literal が動的確保不要でも、一時値の初期化・借用形成まで実行コストゼロとする保証は追加しない。

## 6. 追加レビュー：再索引の対象・診断・表記

| 案 | 判断 | 理由・反映内容 |
| --- | --- | --- |
| 1 再索引上限を整理にも適用 | 採用 | 確保の有無で性能保証に抜け道を作らない。拡張・tombstone 除去・無確保の索引再構築を合算し、縮小を挟まない操作列全体の上限と受け入れ条件を定義した |
| 2 暗黙借用の寿命診断 | 採用・補足 | 借用適合を狭めず、暗黙借用の位置・一時値の終了点・必要な使用を診断に示す。ローカルへの束縛は型・Origin と必要寿命を満たせる場合に提案し、束縛だけで常に解決するとはしない。後続の使用・破棄による依存がなければ、格納したことだけで一律の寿命エラーにはしない |
| 3 reserve の引数名省略 | 採用 | 省略は通常の呼び出し規則どおり許し、値は常に追加数と明記。例と診断の引数説明・修正例に additional: を表示し、名前付き引数の必須化は導入しない |
| 4 段落の区切り | 採用 | §2 の位置説明と通常読み取り、§4.1 の reserve と shrinkToFit を空行で分離した |
