# 分岐本体の構文と match の網羅性

## Current Specification

- ifは式本体 `=> Expression` と、区切りなしのインデント本体を使う。
- matchは全アームに `=>` を要求し、その直後の改行で式本体とブロック本体を区別する。
- Discard Contextで全アームがブロック本体かつ自身へのyieldがないmatchには、網羅性の例外がある。
- 式本体が1つでもある選択式はResult-requiringとなり、結果を捨てる場合も結果供給と型の整合性を要求する。
- unsafe・deferとrequireの失敗本体はInlineStatementを認める。if・ループ・関数・アクセサー・ラベル付きブロックのブロック本体はインデント形式である。

根拠：SPEC.md §2.2、§7.1、§11.2、§14.2〜§14.3、§14.6〜§14.8、§14.11、付録F.5。以下は改訂後の仕様であり、旧提案の1行if・1行ループ・省略既定アームを置き換える。

## Proposed Specification

### 本体を許可する構文

**1行ブロックはmatchアーム・unsafe・defer・requireの失敗本体に限る。** 値を供給する式本体 `=> Expression` は1行ブロックとは区別する。

| 構文 | 1行ブロック | インデント本体 | 式本体 |
| --- | --- | --- | --- |
| if／else if／else | 不可 | 区切りなし | `=> Expression` |
| matchアーム | `: InlineStatement` | `:` の次行 | `=> Expression` |
| for／while／loop（ラベル付きも含む） | 不可 | 区切りなし | 不可 |
| unsafe／defer | `: InlineStatement` | `:` の次行 | 不可 |
| requireの失敗本体 | `else InlineStatement` | `else` の次行 | 不可 |
| ラベル付きブロック | 不可 | 既存の `Name:` の次行 | 不可 |
| 名前付き・匿名関数、getter／setter | 追加しない | 既存構文 | 既存の `=>` |
| コンストラクター／deinit | 不可 | 既存構文 | 追加しない |

宣言コンテナやmatchのアーム列は、実行可能な1文のブロックではない。これらの列に1行形式を追加せず、`match subject` にもコロンを付けない。コンパイル時の `#if`／`#match` は変更しない。

```kimi
if ready
    start()
else
    stop()

for item in items
    process(item)

match event
    .Quit: stop()
    .Write(let text):
        prepare()
        write(text)
    _: ()

defer: close()
unsafe: release(pointer)
require ready else return        // 関数内
```

ifの各分岐・matchの各アームは、表で許可された本体形式を混在できる。統一するのは式本体とブロック本体の評価・結果規則であり、すべての構文に同じ短縮形は設けない。

### InlineStatement

InlineStatementは、**次のいずれか1つを、入れ子の内容も含めて同じ物理行で完結させたもの**とする。

| 内容 | 条件 |
| --- | --- |
| 呼出し・代入などの式文 | 式全体が行内で完結する |
| ローカルのlet／var宣言 | 初期化子を含む宣言全体が行内で完結する |
| return／exit／continue／yield | 通常の転送先・オペランド・境界規則に従う |
| unsafe／defer | 本体もInlineStatementである |
| require | 条件・必須else・失敗本体を含めて行内で完結し、失敗本体もInlineStatementである |

内部に現れるifは、**最終elseがあり、全分岐が `=>` の式本体で、if全体を括弧で囲むものに限る。** 式文・初期化子・引数・転送のオペランドにも同じ条件を適用する。

インデント本体を持つ構文、match、ループ、ラベル付きブロック、関数や宣言コンテナの宣言、コンパイル時ディレクティブは含めない。括弧や初期化子の内部に移しても許可しない。式本体の匿名関数は宣言ではなく式として扱い、内部も行内完結と上記の制限に従う。

```kimi
defer: unsafe: release(pointer)
defer: require ready else exit  // 条件はdefer実行時に評価する
.Some: yield (if ready => 1 else => 2) // matchアームの結果を供給
```

複数文・改行継続・複数行リテラル・後続のインデント本体は認めない。セミコロンで文を連結しない。この制約はInlineStatementの構文内に限り、通常のブロック直下の文全体へは波及しない。

### 本体の開始と終了

- matchアームの区切りは `=>` または `:` とし、どちらも必須の本体を伴う。`:` はPatternまたはガードの終端と同じ物理行に置く。Patternの文法は変更せず、型注釈を追加しない。
- matchアーム・unsafe・deferの `:` の後に同一行の本体があればInlineStatement、空白・コメントだけなら次の有効行から非空のインデント本体とする。requireも `else` の後で同じ判定を使う。
- InlineStatementは構文上の終端で閉じ、次の物理行へ続けない。内側の括弧・引数・requireのelseは、その構文に属するものとして処理する。次行のelseを取り込む特例はない。
- if・ループのインデント本体は従来どおりヘッダーの次の有効行から開始し、`:` も `=>` も付けない。
- `=>` の式は必ず同じ物理行で開始する。開始後は通常の式継続を使える。`=>` 自体のヘッダー継続は§2.2.1に従って許可するが、その次行をブロックへ読み替えない。

インデント本体はヘッダー基準より1段深く、少なくとも1つの完全なソース項目を必要とする。本体がなければ構文エラーとし、後続の同じ深さ・浅い深さの項目を取り込まない。

### 括弧・インデント・else

**ヘッダー内と、選択式の式本体内に現れる本体を取る式は、その式全体を括弧で囲む。** ヘッダーとはif／whileの条件、forの反復対象、matchの対象・ガード、requireの条件を指す。対象の式はif・match・for・while・loop・ラベル付きブロック・ブロック本体の匿名関数である。Boolean束縛の初期化子・演算子のオペランド・引数にも適用する。囲んだ式の本体には外側由来の制約を持ち込まず、内部のヘッダーや式本体は個別に検査する。

この共通規則で内外の本体区切りとelseを分離する。通常の呼出しや、単に複数行になった式全体には追加の括弧を要求しない。InlineStatement内では、さらに前節の行内完結・全分岐式本体の条件を満たす必要がある。

```kimi
let value = if a => (if b => 1 else => 2) else => 3

match event
    .Ready => (
        if enabled => 1
        else => 2
    )
    _: yield 0
```

グループ化 `(E)` はEに外側の評価コンテキストと期待型を引き継ぎ、スコープや転送先を追加しない。引数・初期化子・オペランドなどは、その位置のValue Contextを保つ。

インデントの基準Bは、構文開始時の外側のブロックと未閉鎖の区切りが要求する深さで固定する。キーワードの文字位置やヘッダー内部の括弧で変えない。インデント本体・matchのアーム列・許可されたヘッダー継続はB＋1段とする。else／else ifも初期ifのBを引き継ぎ、別行ではそのBにそろえる。

BranchJoinは次の規則に限る。

1. 式本体の後のelse／else ifは、同じ物理行または次の有効行に置く。
2. インデント本体の後では、DEDENT後の次の有効行に置く。
3. 同一行では構文境界内の最も近い未対応のifに結合する。requireに必須のelseはrequireに属する。括弧などの境界を越えず、結合先がなければ構文エラーとする。

空行・コメントだけの行は無視し、間に別の項目を挟まない。括弧内で項目分離用NEWLINEが抑制されても、有効行とBを使う。通常のRequireJoinは§14.11.1を維持する。

```kimi
print(if ready => 1
    else => 2)                 // Bは4スペース。ifの文字位置には依存しない

defer:
    if needsCleanup
        cleanup()
```

フォーマッタは、elseを別行に置くifを行頭で開始する形を推奨する。必要なら初期化子などを括弧で囲む。未対応ifの個数による拒否規則、行末直前の状態を保存する曖昧さ検査、アーム内ifだけの改行制限は設けない。

### ガードの終端

ガードは正常な結果がboolである1つの式とし、**アームに属する外側の `=>` または `:` で終了する。** 改行・インデントだけではガードを終了せず、本体を開始しない。

開いた区切り内の改行と、区切り外のドット継続は通常の式継続規則に従う。区切り前のドット行を本体へ読み替えない。これはmatchアームの境界の変更であり、if・ループなどの区切りなし本体をドット継続より優先する既存規則は維持する。

```kimi
match request
    .Get(let path) if accepts(
        path,
        mode
    ):
        handle(path)
    _: ()
```

複数行ガードの最後の閉じ区切りは、レイアウト規則が許す範囲でアームのBにそろえる書式を推奨する。ガードから選択中のmatchへのyieldは禁止したままとし、候補束縛・本体束縛の区別、取得・Loan・cleanupの順序も維持する。ガードやそのcleanupが正常完了しなければ、本体の束縛取得も後続アームの実行も行わない。

### 評価・結果・網羅性

式本体はValue Contextで評価し、正常な結果を選択式へ供給する。ブロック本体の直接の式はDiscard Contextで評価し、最後の式も暗黙の結果にしない。1行とインデント形式で、本体スコープ・束縛・取得・転送・Scope Exitの意味を変えない。

matchのPatternの本体束縛と直下の文は同じ宣言空間に属する。`let n: let n = 0` は再宣言エラーとなる。unsafe・deferは式にならず、requireの失敗経路は従来どおり正常継続を許さない。型・所有権・Result破棄警告も省略しない。

**すべての実行時matchに網羅性を要求する。** 本体形式・評価コンテキスト・結果型・yieldによる例外は設けない。既存の限定的な証明規則を維持し、ガード付きアームは網羅性に寄与しない。

Result-requiringは、Value Context、自身の分岐に式本体がある、自身へのyieldがある、のいずれかで決まる。else ifチェーンは1つの選択式として扱う。転送先を解決してから分類し、型や到達可能性で分類を変えない。入れ子の分岐形式や入れ子へのyieldは外側に数えない。網羅性必須化は、全matchに結果要求を発生させる変更ではない。

結果要求がある選択式は、到達可能な正常終了経路で型の整合する結果を供給する。ブロックではUnitを期待する場合もyieldが必要であり、外側への転送や非終了など正常完了しない経路は結果不要である。yieldは最も内側の適格な選択式を対象とし、ループや関数などの境界規則を維持する。

ifはResult-requiringの場合に最終elseを要求する。結果不要のifではelseを省略できる。ガードを本体内ifへ移すと、条件が偽でも後続アームへ進まず、Patternによる網羅性と束縛取得時期も変わるため、整形として相互変換しない。

### 既定アームとlint

既定アームも通常のWildcard Patternと必須の本体で表す。最終アームだけの省略・型推論・暗黙のUnit供給は設けない。

| 記法 | 意味 |
| --- | --- |
| 裸の `_` | 本体欠落の構文エラー |
| `_: ()` | 何もしないブロック。単独では結果要求を発生させない |
| `_: yield ()` | ブロックからUnitを結果として供給 |
| `_ => ()` | Unitを供給する式本体。結果要求を発生させる |

`_:` の次行に `()` をインデントする形も `_: ()` と同じ意味を持つ。何もしない本体でも、対象の取得・Move・借用・破棄は通常どおり行う。

Case追加に関する任意lintは、当該matchと同じKotonohaで宣言されたenumに限定する。先行するガードなしCaseアームが既存の全Caseを証明規則に従って個別にカバーしている場合、後続のガードなし `_` が将来のCaseも吸収することを知らせる。宣言元は型の実体で判定し、別名・再公開で変更しない。外部enum、未処理Caseをカバーする既定アーム、ペイロード分割の合成・ガードの推測は対象外とする。

このlintは受理条件・必須警告・網羅性・到達可能性を変えない。抑止用のAttributeやProject設定は追加せず、非網羅的enumの導入時に対象を再検討する。旧案の「1行の本体内if」を対象にしたlintは、構文自体を認めないため削除する。

### 診断と整形

| 問題 | 修正案 |
| --- | --- |
| if・ループの `: s`／`:` 付き本体 | コロンなしのインデント本体へ移す |
| InlineStatement内に禁止構文・改行がある | それを所有するmatchアーム・unsafe・defer・requireの本体をインデント形式にする |
| 分岐の `=>` の次行に本体がある | ブロックならmatchはヘッダー終端の `:` へ置換し、ifは `=>` を削除する。式なら `=>` と同じ行で開始する |
| 分岐ブロックの結果不足 | 単一の式なら式本体にするか、結果をyieldする。内側のifの結果なら `yield (if …)` などで明示的に供給する |
| Discard Contextの式本体によるelse不足・結果型不一致 | 副作用だけの意図ならブロックにする。ifはインデント形式、matchは許可された1行またはインデント形式を使う |
| 入れ子の括弧不足・結合先のないelse | 内側の式全体を括弧で囲むか、意図する本体のインデントを明示する |
| matchの網羅性不足 | 未処理Patternを追加するか、既定処理の意図がある場合に明示的な `_: ()` などを追加する |

結果を捨てる修正はValue Contextでは勧めない。他の式本体や自身へのyieldが残れば結果要求は続くため、分岐全体を確認する。修正案は意図・評価時期・束縛・cleanupを確認し、構文・型・結果・網羅性・所有権を再検査する。

フォーマッタは、許可された構文についてのみ1行ブロックと単一文のインデント本体を相互変換できる。構文木・スコープ・コメント・elseの所属を保存し、`=>` とブロックは整形として相互変換しない。

## Changes

- matchアームに `=> Expression` と `:` で始まる両ブロック形式を導入し、常に網羅性を要求する。
- if・ループのブロック本体はコロンなしのインデント形式を維持する。1行本体は指定の4箇所と許可された内容に限定する。
- 入れ子は括弧と通常のBranchJoinで区切り、ヘッダー基準Bは括弧内の配置にも使う。旧案の1行if専用規則・診断・lintを削除する。
- Parser、結果分類、網羅性・制御フロー・所有権解析、診断、フォーマッタと検証例を更新する。ループの転送・結果・反復ごとのcleanupは変更しない。

## Rationale

matchアームの一覧性、unsafeの範囲指定、deferによる解放予約、requireによる早期離脱には、1行形式の利益がある。ifでは省略可能なelseと再帰的な1行本体が規則を増やすため採用しない。ループの1行化はifより低リスクだが、今回は反復の表記をインデント形式にそろえる。関数・アクセサーには既存の式本体があり、宣言の短縮形は増やさない。

matchアームのコロンは、1行・複数行を問わず本体開始を明示し、ガードの行末判定を不要にする。一方、if・ループには1行ブロックがないため、既存のインデント構文を維持する。表面の記号を完全に統一するより、各構文の必要な規則を減らすことを優先する。

入れ子の式は括弧で境界を示す。未対応ifの個数や改行前の状態による特別な判定は不要になる。括弧内のレイアウトは式本体・インデント本体の両方に関係するため、基準Bは維持する。

網羅性と結果要求を分離し、本体を整形しただけで安全性検査が変わる問題を解消する。裸の既定アームと暗黙のUnit供給は採用しない。将来のCaseを吸収したくなければ個別列挙を使い、同じKotonohaの不要な既定アームへのlintで判断を助ける。

文法の変更部分と関連部分は次のとおり。ExecutableBlockは既存の非空インデント本体を表す。

```ebnf
BranchBody      := "=>" Expression | ExecutableBlock
MatchArm        := Pattern ("if" GuardExpression)? MatchArmBody
MatchArmBody    := "=>" Expression | ":" ShortOrIndentedBody
ShortOrIndentedBody := InlineStatement | ExecutableBlock
UnsafeStatement := "unsafe" ":" ShortOrIndentedBody
DeferStatement  := "defer" ":" ShortOrIndentedBody
RequireStatement := "require" Expression RequireJoin "else" ShortOrIndentedBody
ForExpression   := "for" ForBinding "in" Expression ExecutableBlock
WhileExpression := "while" Condition ExecutableBlock
LoopExpression  := "loop" ExecutableBlock
InlineStatement := ? 許可表に従い、内部も同じ物理行で完結する1文 ?
GuardExpression := ? アームの外側の => または : で終わる1つの式 ?
BranchJoin      := ? 式本体の同一行結合、または本体終了後のBへの次行結合 ?
```

BranchBodyはif用であり、matchアームにはMatchArmBodyを使う。文法には本書の括弧要件、InlineStatement制限、レイアウト規則を併用し、通常の式文法だけで禁止構文を再許可しない。

| 検証境界 | 必要な判定 |
| --- | --- |
| if／forの区切りなしインデント本体、ラベル付きループ | 有効。本体区切りのコロンや1行本体は不可。ラベルのコロンは維持 |
| `P: f()` と同じ1文の `P:` インデント本体 | スコープ・破棄・結果要求が等しい。整形前後で維持する |
| matchの `P =>` の次行に式・ブロック | 構文エラー。式開始を同じ行にするか `:` に置換する |
| `P:` の後に同じ深さの次アーム、裸の `_` | 本体欠落。次アームを取り込まない |
| `P: yield (if c => 1 else => 2)` | ifの結果をyieldがmatchへ供給する |
| `P: (if c => 1 else => 2)` | 内側ifの結果を捨てる。これだけではmatchの結果にならない |
| InlineStatement内の未括弧if・混在本体if・ループ・match・改行 | 構文エラー。括弧で禁止構文を隠しても不可 |
| `defer: unsafe: release(p)`／`defer: require c else exit` | 構文上有効。実行時期・転送・所有権を通常どおり検査する |
| `require c else log()` | logが正常終了するなら失敗本体の非継続違反 |
| `P: require c else yield 1` | 自身へのyieldで結果要求が発生。require成功後の正常終了経路があれば結果不足 |
| 結果不要のmatch／Unitが必要なmatchの `_: ()` | 前者も網羅性必須。後者は正常終了経路の結果不足 |
| 結果要求がある本体から外側への転送、非終了するcleanup | 正常完了しない経路のyieldは不要。通常の境界・Scope Exit検査は必要 |
| ガードの呼出し引数の改行・区切り前のドット継続 | 通常の継続として検査し、外側の `=>`／`:` でのみ本体へ移る |
| 括弧内のif・アーム式本体内の括弧付きif | Bと通常のBranchJoinで配置でき、整形でelseの所属が変わらない |

## Decision

1. 1行ブロックはmatchアーム・unsafe・defer・requireの失敗本体に限定し、内容はInlineStatementの許可表に従う。
2. if・ループのブロックはコロンなしのインデント形式とする。関数・宣言などへ1行ブロックを追加しない。
3. 分岐の `=>` は式本体専用とし、式を同じ物理行で開始する。matchのブロック本体は両形式とも `:` で始める。
4. ガードは外側の `=>`／`:` で終了する。入れ子は括弧で区切り、Bと通常のBranchJoinを使う。
5. すべての実行時matchに網羅性を要求する。結果要求とは分離し、裸の既定アーム・暗黙のUnit供給は認めない。
6. 既存の型・束縛・転送・所有権・Scope Exitを維持し、診断・整形・任意lintを上記の範囲に限定する。
