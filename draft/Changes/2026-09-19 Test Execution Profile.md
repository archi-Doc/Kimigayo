# Design Change — テスト実行仕様の確定

日付: 2026-09-19  
状態: 採用済み・仕様反映済み

本書は議論で確定した変更の記録である。「現在の仕様」は今回の変更前を指す。正式な仕様は [SPEC.md](../../SPEC.md) とその参照先に統合済みであり、詳細はそちらを参照する。

## Current Specification — 現在の仕様

- `#Test`、`$expect`／`$require`、製品・テスト入力の分離、ケース単位のプロセス隔離は規定されていた。
- トップレベルに実行文があるプロジェクトは、従来のテスト起動規則では拒否する方針だった。トップレベルの `let`／`var` はソース単位の起動本体のローカルであり、ルート group の静的メンバーではない。
- solution 一括実行、具体的な実行設定・既定値、一時領域の公開方法、識別子・通信・結果形式は未確定だった。

## Proposed Specification — 新しい仕様

初版は Windows x64 を対象とし、`kimi test` はプロジェクト・ソース・ディレクトリー・solution を受け付ける。solution 指定時は、記載された全プロジェクトを実行対象にする。依存プロジェクトのテストは、独立した対象として選択された場合だけ実行する。

全対象の本体を検証してから一覧表示・絞り込みを行う。実行に必要な全成果物のビルドが成功するまで、ケースを起動しない。プロジェクトごとに全ケースを含む不変の実行ファイルを用意し、各ケースを新しい管理対象プロセスで一度ずつ実行する。

トップレベルの意味は変更しない。テスト時には起動本体と明示的な `main` を型・所有権・制御フロー検証の対象にするが、自動実行しない。有効な製品用エントリーは要求せず、テストからトップレベルのローカルを捕捉することも認めない。

## Changes — 変更点

| 項目 | 確定内容 |
| --- | --- |
| 起動本体 | 従来の拒否方針を変更し、「検証するが実行しない」とする。通常ビルドの起動規則は維持する。 |
| 実行設定 | `.kimiproj` の単一 `Test` 設定を CLI で上書きする。名前付きプロファイル・設定継承は初版に導入しない。 |
| 一時領域・環境 | ケース専用フォルダーを用意し、`Kimi.Test.tempDirectory() -> string` と `TMP`／`TEMP` で同じ場所を公開する。環境は一度取得した共通スナップショットにプロジェクト設定を適用し、予約されたケース固有設定だけを上書きする。終了後は一時領域を回収する。 |
| 探索・選択 | `--list` は検証のみで、生成・リンク・実行を行わない。全体の選択結果が空なら原則エラーとし、`--allow-empty` で許可する。不明な CaseId は常にエラーとする。 |
| 隔離・上限 | Windows Job Object に生成時から所属させ、子孫も回収する。並列数と総予算は solution 全体で共有する。既定値は実行期限30秒、回収猶予5秒、並列数は最大4かつ論理CPU数以下。診断・ログ・通信にも有限上限を設ける。 |
| 識別・結果 | 単独実行と solution 実行で同じ TestId／CaseId を使う。ArtifactId と実行ファイルのハッシュで成果物を識別する。専用結果チャネルと版付き JSON／テキスト結果を定義し、失敗・終了理由・管理エラー・省略情報を分離して記録する。 |
| 終了・保存 | 親コマンドの終了値は成功0、ケース失敗1、入力・ビルド失敗2、管理エラー3、キャンセル130。結果は原子的に公開し、完了済み結果の保持上限を10実行・1 GiBとする。 |

`$expect`／`$require` の既定の意味は維持する。条件は一度だけ評価し、偽を条件の一時値の破棄前に記録する。メッセージは失敗時だけ一度評価し、その一時値を破棄した後、`$expect` は継続、`$require` は Abort する。`$require` による Abort では外側の `defer` を実行しない。保持上限に達しても、必要な評価・破棄や失敗状態を省略しない。

## Rationale — 変更する理由

- トップレベルを静的メンバーへ変更せず、既存のスコープ・初期化・所有権規則を保ったままテストできるようにする。
- 絞り込みによる検証漏れや、一部プロジェクトだけ実行される状態を防ぐ。
- プロセス・一時領域・環境を明確に分離し、FFI 利用と再現性を両立する。
- ハング、子孫プロセス、ログ過多、通信破損を有限の管理処理で扱い、終了コード0だけで成功と判定しない。
- 既存の解析・所有権処理を共用し、成功した検証では診断用の割り当てや不要な値の再評価を行わない。

## Decision — 最終決定

上記を採用する。トップレベル宣言をルート group の静的メンバーに変える案と、起動本体を検証せず無視する案は採用しない。solution 一括実行、ケース専用一時領域、共通環境に予約設定だけを上書きする方式を初版に含める。

名前付きプロファイル、パラメーター化テスト、同一プロセスの再利用などの拡張は保留する。仕様の確定と全機能の実装完了は区別し、外部モジュール生成・動的 static・生成予算分離などの残課題は [STATUS.md](../../STATUS.md) と [PLAN.md](../../PLAN.md) で管理する。
