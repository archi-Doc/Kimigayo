# 引数名の省略とデフォルト値の分離

## Current Specification — 現在の仕様

変更前は `?` が引数自体の省略を許可し、デフォルト値を必須としていた。
`x: i32 = 10` は必須引数のままで、初期値は実行されなかった。
通常の引数名は、`?` の有無にかかわらず省略できた。

## Proposed Specification — 新しい仕様

`?` は呼び出し時の外部引数名の省略を許可する。
デフォルト値は引数自体の省略を許可し、省略時だけ評価する。

| 宣言 | 名前付き指定 | 位置指定 | 引数自体の省略 |
| --- | --- | --- | --- |
| `x: i32` | 可 | 不可 | 不可 |
| `x: i32 = 10` | 可 | 不可 | 可 |
| `x?: i32` | 可 | 可 | 不可 |
| `x?: i32 = 10` | 可 | 可 | 可 |

## Changes — 変更点

- 名前を分ける場合は `external? => internal: T` と書く。
- 位置引数は名前付き引数より前に置き、宣言順に対応させる。名前必須の引数やデフォルト付き引数を飛ばさない。
- デフォルト付き引数を必須引数の前にも置ける。途中を省略する場合は後続引数を名前で指定する。
- Contract の関数要件は `?` を許可し、デフォルト値は禁止する。呼び出しは要件側の指定に従う。
- 外部関数も `?` を許可し、デフォルト値は禁止する。C ABI は変えない。
- 関数値は名前・省略許可・デフォルト値を保持せず、全引数を位置指定する。
- 特殊化は元の宣言の指定を継承する。コンストラクターにも通常の規則を適用する。
- 受信者の専用規則、デフォルトの評価順・所有権・後始末は維持する。

## Rationale — 変更する理由

本来の設計意図である「名前の省略」と「値の省略」を独立させる。
意味のない初期値をなくし、API の設計者が必要な引数名を要求できるようにする。
位置引数の対応先を型や省略状態から推測しないことで、呼び出しの意味を明確にする。

## Impact on SPEC.md — SPEC.md への影響

- §7.2 に宣言形式と四通りの組み合わせ、§10.1 に引数の対応規則を集約する。
- §6–9、§11–12、§22 と付録 A・F の関連規則を整合させる。
- 標準 API の宣言と仕様例を更新し、参照によって説明の重複を減らす。
- 正式な仕様は SPEC.md と参照章だけで完結させる。本書には依存させない。

## Decision — 最終決定

採用。`?` を名前省略、デフォルト値を引数省略の指定とする。
Contract・関数値・外部関数の扱いも上記のとおり確定した。

コンパイラーでは名前省略のフラグとデフォルト式を分離し、関連する解析・照合・生成を変更した。
旧規則を前提とする標準ライブラリ、実行例、テストを移行した。
実装の検証結果と既存機能の対応範囲は STATUS.md、実行記録は PLAN_HISTORY.md に記載する。
