# G75: Common Ownership Analysis C — Semantics-case verification

Date: 2026-10-06. Status: implementation plan; not integrated, implemented or verified.
Planning baseline: `dev` at `cc4fc370`. Supersedes `2026-10-06 G75 Common Ownership Analysis.md` (A) and `… B.md` (B) for this issue; both remain reference material.

Method: four independent code audits (ownership engine, builder and instance mode, Binding, evidence), three independent designs (conditional roots in one pass; `o_s` plus per-case runs; first principles) and three adversarial judges, each verifying claims against `dev`. All three judges selected the first-principles design. The synthesis was then checked by seven refuters, one claim set each, and a completeness critic; every refuted claim is corrected below. Every `file:line` was verified on the baseline by an audit, a judge or a refuter; a claim marked **probe** is settled in U0 before the unit that depends on it.

## 1. Objective and constraints

Resolve G75 by making Semantics-generic code use the ownership analysis that concrete code already uses. A generic body with pair binders is verified as what the SPEC already says it is: a **finite family of ordinary bodies, one per admitted Semantics case**, each analyzed by the unchanged engine on the complete Types of that case. Bare `s/T` capture entries and per-case call receivers are consequences of that rule, not a separate feature.

- Implement from scratch on `dev`. No code, test or route of `held/n11-conditional-capture` (`fc5ab7cd`) is merged, cherry-picked, copied or ported. Its six review rounds (`artifacts/verify/20261005-n11-held/`) inform coverage only; every reproducer and expectation is written from the SPEC.
- Fix the cause, not routes. After this plan the compiler contains **no generic-specific Loan propagation**: no operation whitelist, no per-route table, no strongest-case shortcut, no definition-only side channel.
- No valid form becomes Unsupported to close the unit. Every located limit that remains is named in STATUS with its reason.
- SPEC changes are made where a simpler, more consistent rule exists (AGENTS.md), with rationale, Principles check, examples and an `INTEGRATED.md` record in the same commit.

## 2. Diagnosis

The SPEC fixes the meaning: `o = OuterOrigin(W)` is the outer Origin of the pair's whole Type, present only for a borrow binding (§8.1.1); every operation on a pair layer "applies the existing rule of each admitted Semantics, and a generic body must be valid for all of them" (§13.5.5.1); a bare acquisition of a pair Place has a finite conditional plan whose "cases are never merged" (§8.9); each case has its own Closure receiver (§7.6.3); a definition is verified for every admitted binding, with no uses (§8.10). The implementation deviates in three places:

1. **The borrow cases have no Origin.** `W` is created without an Origin (`Binding.cs:1612`, the `GenericParameterKoto` case: `WholeType ??= new(identifier, Parameter, symbol)`; `BoundType` defaults `Semantics = Owner`, `Origin = null`, `BindingModel.cs:292`). Concrete code keeps a Loan because a Type names a root's Origin: an exclusive input with a declared Origin is its own root (`IsExclusiveBorrowInput`, `OwnershipBody.Borrows.cs:1298-1300`, self-root at `:112-117`), and every holder whose Type names that Origin inherits the dependency along the flow edges of `RetainBorrowAuthority.Merge` (`:1313-1382`, `NamedOriginRequirement` `:932-950`, `:1427-1434`). A `W`-typed value names nothing, `AddType` skips a pair parameter's Origin (`:471-472`) and `PlaceOrigin` skips a pair layer's stored Origin (`Binding.ArgumentOperations.cs:748-750`). `dev` compensates with a definition-only side channel: `OwnershipAnalysis.Use` emits an exclusive Borrow into a temporary and registers `ConditionalReborrows` (`OwnershipAnalysis.cs:806-813`, the only writer), consumed by the `VerifyBorrows` gates, `AddExplicitDependencies`, `IsPairInput`, `HasExplicitDependency` and an ancestry special case (`OwnershipBody.Borrows.cs:77, 126-129, 295, 657-704, 770-781, 1288-1289, 1590-1607, 2105`) and cleared in `Reset` (`OwnershipModel.cs:370`). That channel propagates only along the operations it lists; the lost Loans of STATUS and of the six review rounds are exactly the operations it does not list.
2. **The template is the owner case.** Universal verification strips pair layers (`SelectedPlace`, `OwnershipAnalysis.Instances.cs:274-282`; `FollowsReference`/`PairLayerExists` hold only in an instance, `:87-98`; `CopyPairTarget`, `:122-144`; `OwnershipAnalysis.cs:966-972`), so `v@follow = x` is a plain Write of `v` and the uniq case's store through the referent (`WriteReferent` → `StorePointer`, `OwnershipAnalysis.cs:1282-1286`) never runs in the definition. STATUS records this as "universal verification treats the layer as the owner case".
3. **Capture and receiver facts are single-valued.** `CaptureEntry` classifies a bare entry from one Type (`Binding.Closures.cs:481-498`): Copy when the premises prove Copy of the whole (a borrow-only or Copy-proven admitted set), Reborrow for a `uniq`/`objuniq` Type, otherwise `TransferRequired`; a `W`-typed binding with an admitted exclusive case is therefore a Language error on a valid form. `BoundClosure.Receiver` is one `SemanticsKind` (`:21`), derived by `ClosureEffects` as the strongest over all uses (`:632-751`), although §7.6.3 gives each case its own receiver.

Two further defects found by the audits are repaired on the way because the plan depends on them: an explicit `s/T during a` becomes a `Parameter`-kind clone that `TryPairLayer` no longer recognizes as a pair layer (`Binding.TypeOrigins.cs:156-159`, `Binding.PairLayers.cs:23-24`), and a pair layer's target is compared covariantly whatever `s` admits (`Binding.TypeRelations.cs:140-150`; also `:45-48`, `:364-371`, `Binding.TypeOrigins.cs:332`, `Binding.OriginDeclarations.cs:713-716`), contrary to §15.3.5 ("`uniq`, `obj`, `objuniq` and `raw` are invariant in their target … in a generic body a relation between pair layers must hold for every admitted Semantics"); the `smuggle` program of §9 (R4) is the probe.

**Invariants.**

1. *No generic branch in the solver.* After U3, `OwnershipBody.*` contains no predicate on `TryPairLayer`, `ConditionalReborrows` or Semantics parameters. `UncheckedOriginObligation` (`OwnershipAnalysis.Borrows.cs:105-113`) stays: it reads declared parameter Types and Binding's Input-kind obligations, never Place Types, and `o_b` never matches its Input test.
2. *Case Types are ordinary Types.* `o_b` is an `OriginKind.Parameter` atom, which the engine already treats as "a lifetime, not an access path": an exclusive input over it is rooted by `IsExclusiveBorrowInput`, carried by `NamedOriginRequirement` and `Merge`, judged as a fixed Origin (`FixedOrigin`, `Binding.OriginProof.cs:90-106`). `NamedOriginRequirement`'s `Contains` compares by reference (`:952-957`), so `o_b` is one interned object.
3. *A one-case body is today's body.* A body without resolved binders runs once with `Concrete` = identity; concrete programs and the library (whose only pair declaration, `Intrinsics.clone<s/T>` with `s is rc or arc`, is bodiless and unresolved) are unchanged.
4. *Instances substitute, never reanalyze.* `AnalyzeInstance` keeps its protocol; a difference between an instance and the case that covered it is an internal invariant failure (`OwnershipAnalysis.Instances.cs:65-70`), never a user diagnostic.
5. *Cases are never merged.* No operation is built from a union of cases; no receiver is the strongest over cases except where the SPEC's per-case check is monotone and the maximum is an admitted case (§5.4).
6. *Consistency of resolution.* In a run, a pair-structure query (`FollowsReference`, `ImplicitPairAdmitted`, a conditional bare plan, a pair capture plan) on a binder outside the run's case vector is `OwnershipFailure.Internal`. Because Binding admits a per-case operation only for a set within `Q` (`FollowablePair` returns none otherwise, `Binding.PairLayers.cs:78-86`; `BareAcquisition` likewise), this guards the agreement of the resolution criterion with Binding's admission, not the completeness of a site list; there is no site list.

**Removed `dev` concepts:** the definition-only side channel (its writer, its six reader sites and `Reset`, §2), the owner-view template paths (`CopyPairTarget`, `CopyThroughPair`, the definition branches of `SelectedPlace`/`FollowsReference`/`ReadsStoredReference`/`ImplicitlyFollowsReference`/`ThroughPairLayers`/`ReadReference`), the single-valued `CaptureAcquisition.Copy`/`Reborrow` split for bare entries, and `HasConditionalReborrowPlan` as a yes/no predicate with its one consumer (`OwnershipAnalysis.cs:806`).

**Alternatives rejected.** (i) A conditional Origin atom with conditional roots and case-selected operations in one pass (plan B, design A): every root-indexed loop of the engine must learn the condition (fifteen sites in `OwnershipBody.Borrows.cs` and `Reservations.cs`), one follow must become a union operation shape (the merging §8.9 forbids), forked holders need an expression-level join and a condition-aware ancestry that do not exist (`PhiInputs` is result-only; `borrowDefinitions[p] = -2` on two definitions), and a new `OriginKind` touches 47 files. (ii) Per-case Types in Binding: §8.1.2 fixes one `W` per occurrence and §7.6.3 forbids re-running selection per receiver; only the ownership facts differ per case, so Binding keeps one Type and records per-case facts only where the SPEC states them. (iii) A SPEC rule that removes conditional plans from bare acquisition: no existing spelling fixes the effect (`@s` borrows the slot, `@follow@uniq` yields `uniq/T` in every case and needs a writable `P` when owner is admitted, `@move` consumes), bare acquisition in generic code would differ from §3.5, and `[v]` ("as `let v = v`") would have no generic form; it is a weakening. (iv) Putting `o_b` on `W` itself (plan B): `BoundType.CarriesOrigin` becomes true for `W`, so `RewriteOrigins`, `WithOrigins` and `SubstituteStoredOrigins` re-intern clones of the one object that `TryPairLayer`, `SemanticsPremise` and `DirectTarget` identify by reference, the accessor gate `Result is { CarriesOrigin: false }` (`OwnershipAnalysis.cs:2361`) makes pair-typed Property results Unsupported, and `PairAnnotationBindingTest` asserts `WholeType.Origin == null`; the accessor gives the same fact with none of that. (v) Resolving a binder by the operations a body records (design B's "resolved binder", an earlier draft of this plan): Binding records follows, implicit follows, receivers and Subjects, but records nothing for comparisons through layers (`Binding.Comparisons.cs:22-37`), structural pattern positions below a nested layer (`Binding.Patterns.cs:391-403`), bare acquisitions or capture entries, so a site list would be incomplete by construction; the admitted-set criterion needs no list.

(2) A generic body is judged by reading each case as the concrete program it becomes; `o` behaves as a declared Origin. ## 5. Design

### 5.1 Binding

- **B1 `PairOuterOrigin(symbol)`.** One interned atom per pair binder: `OriginKind.Parameter`, binder = the declaring function or container (`symbol.Scope.Owner`, the identity `ContainerSlot` uses, `Binding.ContainerReferences.cs:30-33`), a negative slot (declared Origins use slots ≥ 0; today's negative slots, `EnvironmentSlot(i) = -2 - i`, `Binding.ArgumentOperations.cs:112`, are `Projection` atoms and never meet a `Parameter` atom in the intern key `(binder, kind, slot)`, `Binding.Origins.cs:150-158`), `Name` = the pair identifier, `Occurrence = the GenericParameterKoto`. `Occurrence` is `init` and `OriginAtom` cannot set it, so the atom gets its own creation path (as `Binding.Origins.cs:580-585` does). `W` keeps `Origin = null`. One accessor `OuterOrigin(BoundType pairOccurrence)` returns `X.Origin ?? PairOuterOrigin(X.Symbol)` and is the only way Binding obtains a pair occurrence's outer Origin; the two Binding walks that today skip a pair layer use it: `ProvesTypeOriginPremise` (`Binding.OriginProof.cs:312-348`, which yields "inner Origins outlive the outer Origin" only for `IsBorrow` layers and Slices, `:333-340`) treats a pair layer whose admitted set contains a borrow as a borrow layer with outer Origin `OuterOrigin(layer)`, sound because in the value cases no Type denotes `o_b`; and `Binding.EffectBounds.cs:684-700` records a pair layer's access on `OuterOrigin(layer)` instead of exiting silently for `W` (`:695-698`) or violating for a slot-less `s/U` (`:690-692`); summaries stay per definition (§8.4.10).
- **B2 `CaseType(type, cases)`.** A walker over a span of `(BindingSymbol Whole, BoundType Form)` with the mapping of §3, keyed by the pair symbol so function, container and enclosing-function binders work in one pass; recursion through `RentTypes`/`InternType` exactly as `SubstituteType` does; returns the input object when nothing changed. For the original `W` the form uses `OuterOrigin(occurrence)`, so an annotated occurrence forms `uniq/T during a` (§8.1.2). For `s/U` the occurrence's own slot is used; an occurrence without a slot forms its borrow case with `Origin = null`, as instance substitution does (`:506-507`). `Form(uniq, T, o_b).Components[0]` is `T` by construction: `DirectTarget(W)` returns `W.Symbol.Type`, the single `TargetProjection` object (`Binding.TypeRelations.cs:410-420`), and `InternType` stores component references unchanged and matches by `ReferenceEquals` per component (`Binding.Types.cs:808-812, 833`), so `PairLayerExists` (`OwnershipAnalysis.Instances.cs:96-98`) holds symbolically. **probe R1** covers only the walk cases (`ref/Box<s/T>`, `s/(t/U)`, `ref/Collection<s/T>`, `SharedReferenceThroughLayers` on symbolic chains).
- **B3 Resolution and accessors.** `PairBinders(scope, list)` fills a caller-owned list with the pair binders in scope of a `Build` entry (its function's, its container's and, for a closure, static initializer or accessor executable, its enclosing declarations'), outer to inner in slot order, each with `A(b)` and the resolution flag `A(b) ⊆ Q`. `AdmittedSemantics` becomes internal. Nothing is recorded per node for resolution; Binding's existing per-node records (`pairFollows`, `implicitPairFollows`) keep their consumers.
- **B4 `BareAcquisition(type, node, out SemanticsMask reborrow) → SemanticsMask failing`.** For each admitted Semantics of the layer's binder: `CaseType` proven Copy (`ProveCopy`) → Copy; `uniq`/`objuniq` → Reborrow; otherwise failing. Replaces `HasConditionalReborrowPlan` (`Binding.ConstraintValidation.cs:17-33`), whose one consumer is `OwnershipAnalysis.Use` (`OwnershipAnalysis.cs:806`, locals and parameters only); the predicate and that consumer are deleted in U3 (O4), so U2 adds `BareAcquisition` beside them. A bare element acquisition (`OwnershipAnalysis.Elements.cs:214-242`) has no plan today and reports `TransferRequired`; in a case run the element's case Type decides, and Binding's argument check (`Binding.ArgumentOperations.cs:942-951`) consults `BareAcquisition` for a bare pair argument (U5). A nonempty failing mask is the §8.9 definition error, reported with the failing cases. (`Binding.Conversions.cs:400`, `Binding.Patterns.cs:675` and `BodyLowering.CompositeMatch.cs:35` are `TryPairLayer` sites of follow binding, match coverage and lowering's selected-layer stepping; they stay.)
- **B5 Explicit `s/T during a` is a pair layer.** `TryPairLayer` identifies the original pair by `Symbol.Kind == SemanticsTarget && Kind == Parameter` (as `IsPairWhole` does, `Binding.ParameterShapes.cs:82`) instead of reference equality with `WholeType`; `whole` stays the `W` object, so `SemanticsPremise` (`Binding.ConstraintValidation.cs:36-43`) is unaffected; the clone keeps `Kind == Parameter`, so the `TypeFormation` obligation (`Binding.TypeOrigins.cs:124-126`) and the `static`-Origin rejection under an admitted exclusive case (`Binding.ConstraintValidation.cs:411-440`) stay as they are. `PairAnnotationBindingTest` rows keep (`WholeType.Origin` stays null).
- **B6 `PairOrigin`.** For a borrow-only admitted set return `OuterOrigin(layer)` (today `pair.Origin ?? PlaceOrigin(node)`, `Binding.PairLayers.cs:170-171`, and the `PairFollow` branch of `PlaceOrigin`, `Binding.ArgumentOperations.cs:716-721`): a Reborrow through the layer depends on `o` and the parent Loan, not on the slot (§13.5.5.1, §13.5.5.2). For a mixed set keep the operand Place's dependency `p`: in the owner case the layer borrow really depends on `p`, so any conflict the uniq case run reports through `p` the owner case run reports as well (§6). **probe R11** confirms that the mixed-set run still finds the uniq case's referent conflicts; if it does not, `CaseType` selects the outer Origin per case for the Places whose Types Binding derived through a pair layer (node-keyed through `implicitPairFollows`/`pairFollows`, no new `OriginKind`). `PlaceOrigin`'s pair skip at `:748-750` stays: a slot borrow of a pair Place depends on the slot in every case. B6 is the one place that puts `o_b` into a stored Binding Type, so B8 and B10 land in the same unit; the `dev` engine already tolerates such a Type (`AddOrigin` has no `Parameter` branch; `FixedOrigin` accepts `Parameter`).
- **B7 Call contracts (S8).** A callee occurrence of its own pair whole `u/U` (and any Type that merely contains it, such as `uniq/(u/U)`, a `Semantics` Type with an ordinary Input atom) carries no conditional slot: with `u/U := W`, `SubstituteType` returns the caller's `W` object itself (`Binding.TypeRelations.cs:423-447`), the `Static` rule never fires (`Binding.ContractCalls.cs:233-237` requires a `BorrowCondition` Origin, and `W.Origin` is null) and `FormedApplication` is not consulted for a `Parameter`-kind pattern (`Binding.Calls.cs:2064-2068`). `inner<u/U>(x: u/U) -> u/U` and `put2<u/U>(slot: uniq/(u/U), y: u/U)` therefore keep `W` and its case Types; their Loans are an engine matter (O5, E4). ## 6. Soundness and precision

**Why no Loan can be lost on any operation.** In case `c` every Place Type is `CaseType(·, c)` wherever a Type enters the builder (parameters, `Place()`, environment bindings, element Places, `OwnershipAnalysis.Elements.cs:14, 38, 74`), and every operation's shape is selected from those Types by the code paths concrete code uses. After the deletions of O4 the solver has no branch that can tell a case run from the analysis of the counterpart `C_c` (`W` replaced by `uniq/X during a`, `ref/X during a` or `X`), up to requirement effects (§8.4.10.4), which exist only in generic bodies: `AbstractTypes.HasAbstractPart` is true for `uniq/T during o_b` and `T`, so `Carries` and `HasExplicitDependency` treat case-Typed holders as carrying requirement results, which is the SPEC's rule for generic bodies, not an owner-view path. The ownership facts of `G` in case `c` therefore equal those of `C_c` up to the renaming `T ↔ X`, `o ↔ a`; a Loan is lost in `G` iff it is lost in `C_c`, and E1–E4 make the concrete carrying rule total: a holder keeps a root's Loan whenever its Type names the root's Origin and a value flows into it, whatever the operation.

**Why no false conflict arises on the valid families.** The same equality: `G` conflicts in case `c` iff `C_c` conflicts. The evidence audit's valid families are accepted by the concrete engine for reasons it cites: distinct self-roots per exclusive input (two holders into `touch2<U>(a: uniq/U, b: uniq/U)`), regions following last uses (chained stores, bindings of aggregates holding the child), result Origins from the callee contract (`second<A, B>`), a parent Move while a child lives (external roots skip Place-level conflicts). Confounders of the concrete oracle on `dev` are triaged against the SPEC per family and never copied into `G`'s expectations: two-Reborrow invariant fits (recheck on `cc4fc370`, which repaired the G76 applicability blockers), reassignment of a holder (G56 local regions), `CallEffectConflict_Kd` on `Cell<s/T>` methods.

**Specific forms.** Two binders and nested `s/(t/U)`: the product of cases; `CaseType` substitutes inner occurrences first, so `(ref, uniq)` forms `ref/(uniq/U during slot_t) during o_s` and the §3.5 rule "an exclusive reference on a shared path cannot be Reborrowed exclusively" fires in exactly that combination. Explicit `s/T during a`: `OuterOrigin` is `a` (B5, B6). `s/U` applications: the occurrence's conditional slot is active only in borrow cases because `Form(owner, …)` drops it. Closures: bare entries are `BorrowStruct` or a source Consume per case (C2); nested closures run the enclosing case vector (O3); a conditional closure moved into an aggregate or through `keep<F>` carries `o` in its environment Type like any value (E3 covers the closure temporary). Stores through references, Fields, Tuples and component Moves: `o`-naming Types flow through the existing edges and E2; a component Move keeps ancestry (`IsBorrowAncestor` walks `Consume-Move`). Iteration and pattern bindings: the instance paths already execute for all three (`PairFollowTest` Iterated/Matched/Combined at O0/O2), and a case run takes them. Generic calls with several `uniq/T` parameters: `RetainsInput` retains by Origin name as for a declared `a`; with one `o` per binder (§11.1) the counterpart is written with one shared declared `a`. Results of Type `s/T`: the result Place Type is `CaseType(W)`; `pass<s/T>` keeps running. Generic-to-generic pair calls: a callee occurrence of its own whole substitutes to `W` and needs no contract change; a callee application `u/V` is B7; a local Type naming `o_b` at instantiation is B8 (through B6). Element Types of `Collection<s/T>`, `Array<s/T>` and `Dictionary<K, s/T>` are case-Typed by construction; their literals are the Dictionary case of R6. Mixed-set `PairOrigin` keeps `p`: a uniq-run conflict through `p` is an operation on the layer's operand while the layer borrow lives, which the owner case, where the borrow depends on `p`, rejects as well, so no program is rejected that every case accepts (R11 confirms the referent conflicts are still found).

**The one per-case decision in Binding** (receivers) is exact because the receiver function is monotone and its maximum is attained by an admitted case (C4).

## 11. Decisions on open points

1. **One `o` per binder.** §8.1.1 binds one complete Type per pair slot, so every `s/T` input of one binder shares `o` ("independent of the Origins of other inputs that use the same `s`" in §13.5.5.1 refers to `s/U` applications). A callee such as `touch2<U>(a: uniq/U, b: uniq/U)` instantiated with `U := uniq/T during o` may exchange the referents, and `RetainsInput` retains by Origin name accordingly, exactly as the concrete counterpart with one shared declared `a` does. The SPEC is not revised; the evidence family's counterpart is written with a shared `a`, and the generic program is accepted iff that counterpart is.
2. **Unresolved binders stay abstract.** A binder admitting `obj`, `rc` or `arc` admits no pair-layer operation anywhere (`FollowablePair` returns none for a set outside `value or valueborrow`; a conditional plan needs Copy cases in `{owner, ref, objref, raw}`), and `ProveCopy(W)` is Proven only from one premise whose mask lies in `{ref, objref, raw}` or equals `{owner}` with `T is Copy` (`Binding.Capabilities.cs:532-547`; a mixed Copy set such as `{owner, ref}` with `T is Copy` is Unknown and is resolved, since it lies within `Q`). Every remaining operation on such a `W` value is Semantics-independent (Move, slot borrow, store, return, destruction) and none creates or needs a Loan rooted at `o`.
3. **Object-family cases.** A resolved binder admitting `objref`, `objuniq` or `raw` runs those cases; where the engine lacks support for a case Type with an abstract target (an `objuniq` input is not self-rooted today, `IsExclusiveBorrowInput` admits `Uniq` only; R3), that case is a located `UnsupportedOwnership_Kd` naming the case and the STATUS row of the concrete gap, never an accepted owner view. Following object and `raw` pair layers stays deferred (Appendix D); R8 guards the `ObjectPayloadTest` bodies against regression.
4. **Container binders** (`Holder<s/T>`): their methods and accessor bodies have the container's binder in scope and run per case; the G34 storage limit and the accessor gate for pair-typed Property results, if reached, stay their own limits (R14).
5. **G77, G56, G65, G76** stay their own rows; none is folded into G75 or used as evidence that a G75 form works.
6. **`@s`** does not bind today (`Binding.Types.cs:633-636`, `Binding.Conversions.cs:690-693`; only `x@s{a}/T` rows exist). U5 binds it as a per-case acquisition (a borrow for a borrow binding, a same-Type acquisition for an owning one, §8.9) with the receiver rule of C3, or records it as a STATUS limit.
7. **STATUS lines to rewrite in U6:** the uniform-acquisition entry (delete the pair-parameter external-root sentence and the two "held unresolved" limits), the pair-layers entry ("Universal verification treats the layer as the owner case …" → "A definition is verified once per admitted Semantics case with the complete Types of that case; an instance is the closed case its call selects"), the environment-Places entry (E1: "including an exclusive reference with a declared Origin"), new rows for E2 and E3, and rows for `@s` and pair-typed Property results if kept as limits.
8. **Explicit `s/T during a`** is a pair layer whose outer Origin is `a` (B5); its fits use `a`, its case Types use `a`.

## 12. Principles

- **One concept, one canonical form.** One analysis for concrete and generic code; one substitution object for case runs and instances; the only new concept is the Semantics case, which subsumes three dev notions (side channel, owner-view template, single-valued capture and receiver facts). `OuterOrigin` is the one way to obtain a pair occurrence's Origin; `Bare` is one capture rule for Copy bindings, exclusive references and pair bindings; E2 is one store rule for calls and pointer stores; resolution is one criterion on the admitted set.
- **Local reasoning.** A generic body is judged by reading each case as the concrete program it becomes; `o` behaves as a declared Origin; cases are finite, declared and enumerated deterministically with a stated bound.
- **Explicit semantics.** Copy, Reborrow, Move, the active Origin slot and the receiver of each case are explicit in the case Types and plans; nothing is inferred from call sites; a case that neither Copies nor Reborrows is a definition error naming the case.
- **Compiler Server Protocol.** Case facts as catalogued Evidence with roles, a Resource code for the bound, and the structural oracle as an attachable check, inspected on CLI text/JSON and LSP under DIAGNOSTICS §10 against a recorded baseline.
- **User constraints.** From scratch on `dev`; fundamental (the three causes removed by one mechanism); no whitelist (no site list decides resolution; the only table that remains is the concrete engine's flow table, made total); no valid form becomes Unsupported (the plan adds support for B1, B2, B9, B10, B11 and names R14 and §11.3 as the places where an existing limit may stay, explicitly, in STATUS).
