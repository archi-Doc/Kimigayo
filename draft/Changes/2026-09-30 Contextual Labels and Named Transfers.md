# Design Change: 文脈キーワードによるラベル宣言と名前付き制御移動

日付: 2026-09-30

状態: 採用・改訂。原案は `codex/contextual-label-spec` の `c3d9fe5b` に反映済み。本改訂の正式仕様への反映と、コンパイラ実装・実行検証は未完了。

本書はユーザーの依頼による決定記録と、その明示的な改訂である。「現在の仕様」は変更前を指す。別ブランチへの仕様反映、作業ブランチへの統合、実装対応を区別する。正式な必須挙動は `docs/SPEC.md` と参照先を正とする。

## Current Specification — 現在の仕様

`Name:` を `if`・`match`・`for`・`while`・`loop`・`do` の前に置いてラベルを付ける。名前付き `exit`・`yield` では、値を渡すときだけ宛先名の後ろに `:` を置く。

```kimi
let accepted: bool = validate: do
    require score > 0 else => exit to validate: false
    exit to validate: score == 70
```

ラベルは変数・型と別の名前空間に属し、対象構造の本体内だけで有効となる。値なしの `exit to Name`・`yield to Name` は Unit を渡し、`continue to Name` は値を取らない。引数名や Dictionary の区切りと競合するラベル付き式、およびラベル付きの転送値には括弧を要求する。

## Proposed Specification — 新しい仕様

```kimi
let accepted: bool = label validate: do
    require score > 0 else => exit to validate false
    exit to validate score == 70
```

```text
label Name: Construct
exit [Expression] | exit to Name [Expression]
yield [Expression] | yield to Name [Expression]
continue [to Name]
return [Expression]
```

角括弧は省略可能部分を示す。次の規則に統一する。

- `label` は文脈キーワード。Primary の開始位置にある、同一物理行の `label Name :` でラベル構文に確定する。演算子の被演算子や転送値にも適用し、名前解決・型推論・後続構造の解析成功には依存しない。この形に一致しない場合や名前を読む位置では通常名として扱い、変数名、関数名、メンバー名、引数名などに使える。
- `label`・名前・`:`・対象構造のキーワードは同一物理行に置く。対象は従来の六構造に限定し、ラベルの重ね付け、括弧付きの対象、宣言や `require`・`unsafe`・`defer` への付与は認めない。新たな実行本体・値束縛・スコープは作らない。
- `to` の直後は一つの名前だけを宛先として消費する。`label` や `to` という名前も許可する。宛先は呼び出し・修飾名・任意の式には拡張しない。
- `return`・`exit`・`yield` の値の有無は共通規則で決める。キーワード（名前付きなら宛先名）の後で、同一物理行に次のトークンがないか、次が区切りなら値を省略する。区切りは `,`・`)`・`]`・`else`・`=>`・パラメーターリストの境界 `!`、または通常のレイアウト境界・ファイル末尾であり、外側の構文で許可される位置に限る。それ以外では完全な式を必須とし、解析や型検査の失敗後に値なしへ読み替えない。`:` や `and` は区切りではない。
- 名前付き `exit`・`yield` の宛先名と値の開始トークンは隣接させず、空白または同一物理行のブロックコメントで区切る。`-1`、`(value)`、`()`、`[1, 2]`、`.Some(1)`、`..end` は通常の転送値であり、宛先の呼び出し・メンバー参照・添字ではない。整形では空白一つを使い、コメントを保存する。
- 転送キーワード、`to`、宛先、値の式の開始は同一物理行に置く。括弧内でも次行から値を開始しない。開始後の継続は通常の改行規則に従う。省略した値は Unit。`continue` は値を取らず、`return` に名前付き形式は追加しない。`to` は `exit`・`continue`・`yield` の直後だけ文脈キーワードとなるため、値の名前として使う場合は `exit (to)` とする。
- ラベルを理由とする括弧の要求は撤廃するが、優先順位、ヘッダー内の本体付き式、入れ子の `if`、単一項目の本体、字下げの通常規則は維持する。ラベルは新しい区切り領域を作らない。構文の置換では既存の括弧を保存し、削除は結合範囲と区切り領域による意味を保存できる場合に限る。
- `return`・`exit`・`yield` の値を開始すべき位置の `:` は構文エラーとする。値の式を読んだ後の外側の `:` は、その外側の構文に属する。旧表記を代替形式として認めない。

付録 F では Primary の六構造とラベル付き構造の選択肢を次に統合する。`IfExpression` などの対象規則はラベルを含まず、`DoExpression := "do" ExecutableBody` とする。`LabeledSelection` とラベル用の `Iteration` ラッパーは不要になる。既存の演算子・ヘッダー・本体の制約を解除するものではない。

```ebnf
LabelPrefix        := "label" Name ":"
LabelableConstruct := IfExpression | MatchExpression | ForExpression
                    | WhileExpression | LoopExpression | DoExpression
Primary            := ... | LabelPrefix? LabelableConstruct | ...
```

## Changes — 変更点

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| 宣言 | `work: do` | `label work: do` |
| 名前付きの値渡し | `exit to work: value` | `exit to work value` |
| 選択への値渡し | `yield to choice: value` | `yield to choice value` |
| ラベル付き転送値 | `return (work: do => compute())` | `return (label work: do => compute())`（この例の括弧は省略可能） |

ラベルの探索・有効範囲・重複禁止、転送種別ごとの宛先、関数と `defer` の境界、結果型・Never・所有権・後始末の順序は変更しない。例えば `let label = true` と `label label: do` は共存でき、`exit to label label` はラベルを宛先、変数を値として読む。

副作用・注意点は以下のとおり。

- 宣言が一語長くなる一方、値付き転送から記号が一つ減る。`exit to work value` は名前が連続するため視覚的な区切りが弱まるが、`to Name` と値の境界は構文だけで決まる。
- 旧ソース、出力文字列、診断・整形テストの更新が必要になる。旧構文への互換経路は設けない。通常の名前付き引数や Dictionary を誤って旧ラベルとして拒否しない。
- `[exit: value]` と `[exit to work: value]` はともに構文エラーとなる。Unit 転送をキー式として明示するなら `[exit to work (): value]` または `[(exit to work): value]` と書く。値を既に指定した `[exit to work x: value]` のコロンも外側の区切りであり、削除してはならない。いずれも宛先・型の検査は別途行う。
- `exit to work and ok` は値の式を開始できず構文エラーとなる。`exit to work(x)`・`exit to work.value`・`exit to work[0]`・`exit to work..end` のように宛先と値を直結する書き方も認めない。`exit to work/* result */(x)` は通常のコメント規則に従って有効となる。
- `label(...)`、`object.label`、`consume(label: value)` は通常の名前使用を維持する。文脈判定を全位置で一律に適用すると、これらを壊す。
- `return (label choice: if ready => a else => b) + 1` の括弧を削除すると、加算が `else` 側だけに入る。ラベル専用の括弧制約の撤廃は、このような括弧の削除を許可しない。

## Rationale — 変更する理由

目的は、名前より先に役割を示す読み順と、局所的に決まる構文を両立することである。

- **One Concept, One Canonical Form:** 全六構造を一つのラベル文法で扱い、値を取る転送の省略判定を共有する。短縮形や旧形式を併存させない。
- **Local Reasoning:** `label` が名前の役割を予告し、宛先と値の区切りが呼び出しなどへの読み違いを防ぐ。固定個数のトークンと元ソースの位置で判定でき、型やシンボル探索は不要。
- **Explicit Semantics:** 宣言には `label`、参照には `to` を残す。宛先を示す `to` は、値を渡す `exit result` と、ラベルへ移動する `exit to result` を区別する。コロンは宛先名の一部ではなく旧来の区切りであり、削除してもこの区別は失われない。
- **Compiler Server Protocol:** 通常名とラベルの役割、括弧と区切りを AST 上で維持する。修正候補は対象ソースと構文上の役割を確認し、目的・前提・保証を示す。値の開始位置の `:` を削除する候補は必要な空白を補って後続式を転送値にする修正であり、Dictionary を意図する場合の `()` 挿入とは区別する。構文エラーであることだけから意味保存は保証しない。

導入語の候補では、`target` は移動先という用途に寄り、`scope`・`block` は別の構造を作る印象を与える。`named` より役割が直接的な `label` を採用する。`do as Name` は `if`・`for` のヘッダー式との境界規則が別途必要になるため採用しない。

実装では、次の点に対応する。

| 領域 | 問題点と対応 |
| --- | --- |
| 字句・構文解析 | `label` を全面予約語にしない。`Parser.ParseLabeledExpression` とその開始判定を変更し、未完成入力でも次行を誤消費しない。 |
| 引数・コレクション | 旧 `allowLabel` と `DiagnoseUngroupedLabel` はコロン競合を前提とする。ラベルの禁止だけを除き、同じフラグに依存する他の診断・区切り処理を壊さない。 |
| 制御移動 | 宛先を読んだ後は名前なし転送と同じ省略判定・式解析を使う。`:` を汎用の区切り集合へ追加せず、値を読み終えた後の外側のコロンと区別する。宛先と値の隣接はトークン範囲の比較で検出する。 |
| AST・診断・ツール | `LabeledKoto.WriteTo`・`JumpKoto.WriteTo`、ソース範囲、整形・強調表示・修正候補を更新する。往復解析で括弧、宛先、演算子の結合と評価順序を検証する。 |
| Binding・生成・性能 | 意味モデルや生成コードの変更は原則不要。判定時の文字列生成・仮 AST・再解析を避け、同一行検査を重複させない。性能改善は測定前に主張しない。 |
| 検証 | 通常名と Primary の各位置、誤った対象、改行・コメント・隣接、値の省略・不正な開始・完全な式、Dictionary の内外のコロン、括弧の保存、`continue` と関数・`defer` 境界を正負両面で検証する。例・milestones・期待文字列を更新し、Unit と Session 検証を行う。 |

旧構文の変換では宣言・宛先・外側の区切りを区別し、括弧を保存する。字句上の一括置換や、新文法のエラー回復結果だけによる意図の推測は行わない。

## Decision — 最終決定

**改訂案を採用する。** Primary のラベル文法、値の省略判定、宛先と値の非隣接、括弧保存を上記の共通規則で扱う。空白だけを要求する案は既存のコメント規則に合わせて修正した。コロン削除を無条件に意味保存する修正とみなす案は採用しない。

原案の取り込み記録と今回の改訂を区別し、改訂の正式仕様・例・検証要件への反映を行ってから実装を検証する。旧構文の併存、計算された宛先、新しいスコープや制御移動の意味は追加しない。pre-alpha のため言語版の更新や移行文書は要求しない。
