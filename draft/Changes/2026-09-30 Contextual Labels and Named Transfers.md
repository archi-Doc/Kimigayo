# Design Change: 文脈キーワードによるラベル宣言と名前付き制御移動

日付: 2026-09-30

状態: 採用。仕様は `codex/contextual-label-spec` の `c3d9fe5b` に反映済み。実装・実行検証は未完了。

本書はユーザーの依頼により合意内容を記録したものである。「現在の仕様」は変更前を指す。別ブランチへの仕様反映と、作業ブランチへの統合・コンパイラの対応は区別する。正式な必須挙動は `docs/SPEC.md` と参照先を正とする。

## Current Specification — 現在の仕様

`Name:` を `if`・`match`・`for`・`while`・`loop`・`do` の前に置いてラベルを付ける。名前付き `exit`・`yield` では、値を渡すときだけ宛先名の後ろに `:` を置く。

```kimi
let accepted: bool = validate: do
    require score > 0 else => exit to validate: false
    exit to validate: score == 70
```

ラベルは変数・型と別の名前空間に属し、対象構造の本体内だけで有効となる。値なしの `exit to Name`・`yield to Name` は Unit を渡し、`continue to Name` は値を取らない。引数名や Dictionary の区切りと競合するラベル付き式、およびラベル付きの転送値には括弧を要求する。

## Proposed Specification — 新しい仕様

```kimi
let accepted: bool = label validate: do
    require score > 0 else => exit to validate false
    exit to validate score == 70
```

```text
label Name: Construct
exit [Expression] | exit to Name [Expression]
yield [Expression] | yield to Name [Expression]
continue [to Name]
return [Expression]
```

角括弧は省略可能部分を示す。次の規則に統一する。

- `label` は文脈キーワード。式の開始位置にある、同一物理行の `label Name :` でラベル構文に確定する。名前解決・型推論・後続構造の解析成功には依存しない。それ以外では変数名、関数名、メンバー名、引数名などに使える。
- `label`・名前・`:`・対象構造のキーワードは同一物理行に置く。対象は従来の六構造に限定し、ラベルの重ね付け、括弧付きの対象、宣言や `require`・`unsafe`・`defer` への付与は認めない。新たな実行本体・値束縛・スコープは作らない。
- `to` の直後は一つの名前だけを宛先として消費する。`label` や `to` という名前も許可する。宛先は呼び出し・修飾名・任意の式には拡張しない。
- `exit`・`yield` では、宛先の後ろの同一行に式の開始トークンがあれば、そこから完全な値の式を読む。`-1`、`(value)`、`()`、`[1, 2]`、`.Some(1)`、`..end` はいずれも値である。括弧をラベルの呼び出しと解釈せず、解析や型検査の失敗後に値なしへ読み替えない。
- 転送キーワード、`to`、宛先、値の式の開始は同一物理行に置く。括弧内でも次行から値を開始しない。開始後の継続は通常の改行規則に従う。値の省略は従来どおり Unit。`continue` は値を取らず、`return` に名前付き形式は追加しない。
- ラベルを理由とする括弧の要求は撤廃する。ヘッダー内の本体付き式、入れ子の `if`、単一項目の本体、字下げの基準など、通常の規則は維持する。ラベルは新しい区切り領域を作らない。
- 名前付き転送は `:` を消費しない。外側の構文で必要なコロンは、その構文に属する。旧表記を代替形式として認めない。

## Changes — 変更点

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| 宣言 | `work: do` | `label work: do` |
| 名前付きの値渡し | `exit to work: value` | `exit to work value` |
| 選択への値渡し | `yield to choice: value` | `yield to choice value` |
| ラベル付き転送値 | `return (work: do => compute())` | `return label work: do => compute()` |

ラベルの探索・有効範囲・重複禁止、転送種別ごとの宛先、関数と `defer` の境界、結果型・Never・所有権・後始末の順序は変更しない。例えば `let label = true` と `label label: do` は共存でき、`exit to label label` はラベルを宛先、変数を値として読む。

副作用・注意点は以下のとおり。

- 宣言が一語長くなる一方、値付き転送から記号が一つ減る。`exit to work value` は名前が連続するため視覚的な区切りが弱まるが、`to Name` と値の境界は構文だけで決まる。
- 旧ソース、出力文字列、診断・整形テストの更新が必要になる。旧構文への互換経路は設けない。通常の名前付き引数や Dictionary を誤って旧ラベルとして拒否しない。
- `[exit to work: value]` は、Unit を渡す転送をキー式とする Dictionary として解析される。`value` を渡す転送ではない。宛先と型の検査は別途行う。旧コードの機械的置換や診断修正で、外側の区切りまで削除してはならない。
- `label(...)`、`object.label`、`consume(label: value)` は通常の名前使用を維持する。文脈判定を全位置で一律に適用すると、これらを壊す。

## Rationale — 変更する理由

目的は、名前より先に役割を示す読み順と、局所的に決まる構文を両立することである。

- **One Concept, One Canonical Form:** 全六構造で `label Name:`、名前付きの値渡しで `to Name Expression` に統一する。短縮形や旧形式を併存させない。
- **Local Reasoning:** 導入位置で `label` が名前の役割を予告する。固定個数のトークンによる判定と一つの宛先名により、型やシンボル探索なしで構文を決定できる。
- **Explicit Semantics:** 宣言には `label`、参照には `to` を残す。宛先を示す `to` は、値を渡す `exit result` と、ラベルへ移動する `exit to result` を区別する。コロンは宛先名の一部ではなく旧来の区切りであり、削除してもこの区別は失われない。
- **Compiler Server Protocol:** 通常名とラベルの役割を AST 上で維持し、診断・編集・整形が同じ境界規則を使える。修正候補は該当ソースと構文上の役割を確認して提示する。

導入語の候補では、`target` は移動先という用途に寄り、`scope`・`block` は別の構造を作る印象を与える。`named` より役割が直接的な `label` を採用する。`do as Name` は `if`・`for` のヘッダー式との境界規則が別途必要になるため採用しない。

実装では、次の点に対応する。

| 領域 | 問題点と対応 |
| --- | --- |
| 字句・構文解析 | `label` を全面予約語にしない。`Parser.ParseLabeledExpression` とその開始判定を変更し、未完成入力でも次行を誤消費しない。 |
| 引数・コレクション | 旧 `allowLabel` と `DiagnoseUngroupedLabel` はコロン競合を前提とする。ラベルの禁止だけを除き、同じフラグに依存する他の診断・区切り処理を壊さない。 |
| 制御移動 | `ParseJumpExpression` のコロン依存を除き、式開始判定・同一行判定・完全な式の解析を揃える。括弧、符号、先頭ドット、範囲、入れ子のラベル、外側の区切りを検証する。 |
| AST・診断・ツール | `LabeledKoto.WriteTo`・`JumpKoto.WriteTo` を更新する。ソース範囲、構文の往復、整形・強調表示・コード修正の該当処理を点検し、修正後の宛先と評価順序を保存する。 |
| Binding・生成・性能 | 意味モデルや生成コードの変更は原則不要。有限の先読みで実装し、判定のための不要な文字列生成や探索を追加しない。性能改善は測定前に主張しない。 |
| 検証 | 通常名としての `label`、誤った対象、改行、旧構文の拒否、Dictionary、値なし、`continue`、関数・`defer` 境界を正負両面で検証する。例・milestones・期待文字列を更新し、Unit と Session 検証を行う。 |

特に `exit to selection: match ...` を一括置換すると、転送の宛先を宣言と誤認し得る。構文上の役割を区別して変換し、結果を確認する。意味規則に本質的な衝突は見つかっていないが、実装の正当性は実行検証で確定する。

## Decision — 最終決定

**採用する。** `label` は文脈キーワードとし、全ラベル宣言を `label Name: Construct`、値付きの名前付き `exit`・`yield` をコロンなしに統一する。旧構文の併存、計算された宛先、新しいスコープや制御移動の意味は追加しない。

仕様・例・検証要件は別ブランチの `c3d9fe5b` に反映済み。静的な整合性確認は完了したが、パーサーと構文出力の実装、実行テスト、新表記のマイルストーン再検証は残る。pre-alpha のため言語版の更新や移行文書は要求しない。本書は決定記録として取り込み済みに登録し、以後は固定する。
