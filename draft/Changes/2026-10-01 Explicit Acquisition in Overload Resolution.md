# 仕様修正案：オーバーロード競合時の明示取得

作成日：2026-10-01  
状態：採用判断前。正式仕様への取り込み・実装は未実施。

## 1. 現仕様の問題点

[SPEC §10.2.1](../../docs/spec/10-overload-resolution-and-inference.md#1021-inference-and-adaptation-classes) は、裸の Place の値渡しに Copy の証明を要求し、適用可能なら共有借用より優先する。

```kimi
struct Node
    Self is Copy

    var number: i32

    public init(number: i32)
        self.number = number

func process(value: Node) -> i32 => 1
func process(value: ref/Node) -> i32 => 2

let node = Node.init(10)
process(node) // 現仕様：Copy なら 1。Self is Copy を削除すると 2。
```

複製能力を追加しただけで、同じ呼出しが別の処理を実行する。条件付き Copy でも同様であり、ジェネリック定義時と具体型の呼出しで選択が異なり得る。呼出し側の意図が Copy 能力と適応順位に隠れるため、原則2「局所的な推論」と原則3「明示的な意味論」に負担がある。

## 2. 理想的な動作と採用案

**同じ Place を値渡しするか共有借用するかが候補間で競合する場合、Copy 能力にかかわらず明示取得を要求する。** 単一の取得方法しか残らない呼出しは、従来どおり省略できる。

上の宣言に対する各呼出しを独立に考える。

| 呼出し | 提案後の意味 |
| --- | --- |
| `process(node)` | Copy／Non-Copy／Copy 未証明のいずれも明示取得要求 |
| `process(node@ref)` | 元の Place を共有借用し、借用版を選択 |
| `process(node@copy)` | Copy の証明があれば値渡し版を選択。元の値は利用可能 |
| `process(node@move)` | Move が合法なら値渡し版を選択。元の値は Moved |
| `process(Node.init(10))` | 一時値を値渡し版へ移譲。追加の Copy は不要 |

新しい構文や選択演算子は追加しない。`@copy`・`@ref`・`@move` の既存の型・取得結果を通常の解決に渡す。既存の同型取得 `node@Node` も有効だが、意図の表現には `@copy` を推奨する。

以下の例は §1 の `Node` と `process` を必要に応じて共有する独立した断片であり、エラーと記した行は提案後の意図した拒否例である。

## 3. 仕様の変更点

### 3.1. 競合判定用の候補

通常の適用可能候補とは別に、次の手順で競合を検査する。

1. 名前検索を確定する。アクセス、型引数、引数の個数・ラベル、型推論、正規化、宣言された Constraints、条件付きメンバーの前提、独立した期待結果型は、§10.1／§10.5 の手順と推論境界に従う。
2. その検査中、**明示引数の未取得の owner 値 Place を、その完全型で値渡しするための Copy 証明だけ**を候補除外に使わず、取得条件として記録する。他の不適合は候補を除外する。
3. 残った候補について §3.2 の競合を判定する。競合があればエラーとし、順位付けしない。
4. 競合がなければ記録した Copy 条件を検査し、通常の適用可能候補に §10.4 の Best Candidate を適用する。選択後に §10.6 の使用合法性を検査する。

保留はこの呼出しの静的検査内に限る。Copy の仮定、暗黙 Move、暗黙の制約追加、実体化までの検査延期は認めない。Copy が Refuted でも Unknown でも競合判定には残せるが、Unknown を Non-Copy と解釈しない。型や宣言自体の Error は競合の証拠にせず、元のエラーと依存関係を報告する。候補検査は計画の記録のみであり、引数・既定値を実行したり Loan を開始したりしない。

明示的な `T is Copy`、型形成に必要な Copy、receiver・既定値・匿名関数 capture 内の Copy 条件は保留しない。宣言条件そのものによる候補差を一般的に禁止する提案ではない。

競合判定に残すのは、保留対象以外の必要条件を証明できた候補に限る。他の Constraints が Unknown の場合は既存の依存・証明期限に従い、候補の成立や不成立を仮定しない。

### 3.2. 競合の定義

次のすべてを満たす場合、対象引数に明示取得を要求する。

- §3.1 の候補が二つ以上ある。
- 同じソース引数式が、未取得の owner 値の Place `P` を表すことを、現在の静的証拠から確定できる。
- 一方は `P` の正規化済み完全型 `U` を値渡しし、他方は §10.2 の新規共有借用によって `ref/U` を受け取る。`U` の内部 Origin は保持し、通常の Origin 適合を満たす。

型推論後の取得計画を比較し、宣言の綴りや `@` の有無で判定しない。名前付き引数も同じソース式同士を比較する。既定値は比較対象外であり、receiver は §7.3 の単一 receiver shape を維持する。

別の引数の型不一致や独立した期待結果型によって候補が除外されれば、競合しない。一方、適応順位、部分型による優先、非ジェネリック優先、既定値の使用数、第三候補の優位性では競合を解消しない。順位付け前に取得方法を確定するためである。

```kimi
func select(value: Node ! flag: bool) -> i32 => 1
func select(value: ref/Node ! flag: i32) -> i32 => 2

let node = Node.init(10)
select(node, flag: true) // 借用版は flag の型で除外。Node が Copy なら値渡し版。
select(node, flag: 0)    // 値渡し版は flag の型で除外。共有借用版。
```

複数位置で競合する場合、一つを明示しても別の競合が残り得る。明示取得後にも通常の適応を許すためである。

```kimi
func combine(left: Node, right: ref/Node) -> i32 => 1
func combine(left: ref/Node, right: Node) -> i32 => 2
let a = Node.init(1)
let b = Node.init(2)
combine(a@copy, b)      // b に競合が残る。a の適応順位では救済しない。
combine(a@copy, b@ref)  // 最初の候補。Node は read Type ではない。
```

### 3.3. 適用範囲と既存規則

- 対象の Place はローカル、フィールド、要素、Place 戻り値、`@follow` で選んだ Place を含む。括弧は透過的。`@follow` だけでは値を取得しない。
- 一時値・リテラル・通常の値戻り値は対象外。Place からの暗黙 Copy を必要とせず、既存の適応順位を使う。`Never` は取得対象の値を供給しない。
- 既存の参照値の Copy／Reborrow、read Type の暗黙値読み、`uniq`、object 系の適応順位は変更しない。owner 値の Place を共有・排他的な経路から参照している場合は対象に含む。
- `r: ref/U` に対する `r@copy` は参照自体の Copy、`r@ref` は参照スロットの借用である。参照先を選ぶ場合は既存の `r@follow` を用いる。
- `@copy` は「値渡し候補以外を禁止する指定」ではない。借用版しかないなら、Copy した一時値を借用できる。寿命は延長しない。
- 初期化、Loan、Move、unsafe、Property 権限の失敗による候補の再選択は認めない。
- 直接呼出し、メソッドの明示引数、コンストラクター、Contract 経由の候補選択を同じ規則で扱う。固定シグネチャの関数値呼出しと、そのシグネチャによる関数参照の選択には、この取得競合は生じない。

```kimi
func inspect(value: ref/Node) -> i32 => 2

let node = Node.init(10)
inspect(node)      // 競合なし。元の node を暗黙共有借用。
inspect(node@copy) // Copy した一時値を共有借用。
let r = node@ref
process(r)        // 既存の参照値。借用版を選択。
process(r@follow) // owner 値の Place に戻るため明示取得要求。
```

### 3.4. ジェネリックと推論境界

ジェネリック本体は公開された Constraints だけで判定し、実体化時に候補を再選択しない。条件付き Copy の取得証明が未成立でも、対応する値渡し形を競合判定から消さない。

```kimi
func tag<T>(value: Option<T>) -> i32 => 1
func tag<T>(value: ref/Option<T>) -> i32 => 2

func forward<T>(value: Option<T>) -> i32
    return tag(value) // 定義時に明示取得要求。T の実体化を待たない。

func forwardBorrow<T>(value: Option<T>) -> i32
    return tag(value@ref) // T が Copy かどうかによらず借用版。

func forwardCopy<T>(value: Option<T>) -> i32
    T is Copy
    return tag(value@copy) // Option<T> の Copy を証明し、値渡し版。
```

`Option<T>` は現仕様の条件付き Copy 型である。上の `forward` は意図した拒否例であり、修正例は後続の二関数で示す。

§10.5 の入れ子呼出し・匿名関数本体の一回検査を維持する。Copy 条件を保留中の候補を、共通期待型の計算で勝手に除外してはならない。必要な型・カテゴリを確定できない場合は既存の推論境界エラーとし、注釈または明示取得を求める。候補ごとの本体再解析や型の列挙は行わない。

保証するのは、同じ候補形の間で、裸の取得に必要な Copy 能力だけを理由に値渡し／共有借用が暗黙に切り替わらないことである。具体型の判明、宣言条件の変更、期待型や候補集合の変更による一般的な解決差は保証対象外とする。

### 3.5. 診断

Language Error として専用コードを設ける。仮称は `ExplicitArgumentAcquisitionRequired_Kd`。

- 主範囲は競合する引数式。Reason は「値渡し `U` と共有借用 `ref/U` の取得方法を明示する必要がある」とする。
- 関連位置は候補の宣言シグネチャと対応パラメーター。Non-Copy 時に「両方が適用可能」とは説明しない。
- Advice は `@ref`、Copy を証明できる場合の `@copy`、移譲を意図し Take が可能な場合の `@move`。後続の Loan・寿命検査等も必要であると区別する。
- 修正案が保証するのは当該取得競合の解消までであり、呼出し全体の成功ではない。意味の異なる修正を自動選択しない。
- 情報の省略上限下でも競合する取得方法と必要条件を残し、独立したエラーを隠さない。

複数の競合位置はソース順で示し、同じ呼出しの同じ競合を候補対ごとに重複報告しない。

## 4. 実装計画

現行の `AdaptInput` は Copy 未証明で直ちに失敗し、`TryCandidate` 内の型推論からも呼ばれる。`SelectBest` の変更だけでは実現できない。構文・ABI・実行時表現の変更は不要であり、Binding の候補検査と診断の変更で実現可能と判断する。コストと対応範囲は実装・測定による確認が必要である。

| 単位 | 作業と完了条件 |
| --- | --- |
| U1：取得計画の分離 | `Binding.ArgumentOperations.cs` と `Binding.Calls.cs` で型不適合と Copy 取得条件を分離する。`InferInput` を含む早期除外を整理し、単一候補の合法性・推論を維持する。最小再現と正の対照を用意する。 |
| U2：競合判定と診断 | `Binding.CandidateEvaluation.cs` と呼出し確定経路に §3 の判定を追加する。`BindingModel.cs`、診断カタログ、`Binding.cs`／`Binding.Diagnostics.cs` に構造化した事実と位置を追加する。定義時検査と CLI／LSP の説明を確認する。 |
| U3：相互作用と費用 | 下表の回帰、再 Binding、scratch 再利用、候補数・引数数を増やした測定を行う。所有権・コード生成は確定済みの既存取得計画を消費する。 |

Copy 条件は候補ごとの再利用可能な領域に保持する。競合判定は各ソース引数について「値渡し形がある」「新規共有借用形がある」と代表候補を一走査で集計すればよく、候補対の全比較は不要である。候補数 `C`、引数数 `A` に対して、既存取得計画を読む追加判定は `O(CA)` 時間・`O(A)` の再利用領域で実現する。型推論・証明・既存の順位比較の費用は別であり、早期除外の減少による実コストを測定する。

診断用データは失敗時に確保し、既存の成功経路のゼロ割当て保証を維持する。Copy 不成立だけの理由で保持する候補の情報も、再 Binding 時に確実に破棄・再構築する。

| 検証軸 | 必須の対照例 |
| --- | --- |
| Copy と明示取得 | Copy opt-in の追加・削除、条件付き Copy、未証明。裸の競合拒否と `@ref`／合法な `@copy`・`@move` の選択 |
| 型と候補 | 単一候補、型不一致、別名、内部 Origin、名前付き・複数引数、既定値、期待結果型、第三候補、宣言順の入替え、取得 Copy と明示 Copy 制約の区別 |
| 場所と値 | 所有値・共有／排他的経路の Place、要素、Place 戻り値、`@follow`、一時値、リテラル、既存参照、Never |
| 推論 | 条件付き Copy 型のジェネリック、明示型引数、特殊化、入れ子呼出し、匿名関数の共通期待型 |
| 呼出し経路 | 通常関数、メソッドの明示引数、コンストラクター、Contract dispatch、固定シグネチャの関数値・関数参照の対照 |
| 実行と使用合法性 | 左から右に一回評価、元の値の利用、Move 後の拒否、Loan／unsafe 失敗時の再選択禁止、破棄一回 |
| 診断と再利用 | 正確な範囲、候補証拠、修正条件、前提エラー・独立エラー、CLI／LSP、上限、再 Binding の古い状態除去、割当て回帰 |

各単位を「再現・実装・focused tests」で進め、`scripts/verify.ps1 -Class ... -Fixtures ...` で正式検証してから記述的なコミットを作る。明示選択後の実行と既存の一時値選択は native O0／O2 で検証する。最後に一度 `-Mode Session` を実行する。計測は `src/Benchmark`、証拠は `artifacts/verify/`、測定結果は `artifacts/benchmarks/` に置く。NativeAOT は実行しない。

## 6. 設計評価と代替案

| 案 | 利点 | 欠点・判断 |
| --- | --- | --- |
| 本案：Copy 取得条件を保留して競合検査 | Copy 追加前から意図が固定され、Non-Copy と条件付き Copy で同じ書き方になる | 適用可能候補とは別の検査状態が必要。以前は有効だった Non-Copy 呼出しにも明示が必要。推奨。 |
| 適用可能な二候補だけをエラーにする | 実装と候補モデルが小さい。Copy 追加後の暗黙切替を防げる | Non-Copy では借用、Copy ではエラーとなり、明示の要否が能力に依存する。簡素さを優先する場合の代替。 |
| 共有借用を常に優先する | 代表例では Copy 追加後も借用を選べる | 意図を順位に隠し、他の引数の順位との関係も残る。採用しない。 |
| 値渡し／借用の同名宣言を禁止する | receiver と同様に宣言だけで取得方法を固定できる | 他引数で明確に区別できる組も失う。ジェネリック代入後の重なりの判定まで広げると単純でない。今回は採用しない。 |

本案の利点は取得意図の安定性にあり、実行速度の改善ではない。追加費用は候補状態・診断・推論境界に限定できるため、局所的な推論を重視する本言語では見合うと判断する。ただし API 利用時の記法負担と実測したコンパイル費用を採用判断に含める。

精査では、Copy 未証明を理由に宣言条件まで無視すること、明示取得を専用の候補選択指定と扱うこと、推論途中で保留候補を除外することが矛盾の原因になると確認した。§3 でそれぞれを禁止し、複数引数の反例を追加した。また、候補対の比較を引数ごとの集計へ簡素化した。Copy の取得証明だけを変えても、この集計対象と取得形が変わらないため、対象範囲の安定性を静的に説明できる。

Kimigayo Principles との対応は次のとおり。

- **原則1：** 新しい選択構文を作らず、既存の取得操作と正規化済み型を使う。処理目的が違う API は別名で表す。
- **原則2：** 呼出し位置と公開シグネチャで競合を説明し、実体化・探索順・Loan 状態で再選択しない。
- **原則3：** 所有権の扱いが競合する位置だけ明示し、競合のない通常呼出しは簡潔に保つ。
- **原則4：** 診断の原因・関連位置・修正条件を構造化し、同じソースと構成に対応する検証証拠を残す。

## 7. 決断を要する事項
