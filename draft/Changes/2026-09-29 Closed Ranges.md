# 仕様変更案：半開区間への統一と ClosedRange

日付: 2026-09-29

状態: 最終提案。正式仕様への取り込み・実装・検証は未実施。

本書は採用後の仕様を定める。本書が変更する事項は `docs/SPEC.md` とその参照先に優先し、変更しない事項には既存仕様を適用する。基準は、「整数範囲と位置範囲」（2026-09-28）を取り込んだ後の SPEC §4.6.2–§4.6.4 である。

**用語**: 本書では、範囲を 2 つの観点で呼び分ける。

- **範囲の分類**: 位置の範囲（`IndexRange`・`ResolvedRange`）か、整数の範囲（`Range<T>`・`ClosedRange<T>`）か。
- **区間の形**: 半開か、閉か。

## 1. Current Specification — 現在の仕様

### 1.1. 仕様

- **区間の形**: `..`（半開）と `..=`（閉）は同じ型の値を作り、フィールド `isInclusive: bool` で区別する。
  - 対象は `Range<T>`（`start: T`・`end: T`）と `IndexRange`（`start: Index`・`end: Index`）である。
  - `ResolvedRange` は常に半開である。
- **種別**: 両端が整数なら `Range<T>` になる。Index の境界か省略があれば `IndexRange` になり、`..=b`（開始の省略）もこちらに入る。
- **等価性**: `isInclusive` も比較するので、`0..3 != 0..=2` となる。
- **解決**: 半開は `0 <= s <= e <= L` のとき `[s, e)`、閉は `0 <= s <= e < L` のとき `[s, e + 1)` となる。
- **Index**: 格納フィールド `offset: isize`・`isFromEnd: bool` を公開する。

### 1.2. 実装

- **フラグの扱い**: `resolve`・`tryResolve` は、実行時に `isInclusive` で分岐する。反復入口は、このフラグを共用の `RangeIterator<T>` へ真偽値の引数で渡す。
- **添字の経路**:
  - 整数境界の半開の範囲構文（`values[a..b]`）は、範囲値を作らずに直接選択する。
  - それ以外の添字（`..=`、Index の境界、保存した範囲値、Index）は、キーを解決する経路を通る。この経路では、受け手がパス形の Place に限られる。
- **Index の値の生成**:
  - `^x` は、コンパイラーが Index の 2 フィールドを直接書き込む。
  - 範囲の整数境界は、`Index.unchecked` が不正値を offset -1 の番兵にしておき、`IndexRange.init` が左から検査して Abort する。

## 2. Proposed Specification — 新しい仕様

### 2.1. 型と共通規則

| 型 | 区間の形 | 作り方 | 反復 |
| --- | --- | --- | --- |
| `Range<T>` | 半開 `[start, end)` | 両端が整数の `a..b` | `RangeIterator<T>` |
| `ClosedRange<T>`（新設） | 閉 `[start, end]` | 両端が整数の `a..=b` | `RangeIterator<T>` |
| `IndexRange` | 半開 | Index の境界を含む `a..b`、`a..`・`..b`・`..` | なし |
| `ResolvedRange` | 半開 | `indices`・`resolve`・`tryResolve` | `RangeIterator<isize>` |

1. **区間の形は、値ではなく型が表す。** どの範囲型も包含フラグを持たない。
2. **位置の範囲は半開とする。** 閉区間は、整数の範囲 `ClosedRange<T>` だけとする。
3. **`start`・`end` は、範囲構文の左右の境界に対応する。** 閉区間でも、終端を ±1 して調整することはない。

### 2.2. 構文と種別

| 構文 | 結果 |
| --- | --- |
| 両端が整数の `a..b` / `a..=b` | `Range<T>` / `ClosedRange<T>` |
| Index の境界を含む `a..b`、`a..`・`..b`・`..` | `IndexRange` |
| Index の境界を含む `a..=b` | 型エラー（位置の範囲は半開） |
| `..=b`・`..=` | 構文エラー（`..=` には両端が必要） |

```ebnf
RangeExpression      := OrExpression
                      | OrExpression? ".." OrExpression?
                      | OrExpression "..=" OrExpression
```

- **型の規則**: `Range<T>` の型の規則は、`ClosedRange<T>` にもそのまま適用する。両端で同じ T を使うこと、リテラル式への伝播、Scalar read が該当する。
- **リテラル式**: 両端がリテラル式の `a..=b` は、既定で `ClosedRange<i32>` になる。期待型に適合するのは、演算子に対応する型だけとする。

```kimi
let a = 0..10             // Range<i32>
let b = 0..=255@u8        // ClosedRange<u8>。半開では書けない。
let c = 1..^1             // IndexRange
let d = 1..=^2            // エラー: 位置の範囲は半開。
let e = ..=3              // 構文エラー: 両端が必要。
let f = (0..3) == (0..=2) // エラー: 型が異なる。
```

### 2.3. `ClosedRange<T>`

`Range<T>` とは、次の 3 点だけが異なる。

- **区間**: `end` を含む。
- **解決**: `0 <= s <= e < L` のとき `[s, e + 1)` となる。
- **反復**: `end` まで生成し、T の最大値でも加算しない。

次の点は `Range<T>` と同じである。

- **型と能力**: `T is PrimitiveInteger`。Owned・Copy・Equatable で、等価性は `start` と `end` で決める。
- **公開メンバー**: 読み取り専用の `start`・`end`、`resolve`・`tryResolve`、反復の三入口。
- **生成**: 範囲構文だけで作る。逆転した値（`start > end`）も作れ、反復の入口で Abort する。空の閉区間はない。
- **ないもの**: `length`・`isEmpty` は設けない。

```kimi
var last: u8 = 0
for x in 250@u8..=255   // 250 から 255 まで。255 の後で加算しない。
    last = x
let values: [4 of i32] = [10, 20, 30, 40]
let middle = values[1..=2] // 20 と 30 の共有 Slice
let reversed = 2..=1       // 構築は成功する。
for x in reversed          // 反復の入口で Abort する。
    ()
```

### 2.4. 解決・スライス・反復

| 型 | 解決の成功条件 | 結果 |
| --- | --- | --- |
| `Range<I>`・`IndexRange` | `0 <= s <= e <= L` | `[s, e)` |
| `ClosedRange<I>` | `0 <= s <= e < L` | `[s, e + 1)` |

- **スライス**: `x[r]` と `trySlice(r)` は `ClosedRange<I>` も受け付ける。`Slice<T>` には `trySlice<I>(range: ClosedRange<I>)` を加える。
- **反復**: `Range<T>`・`ClosedRange<T>`・`ResolvedRange` は、いずれも `RangeIterator` を返す。
- **削除する記述**: 「包含の終端 `^0` は無効」。もう書けないためである。

```kimi
let a = (1..=3).resolve(4)    // [1, 4)
let b = (1..4).resolve(4)     // [1, 4)。a == b
let c = (0..=4).tryResolve(4) // None: 終端 4 は要素ではない。
let d = (0..4).tryResolve(4)  // Some([0, 4))
```

### 2.5. `Index` のプロパティ

`offset: isize`・`isFromEnd: bool` を、格納フィールドから読み取り専用の computed Property（§11.2.2）に変える。

- **変わらないもの**: 取得する値と、`init`・`resolve`・`tryResolve`・等価性。
- **変わるもの**: 格納場所への借用は提供しない。`@ref` は、§11.2.3 の computed `get` の結果に対する共通規則に従う。

```kimi
// inspect は ref/isize を受け取る。
inspect(index.offset@ref) // OK: 呼び出し中だけの一時値の借用。
let view = index.offset@ref
inspect(view)             // エラー: 初期化子の一時値は終了している。
let saved = index.offset
inspect(saved@ref)        // OK: ローカルを借用する。
```

### 3.2. 書き換えの規則（診断）

拒否した `..=` に対しては、次の書き換えを示す。

**解釈**: 拒否した位置の範囲 `a..=e` は、終端 e を含む位置の閉区間とみなす。成功条件は `0 <= s <= e < L`、結果は `[s, e + 1)` である。`Range<T>` を求める箇所に置かれた `ClosedRange<T>` は、その値自身の意味で扱う。

**規則**: 閉じた終端を次の境界に置き換えて、区間の形を半開にする。

- 範囲の分類は変えず、元の境界式の評価順と評価回数を保つ。
- 次の境界がリテラル式なら定数に畳み込む。その結果が `^0` になるなら、終端を省略する（`a..=^1` → `a..`）。

| 閉じた終端 | 次の境界 | 前提 |
| --- | --- | --- |
| 位置の範囲の整数 j（`..=b` など） | `j@isize + 1`（j が isize なら `j + 1`） | ― |
| `^n` | `^(n - 1)` | ― |
| `Index.init(j)` | `Index.init(j + 1)` | ― |
| `Range<T>` を求める箇所の `ClosedRange<T>` の j | `j + 1` | j が T の最大値でない |
| 実行時の Index の値 | 候補を出さない（方向が実行時に決まる） | ― |

- **保証**: 解釈した意味で成功するとき、反復で生成する値と解決の結果は同じになる。
  - 位置の範囲で成功するなら j < L ≤ isize.max なので、isize への変換も加算も失敗しない。
  - `j + 1` を元の型のまま計算すると、`b: u8 = 255`・長さ 300 のときに溢れてしまう。
- **保証しないもの**:
  - **境界の観測値と等価比較**: `0..=2` の `end` は 2、`0..3` の `end` は 3 である。境界そのものを扱う API は、`ClosedRange<T>` を受け取る宣言に改めるほうが適切である。
  - **成功条件を満たさない場合の結果**: 1 だけ逆転した範囲（長さ 3 の `^1..=^2`）や n = L + 1（長さ 0 の `0..=^1`）は、書き換え後は空区間として成功する。j = -1 などは、別の箇所で Abort することもある。
- **追加候補**: 位置の範囲の `..=b`（b が整数）では、使用箇所が `ClosedRange<T>` を受け付けるときに限り、`0..=b` も示す。受け付けるのは、スライスの添字と `trySlice` の引数である。
- **示し方**: 構造化した修復候補（§23.5）は未実装なので、当面は診断の `Fix` の文として示す。§23.3.2 により、この文から機械的な編集は推論しない。本節は、CSP を実装するときの候補の定義にも使う。

```kimi
let b: u8 = 255
let s = values[..=b]          // 構文エラー。Fix: values[..(b@isize + 1)] または values[0..=b]
let t = values[i..=^2]        // 型エラー。Fix: values[i..^1]
let u = values[i..=^one()]    // 型エラー。Fix: values[i..^(one() - 1)]。one() の評価は消さない。
take(0..=2)                   // take は Range<i32> を受け取る。Fix: take(0..3)
```

### 3.3. 実装方針

1. **範囲式の処理順**: 種別の決定 → 境界の評価（左から各 1 回）→ `IndexRange` なら整数境界を左からIndex化 → 構築、の順とする。
   - **整数の範囲**: `Range<T>`・`ClosedRange<T>` はIndex化しない。`-3..3` はそのまま構築する。
   - **Index化を遅らせる形**: 右境界の評価後まで遅らせる必要があるのは、左が整数・右が Index の `IndexRange`（`1..^1` など）だけである。この形は、左境界を元の型のまま受け取る内部生成関数で構築し、関数の中でIndex化する。
   - **それ以外の形**: `a..`・`..b` と右側の整数境界は、評価の直後にIndex化しても順序は変わらない。接頭辞 `^` は、現行どおり評価中にIndex化する。
   - **中間値**: 不正な Index も、失敗を運ぶ `Option` も作らない。
2. **Index の値の生成と格納**:
   - **生成**: `^x` と範囲の整数境界は、どちらも内部の Kimi 関数 1 組（先頭相対・末尾相対）で Index の値を作る。`FromEnd` 操作とその専用の変換は廃止する。
   - **直接選択**: Index の値を作らず、解決と融合した検査を生成する（§4.6.4 の融合）。失敗条件は Kimi の関数と一致させる。
   - **コンパイラーの依存**: コンパイラーが Index について依存するのは、公開契約と、呼び出す内部関数の署名だけとする。合成呼び出しは宣言を名前で 1 つに固定する（`ContainerMember`）ので、合成呼び出しが呼ぶ内部関数には、すべて異なる名前を付ける。
   - **格納**: Core.kimi の private な `isize` 1 個とする。先頭相対の n は `n`、末尾相対の n は `~n`（= `-1 - n`）で表す。すべてのビットパターンが有効な Index を表すので、番兵はない。符号化は宣言コメントに記し、サイズと符号化はライブラリのテストで確かめる。
   - **格納値の使い方**: Index 自身の関数は、格納値 raw を直接使う。Index 以外（`IndexRange` など）は、Index の関数を通す。等価比較は raw の比較 1 回で済む。
   - **解決**: `L >= 0` を確かめる。次に位置 p を「raw が 0 以上なら raw、負なら `L + raw + 1`」とし、`0 <= p and p <= L` を確かめる。途中の計算は溢れず、方向の違いは加算の選択だけになる。
     - Kimi ではこの形で書き、符号なし比較への変形はコンパイラーの最適化に任せる。
     - 検査付き変換 `@usize` は、負の p で Abort してしまうので使わない。
3. **スライス**: 範囲の種別ごとの境界検証で半開の両端を得て、共通の適用処理へ渡す。
   - **閉区間**: `ClosedRange<I>` は、`0 <= s <= e < L` を確かめた後にだけ `e + 1` を計算する。
   - **直接選択**: 整数境界の範囲構文は、`..` も `..=` も範囲値を作らずに直接選択する。
   - **残る制約**: Index の添字、Index の境界を含む範囲構文、保存した範囲値では、受け手をパス形の Place に限る現行の制約が残る。これは `docs/STATUS.md` に記録する。解消は別の単位で、共通規則「受け手を 1 回だけ評価し、その長さでキーを解決する」によって行う。
4. **反復**: `RangeIterator<T>` を共用し、入口の内部関数を区間の形ごとに分ける。真偽値の引数は使わない。
   - **半開用**: `[s, e)` で始める。`ResolvedRange` は、順序が保証済みなので順序の検査を省く。
   - **閉用**: `start <= end` を確かめる。終端が T の最大値でなければ `[s, e + 1)` として始め、最大値のときだけ終端のフラグを使う。
   - **効果**: よくある `for i in 0..=n` が、インライン化の後に `0..n + 1` と同じ標準的なループになる見込みである。効果は §6 で確かめる。
5. **Kimi API の規約**（`docs/STYLE.md` §3.2 に加える）:
   - **位置の区間を受け取る API**: 添字 `x[r]` と同じ 4 つの型（`IndexRange`・`Range<I>`・`ClosedRange<I>`・`ResolvedRange`）を受け付け、内部では解決した `ResolvedRange` に処理を任せる。
   - **整数の値の区間を受け取る API**: `Range<T>` を受け取るなら、`ClosedRange<T>` も受け取る。

### 3.5. 実装上の注意

1. **期待型への適合の混同**: `RangeElement` は `Range<T>` の T を返すだけである。これを広げると、`0..=3` が `Range<i32>` の引数に適合してしまう。演算子と型の対応は 1 か所で判定する。
2. **合成呼び出しの再利用**: `rangeCalls` はノードごとに再利用される。編集で `..` と `..=` が入れ替わったとき、再束縛で宣言が切り替わることをテストで確かめる。
3. **開始を省略した `..=`**: 構文エラーに移すと、パーサーの回復と `ExpressionPrecedenceTest` の `..=end + 1` が変わる。`Fix` の文を出すには、回復後も範囲の構造を保つ必要がある。
4. **`^x` の呼び出し化**: `FromEnd` の値の計画と支配関係の検査が、通常の呼び出しの扱いに変わる。raw pointer の添字で `^` を拒否する構文上の検査は残す。
5. **レイアウトの変更**: 1 系統だけの実行では古い期待値が隠れるので、全 fixture を走査する。
6. **作業順序**: 進行中の整数範囲の実装と同じファイルを変更するので、その実装単位をコミットしてから着手する。

## 4. Rationale — 変更する理由

### 4.1. 目的

- 範囲値と `Index` の格納サイズを減らす。
- 区間の形を型で表し、局所的に読めるようにする（原則 2・3）。
- 位置の範囲を半開に統一し、`^0` を終端の境界とする Index の考え方と `ResolvedRange` にそろえる。
- Index の値を作る処理を一つの Kimi 実装にまとめ、コンパイラーが Index の格納に依存しないようにする。

### 4.2. 理由

1. **格納サイズ**: windows-x64-v1 の配置規則（実装仕様 §21.1.3・§21.1.5）で計算すると、次のとおりである。配列では stride がそのまま減る。`Option` や外側の構造体では、タグと切り上げのために、削減の一部または全部が消えることがある。

   | 型 | 単体 | `Option<…>` |
   | --- | --- | --- |
   | `Range<u8>` | 3 → 2 B | 8 → 8 B |
   | `Range<i32>` | 12 → 8 B | 16 → 12 B |
   | `Range<i64>` | 24 → 16 B | 32 → 24 B |
   | `Index` | 16 → 8 B | 24 → 16 B |
   | `IndexRange` | 40 → 16 B | 48 → 24 B |

2. **解決の分岐の除去**: `resolve`・`tryResolve` は型ごとの処理になり、包含の判定が消える。Index の解決でも、方向による分岐が加算の選択に変わる。
3. **反復**: 入口が区間の形ごとに分かれ、閉区間も、終端が T の最大値でなければ半開と同じ状態で始まる。保存・受け渡しした範囲でも同じである。効果は §6 で確かめる。
4. **閉区間は型として残す必要がある**: `0..=255@u8` や `T.min..=T.max` は、終端 + 1 が溢れるので半開では書けない。
5. **位置の閉区間は、要素集合としては半開で表せる**: 違いは閉区間に固有の失敗条件（1 だけの逆転、終端が要素でないこと）だけである。そのために型を増やすほどの用途はない。
6. **等価性の落とし穴の除去**: `(0..3) == (0..=2)` は黙って false になっていたが、型エラーになる。
7. **添字の経路の統一**: 整数境界の範囲構文では、`..=` も直接選択になる。範囲値の生成と解決の呼び出しを省け、受け手の制約も `..` と同じになる。閉区間には終端の変換が加わるので、コストが同じになるかは §6 で確かめる。

### 4.3. 検討した代替案

| 案 | 内容 | 不採用の理由 |
| --- | --- | --- |
| A. `IndexRange` の `..=` を構築時に正規化する | `a..=k` を `a..(k + 1)` に、`a..=^n` を `a..^(n - 1)` にする | 言語の意味として、失敗を成功に変えてしまう（§3.2 の「保証しないもの」）。「逆転を空にしない」規則と `ClosedRange<T>` の挙動に反する。`..=^0` の失敗が構築時に移るので、`trySlice` が None を返せなくなる |
| B. `ClosedIndexRange` を新設する | 位置の閉区間型を設ける | 失敗条件は保てるが、型とスライス API が増える。§4.2 項5 のとおり用途が乏しい |
| C. 閉区間専用の反復器を設ける | `ClosedRangeIterator<T>` | 入口を区間の形ごとに分ければ、閉区間もほとんどの場合、半開と同じ状態で始まる（§3.3 項4）。型を増やすのに見合う効果がない |
| D. フラグを残してビットを詰める | 境界の余りビットを使う | T は全値域を使うので、余りビットがない |

### 4.4. 副作用

- **オーバーロードが増える**: 両方の区間の形を受け取る API には、オーバーロードが 2 つ要る（§3.3 項5）。範囲型を束ねる Contract は対象外とする。
- **混在させると共通の型がない**: 区間の形は型の一部なので、`..` と `..=` を混ぜた分岐の結果や配列の要素は、共通の型を持たない。要素列を保ったまま片方の形にそろえられるのは、正常な範囲だけである。
  - **閉にそろえる**: どの半開範囲も `start < end` なら、`start..=(end - 1)` にする。`start < end` なら終端は T の最小値ではないので、減算は必ず表現できる。
  - **半開にそろえる**: どの閉区間も `start <= end` で、かつ終端が T の最大値でなければ、`start..(end + 1)` にする。
  - **そろえられない場合**: 空の範囲・逆転した範囲・最大値を含む範囲が混ざる場合である（`0@u8..0` と `0@u8..=255` など）。
    - 反復するだけなら、`intoIterator()` で共通の `RangeIterator<T>` を得る。ただし Iterator は消費されるので、範囲値を保存して再利用する代わりにはならない。
    - 範囲値として保存するなら、利用側の enum などで区別する。
  - **変換 API は設けない**: `ClosedRange` から `Range` への変換は、T の最大値を含む区間を表せないためである。

  ```kimi
  let r = if c => 0..n else => 0..=m        // エラー: 共通の型がない。
  let h = if c => 0..n else => 0..(m + 1)   // 0 <= m で、m が T の最大値でなければ、半開にそろえる。

  let empty = true
  let numbers = if empty => (0@u8..0).intoIterator() else => (0@u8..=255).intoIterator()
  for x in Kimi.Iteration.owning(numbers@move) // 反復するだけなら RangeIterator<u8> で共通にする。
      ()

  enum ByteSpan                             // 範囲値として保存するなら、利用側で区別する。
      HalfOpen(Range<u8>)
      Closed(ClosedRange<u8>)
  ```

- **空の閉区間はない**: `0..=n - 1` は、n = 0 のとき次のようになる（現行と同じ）。空になりうる場合は `0..n` を使う。
  - 符号付きの n: 逆転し、反復の入口で Abort する。
  - 符号なしの n: 減算で Abort する。
- **新たなエラー**: 範囲どうしの等価比較と引数の型不一致がエラーになる。`..=b` と、Index の境界を含む閉区間は書けなくなる。§3.2 の書き換えは、境界の観測値と失敗条件までは保たない。
- **借用の書き方**: `index.offset@ref` を束縛に保存するコードは、値を先にローカルへ保存する必要がある。
- **`^x` のコスト**:
  - O0 では、`^x` ごとに呼び出しが 1 回増える。
  - O2 ではインライン化で同等になる見込みである。インライン化されるか、変換と検査が従来と同じ形まで簡約されるかは §6 で確かめる。

## 6. Decision — 最終決定

### 6.1. 決定

- **採用する**: §2 の仕様と §3 の実装方針。要点は次の 6 つである。
  1. `isInclusive` を削除し、`Range<T>`・`IndexRange` を半開区間専用にする。
  2. `ClosedRange<T>` を新設する。
  3. `..=` は、両端とも整数の場合に限る。
  4. `RangeIterator<T>` を共用し、入口を区間の形ごとに分ける。
  5. Index を `isize` 1 個で表し、Index の値を作る処理を Kimi の関数 1 組にまとめる。
  6. 整数境界の `..=` の添字も直接選択する。
- **採用しない**: §4.3 の案 A–D。
- **対象外**:
  - 範囲型を束ねる Contract
  - 降順・刻みの範囲
  - §3.3 項3 の受け手の制約の解消（別の単位で行う）

### 6.2. 実装順序

1. `ClosedRange<T>` の新設、`..=` の切り替えと直接選択、反復の入口の分離、`Range<T>.isInclusive` の削除
2. `IndexRange.isInclusive` の削除と `..=` の制限
3. Index の単一表現、Index 生成の関数の統一（`^x` を含む）、境界のIndex化の順序の変更

各単位は、`./scripts/verify.ps1 -Class ...` と関連する O0・O2 の fixture で検証してからコミットする。

正式仕様と公開索引は、対応する実装単位で更新する。`docs/dev/PLAN.md`・`docs/dev/PLAN_HISTORY.md` には進捗を記録する。`docs/STATUS.md` は、検証済みの対応範囲が変わったときだけ更新する。正式仕様は本書を参照せず自己完結させ、取り込み後は `draft/INTEGRATED.md` に対象節またはコミットを記録して、本書を凍結する。本書を更新しただけでは、正式仕様・実装・STATUS は変えない。

### 6.3. 正しさの検証

- **Index の表現**:
  - サイズと符号化をライブラリのテストで確かめる。
  - 表現の境界である `0`・`^0`・`Index.init(isize.max)`・`^isize.max` について、生成・取得・等価・解決を確かめる。
  - 解決は、`(^1).tryResolve(0)` が None、`(^0).tryResolve(0)` が Some(0)、負の長さでは None になること。最大 offset と、長さ 0・最大長を組み合わせても、余分な Abort がないこと。
- **Index の値の生成**: 負の値と isize に収まらない値で、`^x`・範囲の境界・直接選択の失敗条件が一致すること。例えば、`values[n..]` と `values[(n)..^0]` が同じ条件で Abort すること。
- **順序**: 範囲式の評価順とIndex化の順序を確かめる。整数の範囲（`-3..3`）はIndex化しないこと。
- **`ClosedRange<T>`**:
  - `T.min..=T.max`（`i8`・`u8` の全域）と `T.max..=T.max` を反復し、加算しないことと、終了後も None のままであること。
  - 解決は、e = L - 1 で成功し、e = L で失敗し、空の対象では常に失敗すること。
  - `0..=255@u8` を長さ 300 の対象に適用できること。
- **型**:
  - リテラル式の範囲が、演算子に対応する型にだけ適合すること。
  - `trySlice` の 4 つのオーバーロードから、正しく 1 つが選ばれること。
  - `(0..3) == (0..=2)` と、`..` と `..=` を混ぜた分岐・配列が型エラーになること。
- **失敗の分類**:
  - 境界式の失敗（符号なしの `n - 1`）
  - 逆転した範囲
  - 正常な空（半開の `0..0`）と 1 要素（`0..=0`）
- **添字と診断**:
  - `..=` の直接選択が、受け手を `..` と同じに扱うこと。
  - §3.2 の書き換えが `Fix` の文に出ること。`a..=^one()` は `a..^(one() - 1)` になり、`one()` の評価を消さないこと。

### 6.4. 性能の検証

| 区分 | 対象 | 判定 |
| --- | --- | --- |
| 既存の経路 | `for i in 0..n`・`0..=n`<br>パス形の受け手の `values[a..=b]`・`values[1..^1]`・`s.trySlice(1..^1)`・`values[^1]`<br>範囲の配列の走査とコピー、保存した範囲からの反復、関数から返した Iterator の反復<br>実行時に方向が決まる Index の解決と `offset` の取得 | 同じプログラムを変更前後で比べる |
| 新しく対応する経路 | パス形でない受け手の `values[a..=b]` | 正しさを検証し、時間と生成コードを記録する |

- **長さ**: 空（半開のみ）・1 要素・8 要素・10^6 要素。
- **合格条件**:
  - **既存の経路の時間**: 各単位の直前のコミットを基準として、最小値の悪化が 3% 以内であること。最後に、変更着手前と完成版を同じ条件で比べ、全体でも 3% 以内であること。
  - **格納サイズ**: §4.2 の表の値と一致すること。
- **記録するもの**: 差の分析に使い、単独の合格条件にはしない。
  - O2 の生成コード。`for i in 0..=n` が `for i in 0..n + 1` と同じループになるかを含む。
  - O0 の時間（`^x` の呼び出しを含む）。
- **測定条件**:
  - 入力は実行時に与える。結果は計測の外で検証し、測定対象が生成コードに残ることを確かめる。
  - 短い処理は、多数回をまとめて 1 回の計測とする。
  - ビルド条件をそろえ、ウォームアップ 3 回の後、比較する 2 版をコアを固定して交互に各 21 回測る。
