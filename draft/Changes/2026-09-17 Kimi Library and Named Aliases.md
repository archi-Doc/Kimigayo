# Kimi ライブラリと名前付き alias — 仕様変更案

日付: 2026-09-17

本書で変更する事項は、[SPEC.md](../../SPEC.md) およびその参照先より優先する。変更しない事項には既存仕様を適用する。変更範囲と他案との関係は本書 §6 に示す。本書の確定は実装完了を意味しない。例示コードは、特記しない限り独立した例である。

## 1. 目的と用語

型構成要素の `Core` と基盤ライブラリの名称を分離する。型の定義は変更しない。

```text
Type = Semantics/Core from Origin
```

基盤 Kotonoha の名称と予約参照名を `Core` から `Kimi` へ変更する。言語仕様で `Core` を用いるのは型構成要素とその派生用語に限る。`Core Identity`、`Core-Type`、`sealed Core` などは、その意味で維持する。

| 対象 | 変更後 |
| --- | --- |
| 基盤 Kotonoha／ライブラリ | Kimi Kotonoha／Kimi library |
| 基本型・Contract・Requirement | `Kimi.Option`、`Kimi.Result`、`Kimi.Array`、`Kimi.Copy`、`Kimi.Owned`、`Kimi.Callable` など |
| 標準出力 | `Kimi.Console.writeLine` |
| その他の既定の公開操作 | `Kimi.makeObj`、`Kimi.clone` など |

`writeLine` を除き、旧ライブラリ直下の宣言は Kimi 直下へ移す。各宣言の形・意味・提供範囲は変更しない。他案による追加宣言の読み替えは本書 §6.1 に定める。

## 2. Kimi と標準出力

### 2.1. 予約参照名

各 Compilation は、互換性のある Kimi Kotonoha をちょうど一つ選択し、Compilation root の予約参照名 `Kimi` で公開する。生成定義・読み込み定義の同一性、互換性検査、欠落・重複・不適合の拒否は従来どおりとする。

ユーザー依存関係による参照名 `Kimi` の登録、およびプロジェクトルート宣言による同名の使用を禁止する。`Kimi` を字句上のキーワードにはしない。通常の内側スコープにおけるシャドーイングは既存規則に従う。`::Kimi` はローカル宣言と alias を経由せず、予約された Kimi Kotonoha を指す。

### 2.2. デフォルト alias

有効なデフォルト alias は、次の共通規則で構築する。

```text
有効なデフォルト alias = 言語版が定める必須分 + 定義元の設定による追加分
```

本変更を採用する言語版の必須分には、予約された Kimi Kotonoha を開く alias を含める。設定による除去・別対象への置換は認めない。すべての SourceDocument に、生成ソース・依存モジュールを含め、その定義元の環境で適用する。

必須分と追加分は同じデフォルト検索段階に参加し、同一の解決済み参照は重複排除する。必須分を優先する別段階は設けない。設定とパッケージ manifest の `aliases` には利用者指定の追加分だけを保存し、必須分を自動追記しない。読み込み時は言語版と選択されたライブラリ契約から同じ有効環境を再構築する。追加分が空でも Kimi は有効になる。

ソースに明示した `alias Kimi` は明示 alias の検索段階に参加するため、デフォルトだけの場合と衝突時の優先順位が異なり得る。異なる検索段階をまたいで重複排除し、順位を変えてはならない。

### 2.3. Console

Kimi 直下に通常の公開 `group Console` を置き、その直接メンバーとして次の標準出力関数を置く。

```kimi
public func writeLine(text: string) -> ()
```

これは従来の標準出力関数の公開位置の変更である。文字列の取得・破棄、UTF-8 出力、LF の付加、失敗時の Abort、引数ラベル、関数値としての扱いなどは変更しない。Console は値や専用構文ではなく、新しい出力 API も追加しない。

```kimi
Console.writeLine("Hello")        // デフォルト alias 経由
::Kimi.Console.writeLine("Hello") // ルートから明示
```

alias は再帰的にメンバーを開かない。言語必須の Kimi alias だけでは標準の裸の `writeLine` を導入せず、`Kimi.writeLine` も提供しない。裸の名前は、明示 alias または追加デフォルト alias が `Kimi.Console` を開くと導入される。検索順位とシャドーイングは通常の規則に従う。

```kimi
alias Kimi.Console
writeLine("Hello")
```

設定の追加デフォルト alias に `Kimi.Console` がある場合は、上のソース内の alias 宣言を省略できる。

### 2.4. Intrinsic と旧名

`Intrinsic` は、コンパイラが固有の意味・導出規則を認識するという性質を表す。公開の `Intrinsic` 名前空間や `Kimi.Intrinsic` group は導入せず、公開位置は用途に基づく。特別な意味は元の宣言 Identity に属し、alias 経由でも維持する。同じ綴り・形のユーザー宣言には付与しない。

`$abort`、`$expect`、`$require` と Composition Root の役割は維持し、Kimi の通常メンバーや別名にはしない。標準出力を通常の公開関数として扱い、その実装をコンパイラ／runtime が提供する規則も維持する。

旧ライブラリ名 `Core` と旧 `Core.writeLine` に互換名・自動転送を設けない。`Core` の特別な予約は解除し、ユーザーの宣言や依存参照名は通常の規則で扱う。

## 3. alias の共通規則

### 3.1. 形式と対象

alias は、解決済み Container 参照を名前検索へ導入する。既存の開く形式を維持し、名前付き形式を追加する。

| 構文 | 意味 |
| --- | --- |
| `alias Path` | 対象 Container の直接メンバーを、それぞれの名前空間へ導入する |
| `alias Name => Path` | 対象自体を Type 名前空間の `Name` として導入する |

```kimi
alias A => ::Kimi.Console
A.writeLine("Hello")
```

`Name` は通常の識別子一つとし、修飾名・引数リスト・パターンを認めない。`=>` の右辺は Container 参照であり、式や実行可能な Body ではない。

**名前付き形式の対象は、Kotonoha と `group` に限定する。** struct、enum、Contract、完全な Type、関数、変数、Origin、Semantics への別名は導入しない。`alias Number => i32`、`alias O => ::Kimi.Option<i32>`、`alias f => ::Kimi.Console.writeLine`、`alias Name = Type` はエラーとする。

この制限は名前付き形式の最終対象に適用し、既存の開く形式の対象範囲は狭めない。本書は新しい Container 配置や具体化方法を導入しない。適用される Container 規則で有効な参照について、最終対象が group なら具体化された親を経由する名前付き形式も許可する。必要な型引数・Origin は対象の規則に従って束縛し、未束縛のパラメーターを alias 自身のパラメーターにしない。

名前付き alias は対象のメンバーを裸の名前で開かず、新しい型・値・保存領域・宣言 Identity を生成しない。`A` 単独を値や Core として使うことはできない。名前付き alias 自体にアクセス修飾子を付けることもできない。

### 3.2. 対象の解決

両形式とも SourceDocument のトップレベルで、通常の宣言・実行項目より前に置く。ネストした alias は禁止する。指令による選択・生成との関係は既存規則に従う。

両形式の対象参照全体を、Compilation root を起点とする alias を含まない環境で解決する。先頭の `::` は省略可能で、意味を変えない。途中の修飾子だけでなく、型引数・Origin 指定の内部でもソース alias とデフォルト alias を使わない。`i32`、`from static` などの組み込み構文は維持する。

```kimi
alias A => Kimi.Console       // ::Kimi.Console と同じ対象
```

```kimi
alias K => ::Kimi
alias A => K.Console          // K が alias にしか存在しなければエラー
```

具体化された `Outer<T>.Helpers` が適用される Container 規則で有効な場合も、型引数へ同じ規則を適用する。

```kimi
alias H => Outer<Kimi.Option<i32>>.Helpers // 有効な型引数の指定
// Outer<Option<i32>>.Helpers は、Option がデフォルト alias からしか見えなければエラー。
```

この規則は alias 宣言中の参照に適用する。参照先宣言の本文・制約などを検査する際は、その宣言の定義元環境を維持する。alias の解決を理由に参照先の環境を置換しない。

alias の連鎖・循環・記述順による解決は導入しない。別名と同じ綴りの実在するルート宣言や直接依存参照名がある場合は、その実在する対象として解決する。推移的依存への名前到達性は追加しない。

### 3.3. 参照の保持と適用範囲

alias は元の宣言 Identity と正規化済み引数束縛からなる宣言参照を保持する。対象パスの文字列置換や、使用箇所での引数の再推論は行わない。参照の同一性と検証の完了は別に管理する。

alias 宣言には、途中の修飾子も含むアクセス・型形成・入力条件・Origin の検査義務を登録する。確定した不正はエラーとし、生成待ちなどの未解決事項は既存の期限まで保留できる。最終 Binding では必要な義務をすべて完了させる。

宣言 Identity と引数束縛が確定した同一参照は、未解決の検査義務があっても構造を共有できる。ただし各経路の義務・状態・依存先を保持し、共有や重複排除によって検証済みとみなしてはならない。メンバーのアクセスと使用条件は各使用箇所で検査する。alias はアクセス権や適合の証拠を追加しない。

適用範囲はその SourceDocument だけとする。マージされた Container の別断片、他ファイル、生成ソース、呼び出し元へ伝播させない。alias は再公開されず、`Project.A` や `::A` で参照できるルートメンバーにもならない。公開 Signature に別名経由の型を記述する場合も、元の型へのアクセス・依存関係・名前到達性を検査する。

## 4. 名前検索と診断

### 4.1. 検索段階

通常の名前検索順序を維持する。

1. 現在のローカルスコープから外側の字句・パラメータースコープ。
2. 現在の Container。
3. 親 Container からプロジェクトルート。
4. Compilation root の直接依存参照名。既存どおり Type 修飾子の検索に限る。
5. 使用元 SourceDocument の明示 alias 全体。
6. 定義元のデフォルト alias 全体。

名前付き alias は第5段階の Type 名前空間へ参加し、対象の役割を維持する。Kotonoha／group の別名は Qualifier であり、Core ではない。Type と Value の両経路が成立し得る場合は既存の両経路検索・曖昧性規則を適用し、別名を優先する例外を設けない。

内側の適格な同名宣言によるシャドーイングを認める。一度選んだ修飾子に目的のメンバーがなくても、外側の同名宣言や別の alias へ戻らない。引数・期待型・実行可能性による検索のやり直しも認めない。

### 4.2. 重複と衝突

**明示した名前の対応付けは宣言時に、開いたメンバーの競合は使用時に検査する。**

同じ SourceDocument の選択された名前付き alias では、参照同一性が確定した段階で同じ別名・同じ宣言参照を重複排除する。同じ別名・異なる宣言参照は、使用の有無によらず衝突エラーとし、後の宣言で上書きしない。異なる正規化済み引数束縛は異なる参照である。同一性が未確定なら比較を保留し、検査義務は本書 §3.3 に従って保持する。

開く形式との競合は、同じ検索段階で既存の名前空間・役割・アクセス規則に従って扱う。同一参照への複数経路は重複排除し、異なる適格候補には既存の選択・曖昧性規則を適用する。開く形式の全メンバーを宣言時に展開して衝突検査する必要はない。

### 4.3. ルートの同名修飾子による隠蔽警告

指令選択・生成後の最終環境で、正常に解決・検証された名前付き alias に対し、次の検査を行う。

1. 同名のプロジェクトルート宣言から、その文書全域でアクセス可能な Type 名前空間の Qualifier 候補を集める。
2. 候補がなければ、同名の予約参照名・直接依存参照名を候補とする。
3. 候補があり、alias の対象と同一の宣言参照を含まない場合、alias 宣言箇所に警告する。

これは明示 alias より先に検索を確定させるルート候補の検査であり、潜在的な使用箇所は列挙しない。名前空間・役割・アクセスで判定し、型引数の適用可否、後続メンバー、呼び出し引数は調べない。内側のスコープだけで生じる隠蔽は対象外とし、検索順位・受理条件は変えない。

```kimi
// A が直接依存参照名である文書。
alias A => ::Kimi.Console // 警告: A は依存ライブラリを指す。別の名前を使用する。
A.writeLine("Hello")     // 依存ライブラリのメンバーを検索し、Console へは戻らない。
```

上記を必須の警告条件とし、同一参照への冗長な別名には警告しない。未解決・不正・衝突した alias への二次的な警告も出さない。

## 5. 保存・再利用・実装指針

### 5.1. 保存と無効化

ソースの名前付き alias はソース宣言として保存し、manifest のデフォルト alias 設定へ混ぜない。配布内容、コンパイル入力、意味解析結果の同一性を次のように区別し、既存の ID 規則を維持する。

| 区分 | 識別する内容 |
| --- | --- |
| `SourceId` | 実際の manifest バイト列と、それが内容ハッシュで参照する収録ファイル |
| `ProjectSnapshotId` | ソース内容・所属・順序と、正規化した有効な意味設定。プロジェクトファイルの表記差そのものは含めない |
| 処理段階の入力記録 | 言語版、コンパイラ・検証規則、Kimi の契約など、その段階で必要な入力を既存の区分に従って保持する |
| 意味解析の再利用 | 解決済み宣言参照・検索段階・定義環境と、検査の前提・依存先 |

必須 Kimi alias に対する設定上の重複指定など、名前解決なしで確定する有効設定の同値性は正規化できる。追加設定が空の場合と `Kimi` だけを追加した場合は、他の入力が同じなら同じ有効設定になる。ただし保存された manifest やソースの実バイト列が異なれば、各内容 ID はその違いを既存規則に従って反映する。

入力 ID の構築には alias の完全な意味解析を要求しない。一般の異なるパスが同じ宣言を指すかの判定は解析後に行い、意味解析の再利用へ用いる。別名・経由パスは元の宣言・型の Identity に加えず、名前検索を変える環境、候補の追加・削除・アクセス変更・不在は依存として再検査する。旧入力を名前の読み替えだけで互換とみなさない。

### 5.2. 共通処理と性能

両形式は、対象参照、導入方法、必要なら別名、および定義環境を持つ共通の記録として扱える。参照構造の共有と検証結果の再利用は本書 §3.3 に従って分離する。以下は実装指針であり、特定のデータ構造を言語要件にはしない。

- 名前付き形式は SourceDocument ごとの名前索引、開く形式は対象 Container の既存メンバー索引を利用し、全ファイルの alias 走査や全メンバーの展開コピーを避ける。
- 同一性が確定した対象参照・引数束縛を共有し、Binding の同じ有効世代内でパスを繰り返し解決しない。デフォルト環境は同じ定義元の文書間で共有できる。
- 使用箇所ごとのアクセス・条件検査は維持する。候補の索引と、文脈に依存する検査結果を区別する。
- 完了した検証結果は、その前提・依存先が有効な範囲で再利用する。未解決の義務は完了した証拠として再利用しない。生成・入力変更で解決や検査の依存先が変われば、影響する結果を無効化する。

ライブラリを指す内部名 `CoreIntrinsics`、`CoreDeclaration` 等も改名対象とする。管理オブジェクトの名称例は `KimiLibrary` とし、性質の識別子 `IntrinsicKind` は維持できる。処理本体を表す内部名 `BuildCore` 等は対象外とする。
