Independent alternatives
1. Group current Virtual objects and retain all producers: rejected by design review 1; same-key geometry improves but stored n producer/full-beta/continuation snapshots violate the intended request-storage bound.
2. Program-level producer groups with request-level common bindings: viable performance alternative; source membership and variable maps live in reusable input indexes. It adds a static grouping representation and update paths.
3. SELECTED for simplicity: retain no producer snapshots. One canonical indexed source-query operation enumerates the applicable identity sides when discovering or expanding a virtual node. A stored node/forward requirement says what node is needed and in what class; all producer rows and mappings are reconstructed from the existing side index at the round's snapshot. This trades repeated counted index work for fewer concepts and less retained state. It is the canonical path for every direct candidate/expansion, never a fallback scan.
4. Put unfinished candidates in EGraph: rejected. EGraph currently publishes proven complete Types; holes require new validity/congruence/publication semantics. No speculative candidate becomes equality evidence.

Canonical node and query
A node record is (canonical class, Other residual pattern, used bindings by canonical class). Its key includes explicit heads; bound variables contribute canonical classes; free variables are renamed in first-occurrence order, preserving repeated occurrences. Variables absent from Other do not enter the key or retained binding vector. The source template, row id, base path, VarCount and unused premise variables are absent. The record retains one representative pattern and only its used bindings; its original-variable correspondence is derived from pattern traversal, not one map per producer.
The source query receives that class and residual node requirement. It uses the existing identity-side index (the other head, side heads admissible at the class, conservative kid filters), groups side matches as today, and e-matches each side against the real class with MatchMode.None. A direct match supplies a temporary full producer beta. Its projected Other key must equal the requested record key. Agreement's canonical slot assignments are mapped back into that beta by corresponding free-variable occurrence order; unused producer variables keep exactly the values found by the side match or remain free. That producer then enters the existing Request operation with its original template/view/conditions/supports. Each temporary producer beta is released before retaining a result: no array/list of producer instances survives in a node or forwarding record. Every index entry, side match, projected-key comparison and producer replay is counted in J; allocations are measured.
Discovery and expansion share this source-query owner so the selection rule is not implemented twice. Discovery groups the projected Other keys; expansion enumerates the members of exactly that key. The current per-round memo stores distinct candidate node/query results and visit/resource effects, never producer membership. Repeated shared declarations add reusable index entries and linear scan work, not retained producer instances. Any additional cache is outside this design and needs a new review.

Forwarding without producer paths
A chain record is a node requirement plus a set of forward requirements. A forward requirement is (base canonical class, base residual node key/bindings, needed pattern/bindings). Including base class is mandatory; equal node shapes in different classes do not share an obligation. It contains no template and no captured producer list. The needed pattern is canonically renamed independently, retains repeated-slot correlation and only its used bindings.
A chain through a direct candidate records that direct-base query. A chain through an existing chain carries its first direct-base queries unchanged, as prerequisites: once a base row fires, the next ordinary round's direct match discovers the following step. Multiple paths giving one forward query are a set. A mixed node uses both its direct source query and its forward queries; no direct alternative is overwritten by a forward one. A new direct producer is found by re-enumeration in the later snapshot, so no copied-base update/union protocol exists. Forwarding requests prerequisites only; it cannot establish equality or its own premise.
Canonical chain records and their distinct retained forward obligations count as rows/items. Thus physical persistent query state is O(V+E), plus reusable input indexes and the existing bounded lookup workspace; no n-member snapshot is hidden outside V. Forward/class/node binding keys normalize after class merges. Source statuses and full binding correlations are always re-read from the input rows at expansion; row identity is still used for actual proof supports and subscription deduplication where it has semantic meaning.

Jacobi publication
Each round reads one EGraph/classes and chain-query snapshot. Lookup groups are immutable; newly discovered chain/forward requirements are staged in Effects, unioned in Apply, and exposed next round. A newly added forward wakes readers even when its node key already exists. AfterApply canonicalizes stored query classes/bindings and coalesces equivalent requirements, preserving every distinct base class and pattern. Source re-enumeration uses that same current snapshot; it never invokes semantic mutation. This removes mutable producer membership, recursive provenance-key caches and storedKeys. Existing needs/meeting rows and subscriptions remain the one scheduler.

Child identity and filters
Only a top virtual-node head/arity selects its node family. A Type child compares by its known class; unequal known classes create the existing meeting, a free variable can take a known class, and an uninstantiated child is deferred until built. Delete SameShape and recursive child-shape agreement in Agree/MayUnify. Every Type-child filter (static side index, stored-chain lookup, dynamic KidHeads and chainability) returns Any when its bindings cannot yet define a complete Type; a conservative ground filter includes reachable identity heads.
Contract references already have a distinct semantic sort, SymKind.Ref in Model: SPEC8.6.1 fixes their declaration identity while Type arguments compare modulo identity classes. A reference's declaration head can therefore remain a rigid index key even with unresolved arguments; this is a sort rule, not a Ki/name/form exception, and does not identify references with Types. This distinction prevents an Any child filter from destroying the n-distinct-reference index in palias. No production TypeIdentity ownership changes. Add a focused case for same reference declaration with identity-equivalent arguments, different reference declarations and a Type-child with differing constructor heads that later joins.

Canonical row selection (root decision, supersedes subscription-only pruning)
Grouping geometry and pruning only at Request are insufficient: a dead row can already have created n retained candidates in roundMemo. The existing Usable operation owns ONE row-selection rule: preserve its source/view publication effects at the original boundary, then select a potentially executable row only if every positive prerequisite (Antecedent and all Conditions) has at least one possible positive supplier in the complete existing concludesPositive index. All candidate AND obligation creation follows that one decision. There is no candidate-specific Supports gate, no extra Request/Scan guard and no new table. The immutable input means prerequisite emptiness has the same meaning at every call; repeated checks merely re-evaluate the same static predicate.
Usable processes inadmissibility/under-check exclusions and published Pending/Resource semantics in the existing order. Ordinary Pending and Resource still publish their effects before returning; a Valid or discoverable-Pending row with an empty prerequisite relation creates nothing. The complete supplier index includes supplied conjunction atoms, inputs, refinements, clauses and conformances from ProgramModel.Prepare, conservatively including invalid/pending/frozen/excluded suppliers. A source absent from the index cannot be invented by class identity, which changes Types/arguments but never the concluded Contract declaration.
Request call-site audit: bound expansion BindShape at1459 is guarded by Usable at1451; SelectDemand1525 by1487; SelectIdent1873 by1862; SelectCompound1907 by1897; Settle2316 receives only candidates selected at1256, and the new canonical direct-source query observes Usable again at selection. Scan only advances an already selected row, whose prerequisite relation is immutable, so it does not need another rule. Inputs seeded by Fire have no prerequisites.
For shared-n with only V is Copy, all Ki supplier sets are empty: zero virtual candidates, forward queries, Ki demands or subscriptions are retained. For shared-pos only K1/K2 have supplied inputs: their candidate/obligation set is constant in n. For palias/selfid/deep2/mix the n unrelated row families likewise have no supplier; only the fixed supplied W3/Holder/K3 rows can create candidate records. Thus roundMemo as well as chains/demands/subscriptions is independent of unrelated n. Inspecting n immutable input entries costs linear J; no copied producer/beta/list is retained. Rows that can actually fire may add distinct nodes/requirements, and those counts/bytes are measured, never hidden as constant. Record/forward/member counts and retained allocation accompany V/E/J.
Completeness argument
Induct over finite permitted derivations. The established need/meeting/existing-node selection reaches each positive identity side by an admissible top head. Canonical grouping preserves its residual node; the source query re-enumerates EVERY direct side match at that class, restores its complete beta and row-specific support, and cannot lose an alternative through snapshot deduplication. Slot renaming is bijective on variables used in Other and preserves their repeated occurrence; unused variables remain in the reconstructed producer beta. Every chain path retains its first direct-base query, and its firing enables the next direct side match in the next round; forwarded requirements are not proofs. Class-merge normalization unions, never selects among, query alternatives. Unresolved-child deferral only broadens selection, while known children request the same meetings. A discarded row has a positive prerequisite with no row capable of concluding its required fact, so induction proves that row cannot occur in a derivation. Round-end publication preserves order independence; finite limits return Resource.
