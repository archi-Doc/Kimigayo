This plan resolves the requirements recorded as G34, G73 and G80 in [PLAN §7](../../docs/dev/PLAN.md) at their root causes. It splits the work into small, independently verifiable units in an order that needs no rework, so that no committed state accepts a program a later stage refuses or rejects a valid program with a Language code.

### 1.4 Principle alignment

- **One Concept, One Canonical Form.**
  - An implicit constructor is exactly `public init() => ()` with an omitted base clause, decided by one selection algorithm.
  - A standard Property operation is the same Place operation whether reached directly or through a Contract witness, and whether the Property is own or inherited.
  - A pair layer's outer-Origin slot follows one case-conditional rule shared by premises, obligations, fits and associated families.
  - A constructor of a compiler-managed Kimi Type runs ordinary Kimigayo code through one catalog link.
  - Input and result well-formedness are both premises at the definition and obligations at the use.
- **Local Reasoning.** Existence, premises and published summaries are decided from declarations and published contracts. Use sites, private bodies and favorable instantiations never decide them.
- **Explicit Semantics.** The specification states the case conditions of conditional slots, the receiver of an inherited standard witness, the composition that defines repeating construction, and which Kimi Types have constructors.
- **Compiler Server Protocol.**
  - A valid but unimplemented form fails with one located Unsupported record, and an invalid form gets its Language code.
  - `check` never accepts a program that generation refuses.
  - Each unit ties its tests, fixtures, snapshot and measurements to exact source and configuration.

## 3. G80 analysis

### 3.1 Implicit constructors today

1. **Parse.** Fragments merge into one `StructKoto`. Directive-excluded members are detached, so the member scan sees merged, selected members (`g80-ctor/p05-fragments`, `p06-fragments-ctor`).
2. **Index, every pass.** `Binding.IndexVisitor` (Binding.cs:1752) calls `StructKoto.PrepareImplicitConstructor` (StructKoto.cs:17-36).
   - The method returns at once when `Bases.Count != 0`.
   - Otherwise, when the struct has no constructor and every `let`/`var` has an initializer, it publishes one reused `FunctionKoto(StructKoto)`.
   - That node is indexed like any function: `init` is declared in the struct scope, and its scope, `self` and nodes are added.
   - Library structs are indexed too, unless their catalog intrinsic kind excludes them. So Dictionary, Slice, UniqSlice and Wrapping receive implicit constructors (F23).
3. **Declarations.** `BindDeclarations` (Binding.cs:458-498) binds schemas, constraints and headers. It then runs `ValidateBaseDeclarations` (without Type-constraint checks; those run again after bodies), prepares storage, validates signatures, and only then sets `capabilitiesReady` and validates conformances. Before `capabilitiesReady`, non-leaf capability proofs return a temporary Unknown.
4. **Bodies.** The container binds its Field initializers, then the implicit constructor. A use `S.init()` resolves through `ConstructorMember` (Binding.Structs.cs:145) to the scope's `init` group and then through ordinary `BindCallCore`.
5. **Later phases.** CFA (ControlFlowAnalysis.cs:1257), ownership (`OwnershipAnalysis.Structs.PrepareReceiverFields`, `CheckConstruction`), emission (`LlvmEmitter.CheckInputs` refuses unverified bodies) and Hover (a generated declaration) treat it as an ordinary constructor. `Binding.EffectBounds` queues the `BaseInitializer`. `ValidateBoundDeclarations` re-validates conformances and base clauses after bodies.
6. **Explicit derived constructors without a base clause** already work at O0 and O2:
   - `FunctionKoto.PrepareBaseInitializer` attaches a retained zero-argument invocation with span = `SignatureSpan`.
   - `BindBaseConstructor` resolves the base `init` group, and ordinary `BindCallCore` selects from it: protected allowed, private filtered, all-default candidates applicable, fewer defaults preferred (§10.4 step 4: `init()` beats `init(x: i32 = 0)`), premises judged under the derived Constraints.
   - Ownership runs the base first, then own initializers, then the body. Destruction is derived first.
   - `ImplicitBaseCallTest` pins this behavior.

How ordinary selection treats premises (A.13):
- A candidate with a **Refuted** premise drops out, and another candidate wins.
- A candidate with an **Unknown** premise blocks the whole selection, because `BindCallCore` fails the call before it counts applicable candidates. The block also happens when the Unknown cannot change the winner (F26).

### 3.2 Root causes: constructors

- **K-RC1, phase placement.** Synthesis is decided from syntax alone at index time. There the base-invocation condition of §6.2.3.6 cannot be judged: base Types are unbound, headers and access are not ready, capabilities are not ready, and the base's own implicit constructor may be undecided.
- **K-RC2, selection cannot run silently.**
  - `BindCallCore` interleaves per-candidate evaluation with publication (`CompleteDependent`, `FailWaitingSelection`, `rejectedCandidates`, `FailUnboundSlots`).
  - `TryCandidate` and `SelectBest` do not publish, but no entry point returns an outcome without failing nodes.
  - `TryCandidateCore` also leaves obligations and inference counters behind, and `EndCandidateBounds` rolls back only Origin initializer bounds.
- **K-RC3, one undifferentiated fallback.**
  - `ConstructorMember` (Binding.Structs.cs:160-166) maps both "the qualifier is not a StructKoto-backed Owner Type" and "no `init` symbol" to `Fail(member, Unsupported)`.
  - A qualifier that normalizes to a non-struct Type also lands there: the wrapping Scalar of `Wrapping<integer>` (Binding.Types.cs:854-859), or a primitive.
  - Generic `Wrapping<T>` keeps its struct and its synthesized constructor (F23).
- **K-RC4.** `BindBaseConstructor` reports a base without constructors as `InvalidTypeFormation_Kd`. That includes a derived base that would receive an implicit constructor (`review2/seq-k1`).
- **K-RC5, specification.** See F24 and §6.1.

### 3.3 Standard witness bridges today

- **Binding.** For an inherited `let` or `var`, `PropertyMatching.MatchPropertyOperation` classifies StorageCopy, StorageBorrow and StorageSet. It records three things and publishes the witness as Proven:
  - `ReceiverType`: the requirement receiver over the conforming Type `D`;
  - `ImplementationType`: `B<args>`;
  - `BasePath`.

  `InheritedConformances.VerifyInheritedConformance` re-verifies inherited conformances with the same data.
- **Generation.**
  - `InstantiatePropertyRequirementCall` and `Binding.Specializations.CollectWitnesses` (a second caller, for every verified path) ask `PropertyWitnessFunction` for the bridge.
  - The bridge would mix two contexts. Its receiver comes from the requirement over `D`, while its scope, `Parent` and instantiated declaring Type come from `B`, and `ProjectWitnessCall` (Ref only) is applied as for custom accessors.
  - Because the two contexts cannot agree, `PropertyWitnessFunction` returns null whenever `BasePath` is set (PropertyWitnesses.cs:19-22).
  - `GenericStoragePlan.PrepareEntryDependencies` then reports the string fallback as Internal `GenerationFailed_Kd`.
- **Direct inherited standard access is already correct.** `ElementAccess` and `StructStorage.FindField` resolve base-first Field identities without a whole-base borrow (§9.5.1). This holds for owned, ref, uniq and object receivers and for generic and multilevel bases (`g80b/a1-direct` to `a4-object-borrows`).

### 3.4 Root causes: Property paths

- **P-RC1.** A bridge for an inherited path has no coherent execution owner. The guard sits below Binding, so `check` and generation disagree.
- **P-RC2 (F6).** Ownership proves Copy through `ConstraintScope`, which walks the bridge's `Parent` (the struct). It never sees the conformance path's premise scope (`BoundConformancePath.Scope`, which carries `when` premises and the substituted inherited premises).
- **P-RC3 (F7).** `OwnershipAnalysis.Properties.UpdatePropertyPlace` and `ReborrowPropertyReceiver` borrow the located `D` receiver at the getter's parameter Type `ref/B`. They do not apply the getter's `BaseBorrow` operation (whole borrow, then `BorrowThrough` the base prefix), which `Reservations.PrepareCallArgument` already implements.
- **P-RC4 (F8).**
  - `ProjectedReceiverProof` returns Unknown for exclusive receivers.
  - Conformance validation publishes that Unknown through `RequireConstraint` as Proof-category `UnprovenConstraint_Kd`, while direct projected calls already map it to Unsupported (Binding.Calls.cs ~1048).
  - Inherited paths publish nothing at a declaration (Binding.Contracts.cs ~818 requires `InheritedFrom is null`), so the Proof error appears at the use.

### 3.6 Invariants and existing coverage

**Invariants.** The fix must keep these true:
- **Existence.** An implicit constructor exists exactly when all of these hold:
  - no explicit or generated constructor is selected;
  - every own `let`/`var` has an initializer;
  - the struct has no base, or the omitted-base selection selects a constructor;
  - the Type is not a compiler-managed Kimi Type (§6.1).
- **Agreement.** The synthesized base call selects exactly the query's winner. Any divergence fails closed (Unsupported, no IR).
- **Construction order.** Exactly one base call. The base runs first, then own initializers in logical order, then the empty body. Destruction is derived first.
- **No speculation.** The eligibility query leaves no issue, node state, `rejectedCandidates` entry, obligation or candidate bound behind.
- **Order independence.** The decision is independent of source, file and declaration order. Premises are judged only after `capabilitiesReady`, and the decision is re-judged after the post-body re-validation.
- **Visibility.** A rejected constructor is never selectable, never left in `binding.nodes` after completion, and never visible through `ImplicitConstructor`. Implicit syntax is never written back to source.
- **Bridge semantics.**
  - Standard `get`/`set` stay Place operations; bridges are never lookup candidates.
  - A witness's identity is (Requirement, Property, bridge kind) within one conformance path.
  - Copy is proven under the path's premises.
  - Contract calls keep their function boundaries.
- **Guards kept.** Exclusive custom paths keep their Unsupported/no-IR guards, and so do the G79 guards (Origin-bearing setter inputs; one Property per requirement group).
- **Warm zero allocation** for Bind, ownership and emission.

**Existing coverage and gaps:**
- `ImplicitBaseCallTest` covers explicit omitted-base constructors (defaults, selection failures, a single invocation, zero-allocation rebinding). It has no "base without constructor" row and no implicit-derived row.
- `BorrowStructEmissionTest` covers non-derived implicit constructors. Its invalid-construction rows pin no codes.
- `PropertyWitnessEmissionTest` covers non-inherited Copy, Borrow and Set bridges.
- `ConditionalConformanceBindingTest.AConditionalTypeIdentityCanJustifyTheStorageCopyBridge` checks only at Binding, so F6 is untested.
- `InheritedAccessorEmissionTest` and `InheritedPlanReuseTest` cover inherited shared custom getters and methods. They have no compound-update rows (F7 is untested) and no standard-Property rows.
- `InheritedReceiverBindingTest` checks inherited standard witnesses at Binding only, so F3 is never reached. It pins the exclusive Unsupported rows that must stay.
- `VerificationWorkloads.InheritedPlans` writes `public init() => ()` in every layer to work around F4.
- No test asserts any outcome for inherited standard bridges at generation.

### 4.2 The pair slot and its consumers

A pair layer's outer-Origin slot is either the implicit `o` of the original `s/T`, or the explicit slot of `s/X during a`.
- `o` is a binder atom: `PairCases.PairOuterOrigin`, with a negative slot `-1 - target.Slot`.
- The original `s/T` BoundType deliberately carries no Origin.
- An explicit slot's Origin `a` is an ordinary universal Origin; only its *position* in the pair layer is conditional.
- By §8.1.1, §8.1.2 and §8.10, the slot exists exactly in the admitted borrow cases of its binder.

Each consumer approximates that rule differently:

| Consumer | Current rule | Defect |
| --- | --- | --- |
| Premises: R2 inputs and R4 associated (`OriginPremises.AddTypePremises`); R3 result (`AddResultPremises`); R5 local Places (`AddStoredPremises` from `ExtractOriginPremises`) | Target→slot edges are added when any borrow is admitted, and explicit slots unconditionally. `o` is never added below a borrow layer, because the walkers enumerate only written Origins gated by `CarriesOrigin`. | F2: premise used where the slot is absent. F14: premise missing. |
| Obligations (`TypeOrigins.RetainInnerOutlives`, fits) | Checked whenever any borrow is admitted (`InactiveOuterOrigin`). | Conservative, which is the correct direction |
| Use-site obligations | Input well-formedness is never an obligation (F1). `ResultPremises.VisitResultPremises`/`VisitStoredPremises` is a parallel walk that stops at Kind mismatches. | No `o` mapping; F1 |
| Pair follow (`ArgumentOperations.PlaceOrigin` PairFollow branch, `PairLayers.PairOrigin`) | The slot alone for borrow-only sets. `PathReborrowOrigin` does not step through PairFollow. | F15 |
| Fits (`TypeRelations.FitsTypeCore`, `CheckTypeUse`, `CallRelations.JudgeCallFit`) | Raw `Origin` fields are compared, and a difference in presence fails structurally. | F16, F17 |
| Substitution (`Storage.SubstituteStoredOrigin`, `TypeRelations.SubstituteType`) | `o` is substituted only when it is a Type's whole Origin. A negative slot passes the `Slot < arguments.Length` guard and would be indexed. | Latent crash once `o` enters meets or result premises |
| Formation proof (`ConstraintValidation.ProveTypeRole`) | One boolean | F18 |
| Families (`AssociatedOrigins.HasSupportedAssociatedFormation`, `AssociatedFormation.CheckAssociatedFormation`, `ProvesBorrowedTypeLifetime`) | Only concrete borrow and Slice layers | F21 |
| Conformance completeness (`ContractMatching` ~211-229) | A failed specification is treated as missing | F20 |

Further encodings of "exists only in borrow cases" must be reconciled with the single slot helper:
- `BoundOrigin.BorrowCondition`, read by `ContractCalls` and the result default;
- `InactiveOuterOrigin`, which uses `TryAdaptationSelector` for SemanticsAdaptation layers;
- `AssociatedFormation.StoresTypeArgument`.

### 4.3 Root causes

- **G-RC1.** No canonical model exists for a stored Origin whose existence depends on the Semantics case:
  - premises are over-approximated, which is unsound (F2);
  - the stored-Origin walkers cannot see `o` (F14);
  - fits ignore `o` (F16);
  - follows use one Origin that is weaker than the uniq case's concrete rule (F15).
- **Binder sets.** Some obligations need two binders to be borrows at once. For example, `s/(t/U during b) during a` imposes `b outlives a` only when both `s` and `t` are borrows. A.14 is accepted today and must stay accepted, so the condition must be a set of binders. `CaseBound` (64) limits only the ownership case product, not the number of binders; Binding proves relations even when ownership later reports `OwnershipCaseLimit_Kd` (`review2/cc/sevenbinders`).
- **G-RC2 (F17).** `FitsTypeCore` and `CheckTypeUse` return false when exactly one side has an Origin. §15.6.1 makes the structural part Origin-blind and derives relations that follow a failed slot.

### 4.4 Prerequisite W: input well-formedness at the use (F1)

§15.3.7 makes intrinsic well-formedness a definition premise and a use-site obligation, but §15.6.4 step 3 names only the result Type at the use. Today three mechanisms combine:
- `TypeOrigins.CompleteOrigins` discharges a direct input's Origins as `CallBorrows`, on the claim that each call's borrow formation checks them. No borrow is formed when the argument is an existing reference.
- `RetainInnerOutlives` judges nested relations at the definition, where the same input premise proves them, so they prove themselves.
- `VisitResultPremise` skips the use-site obligation when the callee proves the relation from its other premises, including input premises.

As a result, a caller that instantiates a shared Origin with a shorter one is never checked. This happens through direct calls (A.1) and through Function Item value calls (A.1d). It is not specific to pairs, but G34-4 adds new input premises for `o` (A.1c), so W1 must land first. Because it is wrong code, it is scheduled first overall.

## 5. G73 analysis

### 5.1 Array construction today

- `Kimi.Array<T>` (Array.kimi) is compiler-managed and has no source Fields; `KimiLibraryValidation.ValidCollection` rejects Fields.
- Its only constructor is the bodiless `public init(! capacity: isize)` in ArrayOperations.kimi. It is recognized as the unique `init` (catalog `ArrayWithCapacity`, `Overload` -1) and lowered by `BodyLowering.Arrays.LowerArrayConstruction`, which emits `ArrayInit` and `ArrayReserve` with the caller location.
- The SPEC's `init(! repeating: T, count: isize)` with `T is Copy` (§4.7.2, LIBRARY.md:283) is absent, so every form reaches overload resolution with one inapplicable candidate.
- The Kimigayo fill pattern lives in `Array.appendCopies` (Array.kimi:160-173): reserve, then `Storage.borrowStorageUniq(...).storage`, then `Raw.initialize` per element, then `Storage.setArrayLength`.
- `Slice.toArray` composes `init(capacity:)` with `appendCopies`, which is exactly the shape §6.3 specifies for repeating construction.
- Conditional constructors with constructor Type inference, and Type functions of generic structs, already work for user structs (`g73/condctor`, `g73/typefunc2`).

### 5.2 Root causes

- **A-RC1.** The declaration is missing (F9).
- **A-RC2, the PLAN's "initialization bridge" (F10).** A constructor of a compiler-managed Type can be implemented only by hand-written lowering. An ordinary body cannot construct field-less storage (§6.2.3.4).
- **A-RC3, recognition traps.**
  - A second `init` makes `KimiLibrary.FindDeclaration` return null unless both entries carry overload indices, and that invalidates the whole library.
  - `Entry.IsFunction` is false for a bodiless entry without a compiler kind.
  - A new non-source ID without an explicit arm, such as the bodiless public constructor, falls into the `>= Utf8Format` `ValidFormatting` arm. A `SourceFunction` ID is validated by the existing source-function arm (KimiLibraryValidation.cs:75).
  - `ValidCollectionOperation` hard-codes the constructor ID and rejects Constraint clauses.
  - `ValidCollection` (KimiLibraryValidation.cs:533-538) rejects every bodiless Array member whose symbol has no registered `CompilerFunction`.
- **A-RC4 (F11).** `Allows` classifies by hand-written enum sub-ranges, so storage kinds appended later were never classified. The family predicates `KimiLibraryCatalog.IsStorageOperation` and `IsRawOperation` already exist (lines 227-229).
- **A-RC5 (F12).** `OwnershipAnalysis` records `RequirementEffects` for every source-function target. It has no notion of a published summary, so §4.7.5 operations are treated as unbounded generic calls.
- **A-RC6 (F24).** Unlike `init(capacity:)`, repeating construction has no composition in §4.7.4 and no row in §4.7.5.

The spike confirmed the design end to end at O0 and O2:
- explicit, inferred and expected-Type forms, count 0, Copy aggregates, zero-sized elements and generic defaults produce correct values;
- a negative count reports `KIMI_E_ARG_RANGE` at the user's construction;
- a Non-Copy `T` reports the refuted `T is Copy` premise;
- the caller-location ABI is propagated.

The spike also showed four costs:
- the `ValidCollection` admission had to be patched;
- an explicit `result@uniq` borrow is required, because without it the library body produced a Repair diagnostic and `check` faulted with `CheckFaulted_Kd`;
- F12 appears;
- the storage classification (F11) appears.

### 5.3 Invariants and existing coverage

**Invariants.**
- **Selection.** Selection works only on the public declaration.
- **Execution and presentation.** `BoundCall.Target` is the executed implementation, and every user-visible presentation uses the public declaration (lsp-hover.md: no internal names).
- **Catalog agreement.** Constructor and implementation agree through one signature row, and a disagreement makes the library invalid.
- **Scope.** Only catalog-designated constructors are bridged.
- **Evaluation.** `repeating` is acquired once, even for count 0.
- **Failures.** A negative count aborts with `KIMI_E_ARG_RANGE` at the user's construction before any element is placed.
- **Allocation.** Count 0 and zero-sized elements allocate nothing; otherwise construction allocates exactly once, with no growth.
- **Initialization.** Every element is initialized once before the length is published, and no user code runs during the fill.
- **Dependencies.** The result carries exactly `T`'s dependencies.
- **Warm paths** allocate nothing.
- **Catalog IDs** are append-only.

## 6. Specification position

Each revision below is deliberate. It makes the language more consistent or removes a contradictory reading, and it weakens no requirement. The texts are indicative. The documentation step finalizes the wording, follows STYLE [Kimi] rules for examples, and fixes cross-references.

### 6.1 G80 (G80-S)

1. **§6.2.3.6, replace the base condition and the last sentence.**
   - **Existence.** The implicit constructor exists if and only if all of these hold:
     - no explicit or generated constructor is selected;
     - every own Field has an initializer;
     - for a structure with a base, the omitted base clause of §6.2.3.3 selects a base constructor.
   - **Selection.** That selection is ordinary selection (§10) over the direct base's constructors with no arguments. It is made from the derived declaration, where protected base constructors are accessible, under the derived declaration's Constraints.
   - **Refuted premises.** A Refuted premise makes only its own candidate inapplicable.
   - **No candidate or ambiguity.** If no candidate applies, or the selection is ambiguous, no implicit constructor exists.
   - **Unknown premises.**
     - If ordinary selection cannot be decided because a candidate premise is Unknown there (§8.4.8.2), the selection is unproven and no implicit constructor exists.
     - A construction of the Type reports the unproven premise.
     - A derived synthesis or an explicit omitted-base call that depends on this absence is a derived problem with that premise as its prerequisite (§23.3.6.4).
   - **Invalid bases.** If the base declaration is invalid, or the structure's `: BaseType` clause has Constraints that are not Proven, the decision is dependent on that failure.
   - **Behavior.** The synthesized constructor has the Type's effective access and behaves as `init() => ()` with an omitted base clause. Errors of its base call are reported at the structure's `: BaseType` clause (§6.2.2).
   - **Generic structures.** Synthesis depends on declarations, not on the validity of initializers, defaults or the selected base call. The synthesized constructor of a generic structure is a generic definition (§8.10), and only its Deferred Obligations wait for instantiation.
   - **Example pair.** A derived struct over `protected init()` gets a synthesized constructor. A derived struct over two one-default constructors is a valid Type without a constructor, and its `.init()` is an error.
2. **§6.2.3.3.** "Omitting the base clause selects, by ordinary selection (§10) with no arguments, an accessible base constructor, including one whose parameters all have defaults."
3. **§6.2.3.2.** Add: a structure without a constructor, including one whose implicit constructor is not synthesized, cannot be constructed. `.init` on such a structure, on an enum (whose values the Cases form, §6.3), or on a Type parameter without an available identity premise (§8.3) is an error at the construction.
4. **§22.1.** A compiler-managed Kimi Type has exactly the constructors its §22.1 row and LIBRARY list, and §6.2.3.6 synthesizes none for it. This fixes F23.
   - It restates §22.1's own rows ("Wrapping has no public constructor").
   - It keeps empty-Dictionary construction in one canonical form, `[:]`.
   - The user may instead choose to list `Dictionary.init()` in LIBRARY (§14).
5. **§11.4.2, with §8.4.4, §8.4.8.2, §8.4.8.3, §11.4 ¶3, §11.4.1, §12.4.4.1 and §12.4.4.2.**
   - **Ownership of the bridge.** For a Property inherited along a base path, the standard bridge belongs to the conforming Type's mapping. It takes the requirement receiver over the conforming Type and reaches the Field by standard projection (§11.1.2), with the Field's Type and Origins substituted along the path.
   - **No projection, status Proven.** The bridge forms no base-subobject receiver projection (§9.5.1). Its ObjectCallCompatible status is Proven:
     - a shared bridge under §12.4.4.2;
     - a `set` bridge because its only receiver effect is one completeness-preserving Part Replacement (§12.4.4.2 table).
   - **Premises.** Every bridge is checked and executed under its conformance path's premises, including `when` conditions and the substituted premises of an inherited path.
   - **§8.4.4, inherited conformance.** Standard bridges are regenerated for `D`'s mapping. The Property keeps `A` as the Field's declaring Type.
   - **§8.4.8.2.** "Field bridges where applicable" becomes "the Property and bridge kind of each standard witness".
   - **§8.4.8.3 and §8.4.4, path agreement.** Two paths agree on a standard witness when they agree on its Property and bridge kind.
   - **Rationale.**
     - §9.5.1 already says standard access forms no whole-base borrow. The current reading would require an exclusive projection plus an OCC fixed point for one Part Replacement.
     - With this change, witness access has the same canonical form as direct access, and no dependency on OCC-X remains.
     - It avoids requirement result Types that cannot be re-expressed in base parameters, and it is faster.
     - The caller's receiver Loan still covers the whole `D` for the call (§15.6.4), so no guarantee weakens.

### 6.2 G34 (G34-S)

1. **§8.10, "Universal body verification" paragraph.** Replace "adds no premise to the proofs of §8.7" with the following rule. Case enumeration still adds no premise to Constraint proofs; the rest applies to Origin relations (§15.6.5).
   - **Pair-slot atom.** The implicit outer Origin `o` of an original `s/T` (§8.1.1) is a *pair-slot atom*. In its binder's admitted cases that have an outer Origin, it is an Origin stored in every Type that contains the layer, exactly as an explicit stored Origin at the same position. Enclosing well-formedness relates it like any stored Origin (§15.3.7).
   - **Explicit slots.** An explicitly annotated slot's Origin is an ordinary universal Origin. Only the facts produced by its pair-layer position are conditional: the target-outlives-slot fact and the slot-outlives-enclosing-borrow fact. Origins reached from an enclosing borrow layer by ordinary recursion keep no condition.
   - **Conditions.** The *case condition* of a fact is the set of binders whose cases with an outer Origin it requires. A binder that admits only such Semantics, or none, is decided statically and never appears in a condition. The condition of a connected chain (§15.6.5) is the union of its relations' conditions.
   - **Usable premises.** A premise is usable for a chain when its condition is included in the chain's condition. Judging the chain once with usable premises is equivalent to judging it in each case.
   - **Example.** A `Holder<s/T>` getter under `s is ref or uniq` is valid. `f<s/T>(b: ref/Box<s/T during a> during c, x: ref/i32 during a) -> ref/i32 during c` under `s is owner or ref` returning `x` is an error (A.2b).
   - **Function Types.** The rule states no Function-Type exclusion for `o`. The existing result-side stop remains a STATUS limit.
2. **§15.6.5, "Proven" bullet.** In a body with pair binders, well-formedness is that of each case's Types, under §8.10.
3. **§15.6.1, Advice bullet.** Add a carve-out like the one for the Closure call receiver. For an end that is a pair binder's implicit outer Origin, which no Origin expression writes, the Advice suggests one of:
   - annotating the occurrence as `s/T during name`;
   - returning an owned or Copied value;
   - bounding the result by an existing borrowed input.
4. **§8.4.3.1, formation conditions.** A pair layer publishes its conditions only for its admitted cases that have an outer Origin. A use proves them in those cases of its substituted binding: unconditionally for a concrete borrow, and under the caller binder's condition for a pair layer. An implementation relies on them only in those cases.
5. **§15.4.2 table.** Add a row for associated-Type specifications, requirement right-hand sides and formation Types: no omission; complete explicitly with family parameters, enclosing Origins or attached relations; a pair layer's slot follows §8.1.2. The implementation already reports `MissingOriginBinding_Kd` for the concrete form (`g34-design/assoc-ref-omitted`).
6. **§15.3.5 (F25)** is not revised here. G34-S records it as a SPEC_GAP with a PLAN row, owned by a G34 follow-up. A rule must first decide how owner instances are stored statically (inference: a "strongest admitted case" rule would reject static owner instances).

F15 needs no change: §13.5.5.1, §15.5 and §15.6.3 already fix the per-case follow. F17 (§15.6.1), F20 (§23.3.6.4) and F22 (§15.3.6) need none either.

## 9. Verification design

- **Formal evidence comes only from verify.ps1.** Incremental builds and direct test runs are feedback only. StyleCop SA1202/SA1204 and enum-cref errors appear only in the non-incremental Release build.
- **Snapshot chain** (§8 preamble). The corpus covers milestones, `docs/examples`, mutations and syntax cases. The allowed kinds are `case`, `acceptance`, `code`, `severity`, `attribution`, `location`, `text`, `repair` and `order`. Record every difference in the commit.
- **Native fixtures** are only for behavior that depends on generated code. Each `-Fixtures` family must be emitted by a class in the same command. K3 adds a sweep over every family that contains a derived struct without an explicit constructor.
- **Milestones.**
  - Harnesses exist for Programs 1–32, 34, 37 and 39–43.
  - `MilestoneSourcesTest` stage baselines pin Programs 33, 35, 36 and 38. Those baselines must stay unchanged.
  - If P25 becomes DONE, the Session runs every completed program harness.
- **Allocation.**
  - Hot-path units include their `Purpose=Allocation` owners; Unit includes them by default.
  - Assertions are never relaxed, and no extra warming is added.
- **Measurements.**
  - Run in `src/Benchmark` under fixed conditions, pinned and interleaved A/B against U0's A side. Check the compiler id in each JSON, and set `DOTNET_TieredCompilation=0` when pinning.
  - Flags: `--origin-proof`, `--pair-cases`, `--associated-inference`, `--constructor-inference`, `--inheritance-plans`, `--inheritance-lifecycle`, `--property-plans`, library Bind.
  - Results go in `artifacts/benchmarks/`. No speedup claims.
- **Sessions.** Run one per working session, after its last unit. A final Session may satisfy the last Unit only when it covers the same source, configuration and checks.

## 10. Implementation cautions

1. **Constructor query and pending constructors.**
   - Never run the omitted-base query before `capabilitiesReady`.
   - Never publish, insert into an `init` group, or keep obligations for a rejected or pending constructor.
2. **Keep existing guards** until their replacement passes analysis and execution:
   - the Unsupported guard in `PrepareReceiverFields`;
   - `LlvmEmitter.CheckInputs`;
   - the source-writing exclusion of implicit syntax (FunctionKoto.cs ~882);
   - every OCC-X guard: `ProjectedReceiverProof`, `ProjectWitnessCall` Ref-only, base borrows limited to Ref/ObjRef.
3. **Pair-slot rules.**
   - The premise and obligation sides change in the same unit for each slot kind.
   - The original `s/T` BoundType never gains an Origin.
   - Only `o` is a pair-slot atom.
   - Obligations stay over-approximated. Premises are usable only where they hold.
4. **G74 invariants.** Keep proofs pure and version-checked, one environment per request, a linear closure, and `Clear()` resetting every new field. Warm paths use no LINQ and no closures.
5. **Kimi library changes.**
   - Catalog IDs are append-only.
   - `ArrayWithCapacity` gets an explicit overload index before a second `init` exists.
   - New non-source IDs get explicit validation arms, and `ValidCollection` must admit linked constructors.
   - Library bodies must produce no diagnostics; otherwise every program that reaches them faults with `CheckFaulted_Kd`.

   - User-visible text never names an internal implementation.
7. **Diagnostics stay ordinary:** code, location and a concise reason. The detailed diagnostic workflow runs only on explicit instruction.
8. **Shared tree.**
   - Stage explicit paths only.
   - Never edit sources during a build or verify.
   - Pass class lists through `pwsh -Command`.
   - Before rebuilding, check for leftover `xUnitTest.exe` processes and background loops.
