# 変更提案：固定長配列の推論・初期化省略・スライス

日付：2026-10-05。状態：設計方針決定済みの提案。正式仕様への取り込み・実装・実装検証は未実施。

本書で変更する事項は SPEC とその参照先より優先し、それ以外には既存仕様を適用する。

## 1. 現在の仕様

- [SPEC §4.3](../../docs/spec/04-arrays-indexing-and-slices.md#43-initialization-and-inference)：ローカル宣言の `[N of _]` は要素型を推論するが、長さの `_` は禁止。固定長の期待型がない独立した配列リテラルは `Array<T>` を作る。
- 初期値のない固定長配列はゼロ埋めされない。ただし、初回構築は配列全体の初期化・代入に限り、未構築配列への要素書込みと借用は禁止。
- [SPEC §4.6.5–9](../../docs/spec/04-arrays-indexing-and-slices.md#465-slice-storage-lifetime-and-permissions)：`array[range]` は共有専用の `Slice<T>`。`var` 束縛や `uniq/Slice<T>` でも要素の変更権限は得られない。
- `Array<T>.appendCopies(Slice<T>)` は `T is Copy` の要素をコピーする。`Slice<T>.toArray()` と公開の排他的スライスは未定義。

## 2. 問題

- 固定長配列ではリテラルの要素数と型注釈の長さを二重管理する。注釈全体を省くと動的配列になり、格納方式まで変わる。
- 後から全要素を書き込む作業用配列でも、安全な構築のために不要な初期値を埋める必要がある。既存の未初期化宣言だけでは用途を満たさない。
- 変更可能な部分範囲を一つの値として渡せず、配列全体と境界を別々に渡す必要がある。スライスから配列を作る手順も各利用箇所で繰り返す。

## 3. 新しい仕様

### 3.1. 固定長配列の推論

**型注釈に書かれた構造だけを期待型として伝え、穴を既存の推論で埋める。**

- 初期値を持つローカル `let` / `var` の固定長配列注釈で、長さ・要素型の `_` を許可する。注釈に書いたネストにも再帰適用する。
- 長さはリテラルの要素数、または初期値の固定長配列型で確定した長さから決める。既知の要素型も期待型として伝え、関数の公開シグネチャによる推論に利用する。すべての制約が整合し、宣言時点で一意に確定する必要がある。
- 要素型の `_` だけでは、内側のリテラルに固定長構造を要求しない。固定長の期待型がないリテラルは既存規則で `Array<T>` になる。明記した固定長構造の長さが一致しない場合はエラーとし、動的配列には切り替えない。
- 数値・取得・所有権・Origin・候補解決には既存規則を適用する。後続の使用、呼出先の実装本体、`Array<T>` の実行時の長さからは推論せず、長さの式も逆算しない。
- シグネチャ・Field・静的格納・明示ジェネリック引数には `_` を許可しない。関数の長さパラメーターには既存の `<length N>` を使う。

```kimi
var a: [_ of i32] = [1, 2, 3, ] // [3 of i32]
var b: [_ of _] = [1, 2, 3, ]   // [3 of i32]
let empty: [_ of i32] = []       // [0 of i32]
// let unknown: [_ of _] = []    // エラー：要素型を決められない。

var rows: [_ of _] = [[1], [2, 3]] // [2 of Array<i32>]
// var matrix: [_ of [_ of _]] = [[1], [2, 3]] // エラー：内側の固定長が不一致。

func zeros<T>() -> [3 of T]
    T is PrimitiveInteger
    return [3 of 0]

var values: [_ of i64] = zeros() // 注釈から T = i64、戻り型から長さ3。
```

### 3.2. `noinit`

#### 意味と宣言後の扱い

**`noinit` は初期化状態を追跡する機能ではなく、実際の初期書込みを省き、コンパイラには初期化済みとして扱わせる指定である。** 値ではなく、宣言時の特別な初期化指定とする。

次の二つは、初期書込みの有無を除き、宣言後のコンパイラ上の扱いが同じである。

```kimi
unsafe
    var skipped: [3 of i32] = noinit
    var written: [3 of i32] = [1, 2, 3, ]
```

- 宣言で構築完了・初期化済みとし、型検査・代入・取得・借用・呼出し・raw 操作・破棄には通常の規則を適用する。`noinit` 由来の型・状態・フラグを配列や派生値に付加しない。
- 宣言による各要素の初期化状態は解析・記録しない。通常の権限・境界・Loan・Origin・Move 後の使用の検査は維持する。
- 単純代入、アドレス取得、借用、`slice` / `sliceUniq`、メタデータ取得、Scalar 配列の破棄は古い要素値を読まないため、宣言直後から行える。raw 操作にも初回書込み専用の手順を追加しない。

#### 使用条件とプログラマーの責任

- 型注釈を明記したローカル `var` 宣言で、`unsafe` 文脈内だけに許可する。未確定の `_` は許可しない。
- 対象は、直接の要素型が `owner` の Scalar である固定長配列。整数・`Wrapping` 整数・浮動小数点・`bool`・`char` を含み、参照・ポインター・ユーザー型・ネストした配列は含めない。長さ0も許可する。
- 型別名は解決後の型で判定する。ジェネリックでは既存の制約から適格性を定義時に証明する。`Copy` だけでは不足し、新しい `Scalar` Contract は追加しない。
- **読取り前に有効な値を書き込む責任はプログラマーが負う。書込み前の読取りは未定義動作とし、検出は要求しない。** この責任は関数・参照・ビュー・raw を経由しても変わらない。`bool`・`char` にも有効な値が必要で、偶然残ったビット列は書込みの代わりにならない。
- 通常の配列値の Copy・Move・値渡しは全要素の読取りとする。以後の操作には、通常その操作が要求する以上の `unsafe` を追加しない。

最適化や呼出し境界でも、上記の定義された動作を保つ。余分な読取りや値の有効性の仮定で動作を壊してはならず、初期化状態の追跡も要求しない。

#### 構文と例

文脈キーワードとして、宣言の `=` に続く初期化指定全体が括弧なしの `noinit` である場合に認識し、同名の変数より優先する。その後で上記条件を検査し、不適格でも名前参照に解釈し直さない。それ以外では通常の識別子であり、`(noinit)` や修飾名は通常の式として解決する。

```kimi
unsafe
    var array: [3 of i32] = noinit
    var view = array.sliceUniq() // 宣言後は通常の初期化済み配列と同じ扱い。
    view[0] = 1
    view[1] = 2
    view[2] = 3
    let copied = view.slice().toArray()
```

### 3.3. `UniqSlice<T>` と `slice` / `sliceUniq`

`UniqSlice<T>{source}` は、構築完了した配列の連続領域を排他的に借用する通常の Non-Copy 値とする。`noinit` 指定のある配列も3.2により同じ条件を満たす。

#### API と操作

各 `slice` / `sliceUniq` は、引数なしの全体版と、`range: R`・`R is PositionRange` の部分範囲版を持つ。

| 提供元 | `slice()` / `slice(range)` | `sliceUniq()` / `sliceUniq(range)` |
| --- | --- | --- |
| `[N of T]`、`Array<T>` | `ref/Self` を借り、`Slice<T> during self` | `uniq/Self` を借り、`UniqSlice<T> during self` |
| `Slice<T>` | `Self` を Copy し、元の `source` を保持した `Slice<T>` | 提供しない |
| `UniqSlice<T>` | `ref/Self` を借り、`Slice<T> during self` | `uniq/Self` を借り、`UniqSlice<T> during self` |

- 要素の所有権を持たず、ビューの破棄で要素を破棄しない。`T` に Copy・Owned を要求せず、元の領域と要素内部の Origin・Loan を保持する。
- メタデータは読取り専用の `length: isize`、`isEmpty: bool`、`indices: ResolvedRange`。要素添字は既存の Position 正規化と `UniqIndexable<isize>` に従い、使用に応じて `place ref/T` / `place uniq/T` を返す。結果は receiver の借用に依存する。
- 要素の読取り・置換・借用は可能だが、要素を Move して穴を残すことはできない。範囲添字は常に共有ビューであり、`view[range]` は `view.slice(range)` と同じ。
- receiver と範囲は通常の順序で各1回評価する。既存の範囲解決・境界検査に従い、範囲外は Abort。添字はビューの先頭から0起点とし、ネストした配列を平坦化しない。
- 形成・再スライスは O(1)、要素コピー・ヒープ確保なし。一時値の寿命を延長せず、同一式内の一時ビューを通じた代入は許可する。

#### 取得・権限・依存

- `UniqSlice<T>` の所有値に暗黙の再借用・Copy・Move・共有ビューへの変換は追加しない。子ビューは `view.sliceUniq(...)`、共有化は `view.slice(...)`、移譲は `view@move` を使う。メソッドの receiver 借用は通常どおり行う。
- 所有値を名前付きローカルに束縛した場合、排他的操作には `var` が必要。`uniq/UniqSlice<T>` の参照先への権限は別であり、その参照を `let` に束縛しても既存規則で排他的アクセス・再借用ができる。共有経路は変更権限を持たない。
- `T` の完全な型は不変とする。`source` の短縮は通常の借用規則に従い、排他的権限を複製しない。空のビューも Non-Copy で、元の借用を保持する。
- 子ビューは元領域と親ビューへの今回の借用に依存し、その借用が必要な間は親の競合する使用を禁止する。共有化しても元配列の排他的 Loan は解放・弱化せず、共有借用中は書込みを禁止する。
- 配列からのビューは元配列全体を借りる。別々の範囲や実行時の不等式から非重複を推論せず、元配列の競合する変更・再配置・Move・破棄を禁止する。

```kimi
var array: [3 of i32] = [1, 2, 3]
array.sliceUniq(0..3)[0] = 10 // 元配列を変更する。
// array[0..3][0] = 10       // 共有ビューなので不可。

var view = array.sliceUniq()
let reference = view@uniq
reference[0] = 20           // let に格納した排他的参照からの変更は可能。

// let frozen = array.sliceUniq()
// frozen[0] = 30           // 所有値を let に束縛した場合は不可。
```

初版はメタデータ、要素添字、共有・排他の再スライスまで。`UniqSlice` の反復適合、専用の非重複分割、新たな try 系API、任意ポインターからの公開構築は導入しない。既存型の反復・try 系APIは維持する。

### 3.4. `Slice<T>.toArray()`

`toArray(self: Self) -> Array<T>` を追加し、`T is Copy` を要求する。各要素を1回ずつコピーし、同じ要素順序・長さで、独立した要素格納域を持つ配列を返す。深い複製や暗黙の所有権移譲は行わない。

コピー後に元スライスの外側の借用を保持する必要はないが、`T` 内部の依存は保持する。全対象要素を読むため、3.2の読取り前の責任も適用する。

O(n) とし、必要容量を最初に確保して構築中に拡張しない。要素格納用の確保は最大1回、空なら0回。容量は長さ以上であればよく、確保失敗は既存規則に従う。意味と費用の保証を満たせば、一括コピーなどの実装・最適化を許可する。

`UniqSlice` からは `view.slice().toArray()` を使う。`UniqSlice.toArray()`、`toSlice()`、`toUniqSlice()`、`toSliceUniq()` は追加しない。

## 4. 変更点

| 対象 | 変更 |
| --- | --- |
| 型推論 | ローカルの固定長配列注釈に、長さの `_` とその再帰的解決を追加 |
| 宣言・初期化 | Scalar 要素の固定長配列に `noinit` 指定を追加。通常の初期値なし宣言の解析は維持 |
| 宣言後の扱い | `noinit` も通常の初期化済み配列として扱う。読取り前の書込みはプログラマーの責任 |
| 公開ライブラリ | `UniqSlice<T>`、共有・排他の `slice` API、`Slice.toArray` を追加 |
| 既存の操作 | `array[..]` は共有のまま。`uniq/Slice<T>` はハンドルの借用のまま |

`Uninit<T>`、書込み専用ビュー、初期化完了を通知する操作、初期化状況の実行時管理は導入しない。

## 5. 変更する理由

- **One Concept, One Canonical Form**：固定長配列を選ぶ書式を維持し、未知の部分だけ `_` にする。共有・排他の切出しは `slice` / `sliceUniq` に統一する。共有の範囲添字は汎用の範囲構文、メソッドは全体版との一貫性とAPIの発見しやすさを担うため、同義の形式として併存させる。
- **Local Reasoning**：推論を宣言内で完了させ、取得・再借用・非重複の規則を拡張しすぎない。呼出先は公開契約だけで検査できる。
- **Explicit Semantics**：初期化保証の委譲を `unsafe` と `noinit`、排他的アクセスを Non-Copy 型と `Uniq` 接尾辞、要素コピーを `toArray` の契約で明示する。
- **Compiler Server Protocol**：推論結果と根拠、初期化保証を委譲した指定位置、借用モードと依存をソース位置付きで公開できる形にする。初期化状況の追跡は追加せず、診断・検査・測定を正確なソースと構成に結び付ける。

### 実装と検証の要点

- **参照引数の最適化：** Scalar の参照引数を物理的な値渡しに変える場合も、元のプログラムで不要だった値の有効性を要求しない。ポインター自身と参照先の値の保証を混同せず、値を読まない関数への参照渡しが宣言直後でも O0/O2 で成立することを確認する。
- **コピー処理の共通化：** `toArray` は容量指定構築と `appendCopies` を利用する方針とする。重複した容量確認などは共通の `appendCopies` 側で改善し、必要容量・オーバーフローを先に確認してコピー後に長さを更新する処理を検討する。一括コピーは Copy の意味と Origin・Loan を保つ条件で行い、専用のコピー機構を増やさない。
- **診断と実行：** `unsafe` / `noinit` の追加を無条件の自動修復にしない。書込み前の読取り例は受理だけを確認し、実行結果に期待値を置かない。正常例では借用先での書込み後に読み出し、O0/O2 の動作を確認する。

各実装単位は関連する機能・割当て/再利用・ネイティブ O0/O2 を Unit Verify で確認し、セッション末に Session Verify を行う。初期ストアと余分な読取り、ビュー形成時の確保、`toArray` の確保・拡張回数を確認し、性能測定は固定条件で別途行う。NativeAOT は実行しない。証跡は `artifacts/verify`・`artifacts/benchmarks` に保存し、完了した単位だけをコミット・push する。

機能追加時に CODEMAP・LIBRARY・STATUS・PLAN を実際の変更・検証範囲に合わせて更新する。提案の保存だけでは正式仕様、実装、対応範囲を変更しない。
