# G34, G73 and G80 Repair Plan

- Date: 2026-10-09 (Asia/Tokyo)
- Status: Proposal; investigation and implementation plan only

## 1. Objective, evidence and scope

Resolve the requirements recorded as G34, G73 and G80 in [PLAN](../../docs/dev/PLAN.md), using the existing canonical Type, call, ownership and storage plans. Deliver the work in independently verifiable units, preserving definition-side proofs, actual Loans, initialization order and source identity. This document changes neither the implementation nor the specification.

The investigation read the formal specification, [SETTLED](../../docs/SETTLED.md), [CODEMAP](../../docs/dev/CODEMAP.md), [STATUS](../../docs/STATUS.md), compiler and library sources, and the owning tests. It traced the paths described below. No compiler builds, tests, native execution or measurements were performed for this documentation-only task. Statements about current gates are source observations; existing support claims are those already recorded in STATUS. Historical failures that have not been reproduced on this revision are explicitly distinguished from confirmed source gaps.

In particular, G34's blanket Field-storage description may predate relevant fixes. The first implementation action must establish which examples still fail. A repair plan must not manufacture a new storage subsystem to fix an obsolete symptom.

## 2. Contracts and decisions

The governing sources are [generics §8.1, §8.4.3 and §8.10](../../docs/spec/08-generics-constraints-and-contracts.md), [constructors §6.2.3](../../docs/spec/06-declarations-and-containers.md), [Array §4.7](../../docs/spec/04-arrays-indexing-and-slices.md), [Properties §11](../../docs/spec/11-properties.md), [receiver preservation §12.4.4](../../docs/spec/12-expressions.md), [ownership §15](../../docs/spec/15-ownership-and-lifetime-analysis.md), and [OCC staging D.5.1](../../docs/spec/appendices/D-deferred-features.md). The [embedded-library policy](../../src/Kimi/Library/README.md) assigns ordinary algorithms to Kimigayo and representation/typed memory primitives to the compiler.

No language-rule revision is presently justified. The identified gaps can be addressed without new syntax, a weaker storage requirement or a new constructor capability. Preserve these invariants:

1. **One complete Type.** Original `s/T` reconstructs the pair's supplied `W`. Another `s/U` uses the selector but never inherits `W`'s outer Origin. Binding identities determine the distinction even when instantiated targets happen to become equal.
2. **Conditional Origins.** A borrowing application uses its own occurrence's Origin; a value case drops only the inactive outer slot, retaining dependencies inside the target. A borrowing `s/U` Field without the required annotation remains invalid. Instantiation substitutes a definition contract; it creates no missing binder or proof.
3. **Actual authority.** Equal Origins do not merge independent Loans. Copy, Move, Reborrow, stored-reference follow, last-holder recovery and cleanup remain ordinary ownership operations. `uniq` target invariance and shared-path restrictions are unchanged.
4. **Single selection and acquisition.** Candidate comparison uses declarations and published contracts. Selected body, default, ownership or safety failure does not retry another candidate. A bridge preserves source evaluation order and acquires each argument once.
5. **Construction completeness.** Base construction completes once, then own declaration initializers run in order, then the body. Synthesized constructors use the same plans and cleanup as explicit constructors. An ineligible implicit constructor leaves a valid Type with no constructor; an eligible constructor with an invalid initializer reports that real error.
6. **Initialized storage.** Array capacity is not initialized length. Only initialized elements are readable or destructible. Count validation and allocation finish before the repetition loop; the length publication certifies exactly the initialized prefix.
7. **Receiver identity.** The conforming receiver, the Type that declares a stored Property, the base path, and the requirement's Origin binder are distinct facts. A physical base address never replaces the complete source Loan or proves receiver preservation by itself.
8. **Phase ownership.** Binding records semantic plans; ownership verifies them; lowering consumes verified plans. LLVM writing does not redo Binding or discover lifetime facts. Rebinding invalidates every dependent certificate and body plan.

These choices uphold one canonical form and bounded local reasoning: one pair/Origin model, one ordinary selector, one source repetition algorithm, and one receiver-preservation proof. Existing SETTLED decisions remain valid: accessors retain their fixed receiver modes; inherited names require qualification; generic defaults retain their per-operation interpretation contexts. Do not reopen those decisions as shortcuts.

If implementation reveals a contradictory or unsound rule, stop the affected unit, state the contradiction and a smaller consistent replacement, and update the formal chapters, examples, tests and affected milestone sources together. Record any actual spec intake in `draft/INTEGRATED.md`; update SETTLED only if its recorded rationale changes. This planning document itself is not a spec intake.

## 3. Investigated control flow and root causes

Source stems below are relative to `src/Kimi/Compiler`: `Binding.*` is in `Binding/`, `OwnershipAnalysis.*` and `OwnershipBody.*` in `Analysis/`, and `BodyLowering.*`, `GenericStoragePlan*` and `LlvmModuleWriter.*` in `Emission/`. Test class names refer to `tests/xUnitTest/Tests/`.

### 3.1 Shared pipeline

`Compilation.Bind` enters `Binding.Bind`: reset/invalidate downstream state, index user and library declarations, bind declarations, bind bodies, validate declarations and finalize the result. `OwnershipAnalysis.Analyze` constructs and solves Places, Loans, effects and cleanup from final Binding facts. `LlvmEmitter.TryPrepare` and `GenericStoragePlan` require current valid analyses before physical lowering. Failure must prevent IR publication, including failures discovered while preparing a concrete generic instance.

The repair points lie in different phases. A missing declaration is not an emitter problem; a complete Type's dependencies are not a layout problem; a receiver address conversion is not a preservation proof. Tests must expose those distinctions.

### 3.2 G34: conditional formation versus historical storage boundaries

The confirmed root cause is the mismatch between conditional pair application contracts and the concrete-shape family formation gate/proof walkers. For the two storage claims, the root cause remains an implementation-time investigation item, not a reason to replace already generalized code.

Existing evidence is narrower than G34's requirement. `AssociatedPairFormationTest.PairTargetFamilyExecutes` executes `Holder<i32>` with a `ref/T` family; it does not instantiate that Holder with `ref`/`uniq` or define an `s/U` family. `PairAnnotationBindingTest.OneAnnotatedSignatureServesValueAndBorrowInstances` uses an ordinary generic Box, not a pair-binder Holder. `PairCaseTypeTest`, `PairGroupingBindingTest`, `PairFollowTest`, `GenericStorageEmissionTest`, `LocalRegionCompositionTest` and the associated formation/domain/editing suites cover reusable machinery but do not collectively prove the missing combinations.

### 3.3 G73: no executable initialization bridge

The required overload appears in SPEC §4.7.2 and LIBRARY, but not in [ArrayOperations.kimi](../../src/Kimi/Library/ArrayOperations.kimi) or the recognized constructor catalog. The existing capacity constructor is validated through `KimiLibraryCollections` and lowered by [BodyLowering.Arrays.LowerArrayConstruction](../../src/Kimi/Compiler/Emission/BodyLowering.Arrays.cs). That lowering deliberately accepts one `isize` argument and emits empty-handle initialization plus checked reserve.

An ordinary source constructor cannot simply implement repetition with whole-`self` assignment or mutation calls: constructor `self` admits first placement into own Fields, while Array storage is compiler-managed and has no such source Fields. Nor would adding a loop only in LLVM lowering solve source reachability, generic proof, effects or actual Loan transfer.

The existing [Array.kimi](../../src/Kimi/Library/Array.kimi) `appendCopies` body supplies the relevant pattern: reserve once, borrow stable raw storage, `Raw.initialize` each new element, then `Storage.setArrayLength`. Copy invokes no user code. Capacity construction already forwards caller location through `function.Abi.CallerLocation`.

The root solution is a narrow recognized-constructor bridge to a Kimigayo factory returning `Array<T>`, carrying the selected public call's complete contract. It is an implementation bridge, not a new language feature or public factory spelling. Ordinary user constructors retain their current `self` rules.

Catalog registration is part of the fix: `ArrayWithCapacity` currently has no overload index, and `KimiLibrary.FindDeclaration` rejects a second matching declaration under that lookup. Register both overload identities deliberately, retain existing stable declaration IDs, and validate complete signatures; adding a second `init` line alone can invalidate the embedded library.

### 3.4 G80: phase placement, bridge context and missing preservation proof

**Constructor synthesis.** [StructKoto.PrepareImplicitConstructor](../../src/Kimi/Compiler/Parsing/Koto/Declarations/DeclarationContainers/StructKoto.cs) immediately excludes any struct with a base. The Binding indexer invokes it before declaration headers, base Types, access and constructor candidates are semantically ready. That placement can decide simple syntactic eligibility but cannot answer SPEC §6.2.3.6's ordinary zero-argument base invocation question.

The explicit-constructor path already exists: `FunctionKoto.PrepareBaseInitializer`, `Binding.Structs.BindBaseConstructor`, `Binding.Expressions.BindFunction`, ordinary defaults, `PrepareReceiverFields`, and normal constructor lowering. `ImplicitBaseCallTest.OmittedBaseCallUsesOrdinaryDefaultsBeforeOwnInitializers` verifies its order. Reuse it after a non-publishing eligibility query; do not manufacture a second overload algorithm or call `BindCall` speculatively and delete its diagnostics afterward.

**Standard Property witnesses.** [Binding.PropertyWitnesses.PropertyWitnessFunction](../../src/Kimi/Compiler/Binding/Binding.PropertyWitnesses.cs) returns null for a standard witness with `BasePath`. Below that guard, its synthetic receiver uses `witness.ReceiverType`, while the lexical scope, function parent and instantiated call's declaring Type come from the implementing Property/base. `InstantiatePropertyRequirementCall` subsequently applies the custom-accessor-style receiver projection. Removing the guard leaves conflicting execution contexts.

Use a conformance-owned standard bridge: its receiver remains the conforming Type expected by the requirement; its direct storage access retains the separately instantiated declaring Type and inherited Field path. A custom accessor instead calls the actual base-declared function with the existing receiver projection. These are distinct executable operations, not interchangeable metadata.

`PropertyWitnessEmissionTest` verifies non-inherited Copy/borrow/set witnesses, named requirement Origins, generic associated results and reuse. `InheritedAccessorEmissionTest` and `InheritedConformanceTest` cover shared custom getter/function paths. Neither justifies enabling the standard inherited bridge by deleting its guard.

**Exclusive receivers.** `Binding.ArgumentOperations.ProjectedReceiverProof` proves shared receiver shape but returns Unknown for exclusive shape. `Binding.RequirementInstances.ProjectWitnessCall` accepts only `ref`; `OwnershipAnalysis.Reservations.PrepareCallArgument` and `BodyLowering.StructBorrows` likewise have shared-only base projection paths. These are coordinated support guards, not independent bugs.

SPEC §12.4.4 requires value-flow facts relating operations to the protected receiver, callee composition, closed specialization families and actual Loan checks. Existing effect classifications or Type identity alone do not prove that an operation preserves the same receiver value. P36/static roots and the relevant G78/G83 paths are prerequisite work; PLAN explicitly orders OCC-X after P36. Shared success is not evidence for exclusive use.

There is also a phase dependency to solve before building that proof: `OwnershipAnalysis.Analyze` refuses incomplete Binding, while `Binding.Calls` currently fails an unresolved projection before retaining a successful `BoundCall`. Ownership-derived preservation facts therefore cannot simply be computed after an ordinary failed Bind. An internal selection-complete, proof-pending analysis phase is required; public success and emission must still wait for completed validation.

### B1 — Implement the internal repetition algorithm in Kimigayo

**Targets:** `Library/Storage.kimi` (or a narrowly scoped embedded companion with the existing embedding registration), standard storage validation and the existing Array/storage test owners.

**Changes:** Add an internal generic factory, provisionally `Storage.createRepeatedArray<T>(repeating: T, count: isize) -> Array<T>`, with `T is Copy`. It constructs a local Array with capacity `count`, returns it immediately for zero, initializes indices `[0, count)` by ordinary Copy plus `Raw.initialize`, publishes length once with `Storage.setArrayLength`, then returns the owner by Move. Reuse capacity construction for negative count, size and allocation checks. Retain the existing caller-location mechanism for the eventual bridge. The helper has no public API status and grants no whole-`self` constructor permission.

**Reason:** The algorithm already fits the source/storage boundary used by `appendCopies`; a handwritten LLVM loop would duplicate it. Since Copy executes no user code and reserve has already succeeded, the initialization loop needs no new recoverable-failure or partial-unwind mechanism.

**Verification:** Compile and execute the helper through the embedded-library test path with scalar, zero-count, Copy aggregate and zero-sized inputs. Reuse the pattern in `StorageBoundaryTest.RemainderElementsAreLentByBorrowingRawPlaces`: inject a test-only probe into `c.Library.Kotonoha` to exercise the internal helper, without a public production test hook. Verify length/value/ownership results and that capacity construction is still the common checked allocator. Use the existing storage signature tests for `setArrayLength`/raw initialization contracts. Include private-access and unused-helper reachability checks. Any new embedded source must participate in library loading and warm-reuse verification.

### B2 — Bridge the selected public constructor to the source factory

**Targets:** `Library/ArrayOperations.kimi`, `KimiLibraryCatalog`, `KimiDeclaration.cs` (`KimiDeclarationId`), `KimiLibraryKinds.cs` (`CompilerFunctionKind`), `KimiLibraryCollections`/validation, selected constructor planning, `OwnershipAnalysis.Call` and instance collection, `GenericStoragePlan`, ordinary call lowering and caller-location metadata.

**Changes:** Add the canonical `init(! repeating: T, count: isize)` signature with its checked `T is Copy` obligation. Append stable IDs as required and explicitly register/validate both Array `init` overload identities, including the existing capacity entry. After ordinary constructor selection, create a reusable forwarding certificate containing the public selected call and the instantiated helper execution call. Fix helper `T` to the selected Array element Type; preserve complete parameter/result Types, Origins, argument-to-parameter mapping, source order and any supported default plan. The helper's own Copy constraint must agree with, not replace, the public selected-call obligation.

Validate the helper's source and bound parameter identities, `Array<T>` result, Copy obligation and caller-location contract before issuing a forwarding certificate. The generic `SourceFunction` catalog fallback checks body existence, which is insufficient for this trusted mapping. Mutating or replacing the helper must invalidate the certificate and its reachable instance plans.

Keep the public AST target for diagnostics/Hover. Give ownership, effect collection, reachability and lowering one access path to the retained execution plan. Acquire original inputs once; pass prepared arguments to the helper call, record its result on the original invocation, and use ordinary result ABI/Loan transport. The helper is analyzed and instantiated as source before lowering can emit it. Do not rebind or reselect from emission and do not implement forwarding as only a `LowerCall` special case. Audit consumers that read `InvocationKoto.BoundCall` directly so none accidentally uses the public constructor as a source body or ignores the helper's effects.

**Reason:** A bridge is a cross-phase semantic operation. Only a retained plan can keep ownership/effects, generated reachability, caller location and physical execution consistent. Supporting another overload must not invalidate capacity construction or recognize a user declaration by spelling.

**Verification:** Extend `ArrayMembersTest`, `CatalogSignatureValidationTest`, `CoreCatalogTest` and constructor inference owners. Test both overloads, label rules, explicit/inferred element Types, a source-defined lookalike, source/bound signature mutations of both public entries and the helper, selected Copy failure and absent fallback. Native cases check source evaluation order exactly once, early-exit arguments, public call-site Abort attribution and execution through the helper. Inspect the retained plan at the lowest layer that owns it; verify no generated helper is reachable when the constructor is unused, and a helper edit revokes stale forwarding certificates.

### C1 — Extract a non-publishing ordinary constructor eligibility query

**Targets:** `Binding.Calls`, candidate evaluation/argument mapping helpers, `Binding.Structs.BindBaseConstructor`, constructor candidate storage and existing selection tests.

**Changes:** Separate ordinary constructor selection's decision from committing the chosen call and publishing call-site failures. The query takes the fixed direct-base Type, the derived declaration's access context, zero supplied arguments and existing Constraints. Return a bounded outcome such as unique selection, no applicable candidate, inaccessible, ambiguous, or prerequisite unavailable/error, retaining the winner/default mapping when applicable. Use the ordinary comparator, labels/default availability and access rules. Do not evaluate defaults, bind bodies, acquire arguments, mutate executable syntax or publish a speculative call error. Declaration errors remain owned and reported by declaration validation.

Route real base calls through the same decision plus the existing diagnostic/commit path. Protected constructor access remains legal in this dedicated context. Distinguish an incomplete prerequisite from a definitive absence so declaration order cannot determine synthesis.

**Reason:** Reimplementing a zero-parameter/default-count test would disagree with ordinary overload rules. Suppressing diagnostics after a speculative call would leave other speculative state and could hide real errors.

**Verification:** Extend `ImplicitBaseCallTest` and constructor inference/diagnostic tests. Compare query and actual invocation selection for exact zero-parameter candidates, all-default candidates, competing defaults, required arguments, private/protected access, fixed generic bases and prerequisites. Confirm a query leaves call operations, diagnostics and source syntax unchanged, and a real explicit omitted-base call retains its existing error and location. Check warm reuse and no selected-failure fallback.

### C2 — Complete derived implicit constructors in the semantic phase

**Targets:** `StructKoto.PrepareImplicitConstructor`, Binding indexing/declaration completion, `FunctionKoto.PrepareBaseInitializer`, existing synthetic constructor indexing/header/body work and reset/invalidation.

**Changes:** Separate reusable synthetic syntax allocation from semantic availability. After selected/merged declarations, base Types, candidate signatures and access are ready, complete eligibility base-before-derived using C1. Synthesize exactly one own public zero-parameter constructor when §6.2.3.6 holds, then index/bind it through the existing special-receiver and omitted-base/default machinery before body/conformance consumers need it. Preserve non-derived synthesis and suppress synthesis for every selected explicit/generated constructor, including private ones.

For absent, inaccessible or ambiguous base invocation, publish no implicit constructor and no speculative call error on the unused Type. For a selected eligible declaration, invalid defaults/initializers report normally; do not suppress synthesis merely because execution later fails. ## 7. Implementation cautions and regression risks

| Risk | Required protection |
| --- | --- |
| Mistaking a stale G34 issue description for current behavior | U0 identifies the failing phase; delete unnecessary repair work when current evidence passes. |
| Conflating original pair and another equal instantiated target | Compare declaration Binding Identities; retain independent occurrence Origins and nested dependencies. |
| Treating `s/U` as an unconditional borrow or unconditional owner | Reuse canonical admitted-case formation; test inactive outer slots, nested origins and every admitted definition case. |
| Origin equality substituting for Loan authority | Test distinct referents with equal named Origins and actual conflicts/last use through stored results. |
| Allowing an instance to rescue an invalid generic definition | Require universal body/formation proof before concrete generation; preserve instance failure diagnostics and no IR. |
| G73 forwarding only in emission | Retain one execution certificate consumed by reachability, ownership, effects and lowering; validate Copy at the public call. |
| Two `init` entries corrupting the Kimi catalog | Preserve stable IDs, explicit overload identities and full source/bound signature validation for both entries. |
| Premature Array length publication or per-element allocation | Reserve/check first; initialize Copy values with no intervening user operation; publish exactly once; test zero-sized/count and failure paths. |
| Lost caller location or duplicated argument evaluation | Keep original invocation context and source-order acquisition; exercise generic callers, reordered named arguments and early exits. |
| Synthesis depends on traversal order or hides declaration errors | Semantic readiness after merging, base-before-derived completion, pure eligibility decision and real post-selection diagnostics. |
| Double substitution or wrong receiver on inherited witnesses | Separate conforming execution receiver from storage declaration/base mapping; named Origins and multiple generic layers are essential tests. |
| A `uniq` guard is removed before proof/activation/lowering agree | Land XP then X1–X4 in order, preserving explicit pending obligations and no-IR barriers until the final consumer verifies them. |
| Loss of effects through helpers, defaults, cleanup or specializations | Map semantic operations through actual roots and the closed implementation family; do not propagate only a Boolean summary. |
| Stale pooled certificates or unbounded retained storage | Edit/rebind/failure-recovery tests, versioned proof ownership, existing allocation isolation and fixed-condition scaling inputs. |

Avoid broad API changes: no `Owned` requirement on ordinary pair storage or repeating Copy elements, no memberwise constructor fallback, no public alternate repetition factory, no new accessor receiver form, and no reconstruction of semantic decisions in LLVM. Preserve unrelated user/session edits and frozen draft text.

## 8. Unconfirmed items and conditions for changing the plan

1. **G34 historical storage failures:** the exact present phase outcome for original reference-instantiated Holder and explicitly annotated `s/U` Fields is unconfirmed. If they pass, retain regressions and correct the issue description after verification; cancel A1's code change.
2. **Family proof integration:** the exact smallest shared helper boundary between conditional formation and the current Origin premise catalog requires implementation-time design against the reproducers. Reuse canonical proof machinery; if a proposed helper would introduce a second solver or repeated concrete enumeration, revise A2 before coding it.
3. **G73 source helper composition:** ordinary raw initialization exists, but this exact factory and its complete reference-bearing return path have not been compiled here. If failure is an existing named storage/Callable boundary, identify it before deciding whether it is a prerequisite or outside G73. Do not lower the loop in LLVM to conceal that failure.
4. **Constructor selection readiness:** the precise insertion point for derived synthesis must be proven against fragment merging, generated declarations, generic base constraints and declaration cycles. If the current header order cannot support a pure query, split C1/C2 further to introduce explicit completion state; do not globally rerun Binding or hide diagnostics.
5. **Bridge execution identity:** C3's conformance-owned context may require a small extension to accessor execution metadata. If existing metadata already expresses receiver and storage owner independently, use it. If a new bridge representation duplicates ordinary calls/Places, revise the design rather than adding a second lowering path.
6. **Inline standard setters:** C4 is independent of arbitrary exclusive base calls only when its retained plan truly remains a derived receiver plus Field projection. If it becomes a whole-base call, stop and route that variant through OCC-X.
7. **Exclusive prerequisites:** this audit does not certify P36 static roots, G78 value-flow integration or G83 object witnesses as complete. If they remain unavailable, finish independent A/B/C units and keep X work gated. Never report all of G80 closed on constructor/getter success.
8. **New soundness evidence:** a Loan escape, double destruction, incomplete receiver, stale proof or spec contradiction outranks the planned order. Stop opening support, minimize the reproducer, repair the common invariant and rerun affected verification before continuing.
9. **Measured complexity regression:** if conditional proofs, candidate queries or bridge caches grow superlinearly or violate retained-storage bounds, revisit the representation/worklist before widening acceptance. A performance claim needs comparable fixed-condition measurements; a passing small fixture is insufficient.
10. **Scope change:** an independent G75 B7/E6/E7, G79, G83 or G78 failure is not automatically a G34/G73/G80 root cause. Record the exact blocked acceptance row and dependency. Expand a unit only when the requested behavior cannot be implemented soundly without that dependency, and update its verification/closure conditions first.

Every deviation must state the evidence, the invariant being preserved, the revised targets and the resulting verification scope. The final outcome is a set of verified requirements and explicitly owned remaining limits, not merely the absence of the three original diagnostic symptoms.
