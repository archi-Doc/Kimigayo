# クロージャの引数括弧の省略

日付：2026-10-10。状態：文法方針は利用者合意済み。正式仕様への取り込み・実装は未実施。スタイルとフォーマッター方針は採用時に確定する。

本書は変更提案であり、コンパイラー実装と並行してコードを変更しない。

## 1. 現在の仕様

[SPEC §7.6](../../docs/spec/07-functions-and-callable-values.md#76-function-expressions) と [構文付録 F.4](../../docs/spec/appendices/F-syntax-summary.md) では、匿名関数は `func`、任意のキャプチャリスト、括弧付き引数リスト、任意の戻り値注釈、本体からなる。

```kimi
var f: (i32) -> i32 = func (x) => x * 2
var f2: () -> i32 = func () => 0
var f3: (i32, f32) -> i32 = func (x, y) => x + y@i32
```

引数型の省略には、チェック前に確定した期待シグネチャが必要。本体や後続の呼び出しから引数型を推論しない。本体は `=>` に続く単一項目、またはインデント本体。後者が非 Unit の値を返すには `return` が必要。

## 2. 問題

- 短いコールバックでも引数括弧が必須で、呼び出し側の括弧と重なって読みにくい。
- `func` 自体が匿名関数の開始を示すため、引数なし・型注釈のない１引数には省略の余地がある。
- ただし、省略を無制限にすると、名前付き関数との判別や引数・戻り値の境界が複雑になる。利点は可読性と記述量であり、実行性能の改善ではない。

## 3. 新しい仕様

### 3.1. 引数部

`func` と任意のキャプチャリストの後に、次のいずれかを書く。

| 引数部 | 意味 |
| --- | --- |
| 省略 | ０引数、タスクスロットなし |
| 名前１つ | 型注釈のない１引数、タスクスロットなし |
| 括弧付きリスト | 現行の一般形。空リスト・１引数も引き続き有効 |

複数引数、型注釈付き引数、タスクスロットには括弧を必須とする。名前だけの形式にカンマや型注釈を続けることはできない。

```kimi
var f: (i32) -> i32 = func x => x * 2
var f2: () -> i32 = func => 0
var f3: (i32, f32) -> i32 = func (x, y) => x + y@i32
let typed = func (x: i32) => x * 2
let fixed = func [] => 0

let count: i32 = 0
var next = func [var count] -> i32
    count += 1
    return count

var doubled: (i32) -> i32 = func x -> i32
    return x * 2
```

省略形も明示的な戻り値注釈と両方の本体形式を使える。`=>` の直後の改行は認めない。括弧なしの引数名は `func`、またはキャプチャリストの終端と同じ物理行に置く。引数リストを改行する場合は括弧を使い、戻り値注釈の継続は現行 §2.2 に従う。

### 3.2. 宣言と式の判別

判別は構文だけで行い、型チェックの成否でやり直さない。

- 式だけを許す位置では匿名関数として読む。名前付き関数宣言へ切り替えない。
- 宣言だけを許す位置、または宣言専用の属性・修飾子を伴う場合は、現行の宣言文法に従う。
- 宣言と式の両方を許す位置では、キャプチャリストなしの `func 名前` に引数リストの `(` またはジェネリック引数宣言の開始 `<` が続けば、名前付き関数宣言に確定する。それ以外は匿名関数の文法で検査する。
- いずれも改行・継続の規則を先に守る。構文エラーや引数型不足があっても、別解釈を試さない。

名前付き関数は引数括弧を引き続き必須とする。例えば、実行可能ブロックの `func run => work()` は、引数名 `run` を持つ匿名関数として扱う。期待シグネチャがなければ引数型不足であり、`run()` の宣言として補完しない。

### 3.3. 維持する意味

- `func x` は `func (x)`、引数部省略は `func ()` と同じ意味を持つ。引数個数は期待型から補わない。
- 型推論、引数の不変性、名前の重複・シャドーイング、キャプチャと所有権の規則は変更しない。`_` 引数や引数のパターン分解は追加しない。
- キャプチャリスト省略は従来どおり Copy に限る推論、`[]` はキャプチャ禁止。引数括弧の省略とは独立する。
- タスクスロットは `(task; ...)` と明示する。`func task => task` の `task` は通常の引数名であり、タスクスロットではない。
- 関数型の表記と共通関数型への変換条件は変更しない。排他的・消費的なクロージャや非 static の借用を含む環境を、省略形だからという理由で共通関数型へ変換しない。

## 4. 変更点

匿名関数の引数部に「省略」と「型注釈なしの名前１つ」を追加する。既存の括弧付き形式は削除せず、`func` も必須のままとする。

スタイルとフォーマッターの自動統一は、文法上の許可とは別に決定する。**未決定事項は、省略可能な箇所を標準スタイルで省略形に揃えるか、フォーマッターが既存表記を書き換えるか。正式採用時に方針を固定する。** 整形によって型注釈や本体形式を変更しない。

## 5. 変更する理由

- **One Concept, One Canonical Form**：括弧付きの一般形と同じ意味処理を使う。頻出する短いコールバックの可読性を、省略表記を認める明確な実用上の利点とする。
- **Local Reasoning**：`func`、後続構文、改行から境界と引数個数を確定し、型情報による構文の選び直しを行わない。
- **Explicit Semantics**：所有権・依存関係・タスクスロットを暗黙化せず、引数部の表記だけを簡潔にする。
- **Compiler Server Protocol**：実際のソース範囲と表記を保持し、同じ匿名関数モデルで検査・編集できるようにする。

代償は省略条件と宣言判別の追加、`func 名前` の読み違い、ツールの対応範囲の増加である。型注釈付きの括弧省略などには拡張せず、追加規則を限定する。
