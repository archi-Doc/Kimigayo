# 型の構造に基づく同一性

状態: 一部取り込み（提案受付のみ。仕様への取り込み・実装は未実施）。
作成日: 2026-10-22。対象: G170-C1 の検討から得た、型同一性の仕様変更案。
現行仕様の参照版: `fed0f2073`。本書は言語の意味を定める。内部表現、正規化の方式、実装計画は定めない。

## 1. 現在の仕様

[SPEC §8.2.3](../../docs/spec/08-generics-constraints-and-contracts.md#823-type-identity-and-identity-premises) は、型同一性の前提から、型の内部で同一な型を置き換えられる最小の同値関係を作る。射影も置換の対象になる。

- `T is U` は型の同一性であり、変換を意味しない。
- `T ≡ U` なら `Option<T> ≡ Option<U>`。逆向きには分解しない。
- `T is Option<U>` と `T is Option<i32>` があっても、`U ≡ i32` は導かれない。
- 一つの同一性クラスに異なる完全束縛型が入る場合、または型が自分を真部分として含む場合は宣言の誤り。
- 同一性の要求は、同じクラスなら Proven、両側が完全束縛されて異なるなら Refuted、それ以外は原則 Unknown。

[§8.3](../../docs/spec/08-generics-constraints-and-contracts.md#83-constraint-proof) は Contract の前提からの導出と判断の確定性を、[§8.5.5](../../docs/spec/08-generics-constraints-and-contracts.md#855-inference) は関連型推論の凍結前提と証拠抽出を定める。型同一性と、欠けた型を推論する手続きは別の規則である。

現在の非分解則では、`Option<U>` と `Option<i32>` を同じ型として扱いながら、その構成要素を同じ型として扱えない。本案はこの差をなくす。

## 2. 変更点

| 項目 | 新しい規則 |
| --- | --- |
| 型の構造 | 同じ型形式・固定属性を持つ型の同一性から、対応する型成分の同一性を導く。 |
| 構造の不一致 | 異なる名義型、異なるタプル要素数など、確定した構造の不一致は、型引数が未束縛でも同一性を否定する。 |
| 型以外の条件 | 長さ・Origin・量化などの固定属性の一致は、その領域の既存規則で別途証明する。型の同一性前提から暗黙の条件を作らない。未証明の構造を結び付ける前提は認めない。 |
| 射影 | 同一な主語・引数による同じ射影は同一。射影結果の同一性から主語・引数の同一性は導かない。 |
| 循環 | 型を構成する成分への真部分関係と、射影の主語への依存を区別する。前者の循環だけを無限型として拒否する。 |

`is` の構文、宣言ごとの主語の制限、Contract の証拠供給、関連型推論の証拠源は維持する。案 G の「記述方向をそのまま書き換え規則にする」「宣言時に一度ですべて完備化する」「射影経由の自己参照を一律に Resource とする」は採用しない。

## 3. 新しい仕様

### 3.1. 同一性と前提

`A ≡ B` は本書の説明用記号であり、新しい構文ではない。ソースでは、完全な型を右辺に取る `A is B` を使う。構文上の主語の許可範囲は各宣言の規則に従う。

型同一性は対称である。入力の左右、前提の記述順、問い合わせ順は意味を変えない。型パラメーターはその宣言に束縛された型を表し、任意の型に一致するパターンではない。

同一性の根拠は、利用可能な正の型同一性前提と、関連型の明示指定・利用可能な完了済み束縛である。Contract から許された規則で導かれる前提も含む。`and` からは各前提を取り出せるが、`or` の片側を選んだり、否定された同一性を正の同一性へ分解したりしない。

型同一性は、これらの根拠を含み、反射・対称・推移、型内部の置換、および §3.3 の構造分解で閉じた最小の関係とする。矛盾があれば Error とし、矛盾から任意の同一性を導かない。

### 3.2. 型の形と構成要素

比較前に、別名、括弧、冗長な `owner/`、利用可能な完了済み射影を既存の規則で解釈する。名前の綴りではなく、束縛先の宣言を使う。

型の構造は、**型形式、固定属性、対応する型成分**で比較する。固定属性には、宣言の同一性、個数、長さ、Semantics、Origin、量化・契約条件など、型成分以外の情報を含める。

| 型形式 | 固定属性 | 分解する型成分 |
| --- | --- | --- |
| 原始型・Never | 型そのものの同一性 | なし。値の有無や表現サイズでは同一視しない。 |
| struct・enum・名前付きライブラリー型 | 宣言、および外側宣言を含む非型引数・Origin 束縛 | 自身と外側宣言の型引数。未使用の引数も含む。 |
| タプル | 要素数。Unit は要素数 0 のタプル | 各要素の完全な型 |
| 固定配列 | 既存規則で正規化された長さ | 要素の完全な型 |
| 共通 Function Type | パラメーター数、task スロット、Origin の量化・関係などの契約構造 | 対応するパラメーター型と結果型 |
| Function Item・具体的なクロージャー | 関数宣言または式の出現位置、および実体化の非型情報 | 同一性に含まれる実体化の型引数 |
| 確定した Semantics の層 | Semantics の種類、必要な外側 Origin。対象がビューならその宣言・束縛構造 | 参照先・対象の型成分。対象が実行時 Contract ビューなら、対応する型引数・公開関連型束縛 |

`Wrapping<T>` のような型引数を持つ名前付き型は、Scalar でも名前付き型の行に従う。名義型のフィールド、クロージャーのキャプチャー、メソッド集合は、この分解の対象ではない。異なる宣言の型を同じ構造や同じレイアウトから同一視しない。Function Item・具体的なクロージャーと共通 Function Type の間の変換も、同一性ではない。

型パラメーター、`Self`、未解決の関連型射影・ペアの対象は、それだけでは上表の構造を持たない。未確定のペア適用 `s/U` も、確定した Semantics の層とみなさない。既存の束縛・許容集合・Semantics ごとの規則で形が確定した場合に、その形を比較する。`owner/U` が `U` に消えることを無視して、任意の `s/U` を単射な型形式とは扱わない。

### 3.3. 構造分解と不一致

型形式と固定属性が同一と証明された構造を `F<…>` と書く。このとき、

```text
F<A1, …, An> ≡ F<B1, …, Bn>  ⇔  各 i について Ai ≡ Bi
```

右から左は型内部の置換、左から右が新しい分解則である。推移的に得た同一性や関連型の束縛にも、同じ規則を適用する。

型形式・固定属性の確定した不一致、または対応する型成分の Refuted な同一性は、全体の同一性を Refuted にする。その二つを同じ型とする前提が利用可能なら、前提の矛盾として Error にする。

同じ型に複数の束縛があっても、最初や最後の束縛を優先しない。すべてを同じ関係に含め、分解と矛盾の規則を適用する。

### 3.4. 固定属性とスコープの境界

型成分の分解は、長さの方程式、Origin の関係、Semantics の許容集合を新たに解く規則ではない。構造を結び付ける前提の固定属性は、その型同一性に直接にも間接にも依存せず、宣言の利用可能な前提と各領域の既存規則で同一と証明する。

| 比較 | 扱い |
| --- | --- |
| `[4 of U]` と `[(2 + 2) of i32]` | 長さは同一。型同一性から `U ≡ i32` を導く。 |
| `[N of U]` と `[M of i32]` | 正規化で長さが一致しなければ、型同一性前提から `N = M` を作らない。その一致が未証明のままなら、両者を結ぶ前提は未証明要件による宣言の誤り。 |
| `ref/U during a` と `ref/i32 during b` | `a` と `b` の同一性が別途証明されれば分解する。必要なら `origin a == b` を明記する。一方向の `outlives` だけでは同一でない。 |
| 共通 Function Type の Origin | 対応する量化された束縛変数を位置で対応付け、固定 Origin と区別する。束縛変数の改名は同一性を変えない。 |

固定属性の一致が未証明であることは、不一致の証明ではない。一般の問い合わせでは Unknown、必須の前提の妥当性確認では未証明要件として扱う。判定には宣言の独立した全前提を使い、記述順の途中で拒否しない。

分解で得る型は、結び付けるパラメーターのスコープで有効でなければならない。Function Type 内で束縛された Origin を、外側の型パラメーターへ逃がす同一性は認めない。Function Type 全体を束縛し、その内部に量化を保つことはできる。

### 3.5. 射影

関連型射影の同一性は、主語、関連型の宣言、束縛済みの定義元 Contract、必要な Origin 引数に基づく。継承経路や同じ名前だけで別の関連型を同一視しない。

- 同一な主語・引数に同じ射影を適用した結果は同一である。
- 射影結果が同一でも、主語、Contract の型引数、Origin 引数の同一性は導かない。
- 射影の束縛が分かれば結果の型を使う。その結果が上表の構造なら、通常の構造分解に参加する。

関連型束縛の利用には、その適合経路の前提が必要である。条件付き適合の束縛を別のスコープへ無条件に持ち出さない。ペアの対象も、対象の同一性から元の完全な型や外側 Semantics を逆算しない。

### 3.6. 循環

型の真部分は、§3.2 の確定した型構造の型成分を一段以上たどって得る型とする。同一性による置換も考慮し、ある型が自分の真部分と同一になる前提は宣言の誤りとする。

射影の主語・引数をたどること、名義型のフィールドを展開することは、この真部分関係に含めない。未確定のペア適用も、必ず層を追加するとは扱わない。

従って、`T ≡ U ≡ T` は同一視、`T ≡ Option<T>` は不正な循環、`T ≡ T.(C).X` はそれ自体では不正な循環でない。`T ≡ Option<T.(C).X>` も、射影の主語に `T` があることだけでは拒否しない。さらに `T.(C).X ≡ T` が得られれば拒否する。

これは型の同一性の規則である。再帰する名義型のレイアウト制約、Contract の再帰、証拠が自分自身に依存することの制限は、それぞれの既存規則に従う。

### 3.7. 証拠供給と推論

同一性の導出は利用可能な前提に相対的である。Contract から必要な前提を導く規則を維持し、問い合わせで初めて必要となった深い射影にも適用する。宣言時に有限個の射影を列挙した範囲だけを意味としない。

同一な型についての Contract 事実は、その根拠が使えるスコープで利用できる。型が閉じていることを理由に証拠の利用を禁止せず、新たな適合宣言やメンバー宣言を作ることもない。名前探索と適合の利用は既存規則に従う。

関連型推論の凍結前提には、本案の分解による帰結を含める。ただし、現在の定義で推論された値、またはその値に依存する証拠を、現在の定義の推論へ戻さない。他の定義の値を使える条件も維持する。

結果型からの証拠抽出、実装の識別、呼出しの型引数推論は、それぞれの規則を維持する。例えば、本案が Function Type の同一性を分解できても、関連型推論が未束縛位置を探すために Function Type の内部へ入れるようにはならない。

### 3.8. 判定と診断

| 状況 | 結果 |
| --- | --- |
| 利用可能な根拠と本案の規則で同一 | Proven |
| 明示された否定、または構造上の不一致で同一性を否定 | Refuted |
| どちらも証明されない | Unknown。要求される箇所では未証明要件の誤り。 |
| 正負の根拠の衝突、構造の矛盾、不正な真部分循環 | Error。宣言の矛盾は Language 診断。 |
| 解析が実装の上限に到達 | Resource。Unknown・Refuted・不正な型の証明には読み替えない。 |

型の同一性そのものを変換、サブタイプ、Copy、適合とみなさない。同一な型の既知の能力は、通常の証拠供給で利用する。未解決の射影や異なる型パラメーターを、見た目が異なるだけで Refuted にしない。否定された複合型の同一性から、どの型成分が異なるかを選ぶこともしない。

矛盾の診断は、矛盾した構造・循環と、それを結び付けた元の前提の位置を示す。固定属性の未証明は不足した要件、Resource は到達した上限と対象位置を区別して示す。結果は対象のソースと設定に関連付ける。規則の表現や代表の選び方を、診断の意味にしない。

## 4. 例示コード

以下は変更後の仕様例であり、現行コンパイラーでの実行結果ではない。各例は独立して読む。

### 4.1. 同じ構造の型引数を分解する

```kimi
func same<T, U>(value: U) -> i32
    T is Option<U>
    T is Option<i32>
    return value // 新仕様: U は i32。現行の同一性前提では導けない。

let n = same<Option<i32>, i32>(42)
```

### 4.2. 異なる構造は、未束縛でも矛盾する

```kimi
func conflict<T, U>(value: T) -> i32
    T is Option<U>
    T is Array<U> // 宣言の誤り: 異なる名義型を同一視している。
    return 0
```

### 4.3. タプル・配列・Function Type に同じ分解則を使う

```kimi
func tuplePart<T, U>(value: U) -> i32
    T is (U, bool)
    T is (i32, bool)
    return value

func arrayPart<T, U>(value: U) -> i32
    T is [4 of U]
    T is [(2 + 2) of i32]
    return value

func functionPart<F, U>(value: U) -> i32
    F is (U) -> U
    F is (i32) -> i32
    return value
```

### 4.4. 射影結果から主語を逆算しない

```kimi
contract Source
    associate Item

func independent<T, U>(left: T, right: U) -> i32
    T is Source
    U is Source
    T.(Source).Item is U.(Source).Item
    return 0 // Item は同一だが、T と U の同一性は導かれない。
```

### 4.5. 同一視と真部分循環を区別する

```kimi
func aliases<T, U>(value: T) -> U
    T is U
    U is T
    return value@move // 有効。同一性前提の左右で結果は変わらない。

func cyclic<T, U>(value: T) -> i32
    T is Option<U>
    U is Option<T> // 宣言の誤り: T が自分自身を真部分として含む。
    return 0
```

### 4.6. 射影の主語への依存は、それだけでは無限型でない

```kimi
contract HasItem
    associate Item

struct Box<E>
    Self is HasItem
    associate HasItem.Item is E
    var value: E

func reconstructed<T>(value: T) -> T
    T is HasItem
    T is Box<T.(HasItem).Item>
    return value@move
```

例えば `T = Box<i32>` はこの前提を満たす。`T.(HasItem).Item = i32` であり、型の構造に `T` 自身を含める必要はない。

### 4.7. Origin の一致は明示した前提から証明する

```kimi
func sameReferent<T, U>(x: ref/U during a, y: ref/i32 during b) -> i32
    T is ref/U during a
    T is ref/i32 during b
    origin a == b
    return 0 // 固定属性が一致するため、U は i32。
```

`origin a == b` を除き、ほかにも一致の根拠がなければ、二つの構造を結ぶ前提は未証明要件による宣言の誤りになる。型同一性から暗黙に `a == b` を追加しない。

## 5. Kimigayo Principles との対応

| 原則 | 本案の判断 |
| --- | --- |
| One Concept, One Canonical Form | 型同一性を一つの関係として扱い、直接の前提・推移的な同一性・関連型束縛へ同じ分解則を使う。 |
| Local Reasoning | 宣言の前提と型の構造から帰結を読める。長さや Origin の暗黙条件を増やさず、射影の逆算や型の探索をしない。 |
| Explicit Semantics | 同一性、変換、適合、推論、真部分循環、解析未完了を区別する。 |
| Compiler Server Protocol | 結論だけでなく、元の前提、矛盾・未証明・上限の別、対象ソースと設定を説明できる意味を保つ。 |

本案が簡素化するのは、型全体を同一視しながら対応する型成分を区別する規則である。証拠の依存関係や Contract の導出を省略する変更ではなく、実装量や性能の改善を保証するものでもない。
