# LSP Hover：仕様・実装計画

日付：2026-10-06。状態：方針決定済み。正式仕様への取り込み・本計画の実装と検証は未実施。

## 1. 位置付けと目的

本書は、LSP Hoverの仕様と実装計画を一体で定める。本書で追加・変更する事項は、[SPEC.md](../../docs/SPEC.md)およびその参照先より優先する。本書が変更しない事項には既存仕様を適用する。この優先関係は本書の対象範囲に限り、他の未完了提案を暗黙に採用しない。

今回の成果物は本書だけとし、`docs/SPEC.md`、その参照先、実装、既存の計画・状態・取り込み記録は変更しない。正式仕様への取り込みは別作業とし、本計画の実装開始条件にはしない。

目的は、型・Property・関数について、その場所で確定した宣言・契約・説明を素早く確認できるようにすることである。

- 型には宣言、Copy判定、コメントを表示する。Property・関数には宣言とコメントを表示する。
- 意味情報はコンパイラの判定を使い、Hover側で名前解決・型推論・Copy判定を再実装しない。
- 確定した事実、未確定の事項、説明文を区別する。コメントは言語上の保証を増やさない。
- ソースと設定が一致する不変の結果から応答し、将来のCSPや他の表示にも再利用できる形にする。

追加するのはHoverの対象・表示・応答条件と、そのための内部情報である。言語構文、アクセス制御、所有権、Copyの成立条件、呼び出し選択、コメントの対応付け規則は変更しない。

## 2. Hoverの対象と表示

### 2.1. 初版の範囲

開いていて同期の取れた`file:`の`.kimi`文書について、次の宣言箇所と解決済みの参照箇所を対象にする。

| 対象 | 含めるもの | 基本表示 |
| --- | --- | --- |
| 型 | struct、enum、組み込み型、型パラメーター、関連型、型の具体化 | 宣言または型表記、関連制約、Copy、コメント |
| Contract | Contract名とその参照 | 宣言、要求する契約とeffect、コメント。Contract自体にはCopy欄を付けない |
| Property | `let`・`var`・`computed`、ContractのProperty要求 | 宣言、型、アクセサの契約、コメント |
| 関数 | 名前付き関数、メンバー関数、Contract要求、`init`・`drop`、明示特殊化 | シグネチャ、制約、effect、コメント |

依存先とKimiライブラリの宣言も、参照が解決済みなら同じ規則で扱う。生成宣言は、確定した表示情報だけを使い、存在しない物理ファイルや宣言位置を作らない。

ローカル変数・通常の引数・enum Case・group・Origin名・Semantics名の専用Hover、任意の式の型表示、補完、Signature Help、定義への移動、コメント中のDocument Linkは初版の対象外とする。ただし、既存のCallable呼び出しのeffect表示は維持する。通常の引数やローカル変数の専用Hoverがなくても、Callable呼び出しの呼出対象にはその契約とeffectを表示する。

### 2.2. 位置と対象の選択

1. 位置と範囲はLSPのUTF-16座標とし、範囲は開始を含み終端を含まない。行末を超える文字位置は行末に丸める。存在しない行や対象のない位置は`null`とする。不正な形式の要求はプロトコルエラーとして扱う。
2. 宣言名・参照名・`init`・`drop`の書かれたトークンを基本範囲とする。`Container<T>`では、`Container`は具体化した外側の型、`T`は内側の型を表す。
3. 型修飾子を含む型構文では、小さい対象を優先する。例えば`ref/T`の`T`上では`T`、`ref`上では完全な`ref/T`を扱う。各表示にはCopy判定の対象型を明記する。
4. 宣言・使用箇所の型・effectは、選択した同じ対象の一つのHoverにまとめる。呼び出し式全体を候補範囲にして、引数や空白へ呼出対象の情報を広げない。
5. オーバーロードはBindingが選択した宣言を使う。複数候補、未解決、回復処理で推測した対象、同順位で異なる対象が残る場合は`null`とする。

型修飾子以外の一般キーワード、区切り、コメント本文に新しいHoverは設けない。`range`は要求された文書内で要求位置を含む対象範囲とする。参照上のHoverに宣言元の範囲を返さない。

### 2.3. 宣言と使用箇所の情報

表示順は、所属先と対象種別、元宣言、使用箇所で確定した補足、Copy・effect、コメントとする。空の項目は表示しない。装飾や見出しの文言は固定APIとしないが、事実の区別と順序を保つ。

- 元宣言は本体を除く正規化したヘッダとする。修飾子、型・長さ引数、引数名、受け手、`task;`、取得Semantics、結果区分・型、Origin、制約など、公開契約に必要な情報を保持する。
- 関数の既定引数は存在を保持する。表示上限で式を省略するときは、省略したことを明示する。関数本体、Propertyの初期化式、アクセサ本体は表示しない。
- 型の全メンバー一覧は展開しない。Propertyは宣言された操作とアクセス条件を示し、`var`だけを根拠に「この場所で書込可能」とは表示しない。個別の使用可否を補足する場合は確認済みの事実に限る。
- ジェネリックの元宣言を書き換えず、確定した型・長さ引数や呼び出しシグネチャを別項目で補足する。無関係な内部型名や未確定の代入を出さない。
- `i32`などソース宣言のない型は、正規の型表記と「組み込み型」を表示する。架空の宣言・位置・コメントは作らない。

表示用フォーマッターは宣言ヘッダと意味情報を共通に扱い、構文全体の`ToString()`やソース行の切り出しを完成形として使わない。省略された結果型などを補う場合も、元の表記とコンパイラの確定情報を区別する。

### 2.4. Copyとeffect

Copyは、表示対象の完全な型と当該箇所の制約を渡して、既存の`Binding.ProveCopy(type, context)`から取得する。宣言箇所では宣言の文脈、使用箇所では使用側の文脈を使う。

| 証明結果 | 表示 |
| --- | --- |
| `Proven` | `Copy` |
| `Refuted` | `Non-Copy` |
| `Unknown` | `Copy: この文脈では未確定` |
| `Error` | `Copy: 判定できません`。根拠が成立しないことを保証の否定と取り違えない |

Contract自体など判定対象外のものには欄を設けない。未解決の型には証明を要求しない。無効な制約・回復ノード・未検査の呼び出しから保証を発行しない。型パラメーターにCopyの証明がないことをNon-Copyと解釈しない。

effectは[§8.4.10.6–7](../../docs/spec/08-generics-constraints-and-contracts.md#84106-diagnostics-and-recovery)の要求を満たす。

- Contractが宣言するboundを表示する。
- requirement呼び出しでは利用可能なbound、各boundを宣言したすべてのContract、証明に寄与したpremiseを表示する。
- Callable呼び出しでは現在のeffect表示を維持し、寄与するすべてのpremiseを残す。
- 同じ対象の宣言表示と統合する。内部実装や特殊化の本文から呼び出し契約を強めない。

### 2.5. 例

```kimi
/// 値を複製して返す。
///
/// - T: Copy可能な値の型。
/// - value: 複製する値。
/// - return: 複製した値。
/// - note: [利用例](guide.md#copy)を参照。
public func duplicate<T>(value: T) -> T
    T is Copy
    return value
```

`duplicate`の宣言上では本体を除くシグネチャ・制約・コメントを表示する。`T`上では型パラメーターであること、制約、`Copy`、親宣言の`T`項目を表示する。`T = i32`と確定した呼び出しでは、元宣言にその具体化情報を補足する。`guide.md`は呼び出し側ではなく、このコメントの宣言元から解決する。

## 3. コメントとリンク

### 3.1. コメントの取得範囲

[§2.3](../../docs/spec/02-source-and-lexical-structure.md#23-whitespace-and-comments)の収集・対応付け・選択規則を維持し、次の参照範囲をHoverに適用する。

| 場所 | 取得する説明 |
| --- | --- |
| 宣言箇所 | その宣言自身の選択済みコメント。アクセスレベルを問わない |
| 解決済みの参照 | その場所から正当に参照できる対象宣言のコメント。`publicOnly`を一律適用しない |
| 通常の呼び出し・特殊化された呼び出し | 呼び出し契約を定める元宣言のコメント |
| 特殊化の宣言箇所 | 特殊化自身のコメントを「実装上の補足」として表示。元契約を示す場合は出典を明記し、別項目にする |
| 型パラメーター | 親宣言の分類済みパラメーター項目のうち、その型パラメーターを一意に指すものを出典付きで表示。該当しなければ省略 |

継承・実装関係の別宣言から説明を暗黙にコピーしない。オーバーロード間で共有しない。分割されたgroup・structのコメントは、断片の出典を保持し、既存の論理宣言順で独立して解析・表示する。

コメントなし、明示的に空、対応付け保留を内部では区別する。構文エラーがあるSourceDocumentは、既存仕様どおり文書全体の対応付けを保留する。除外構文のコメントを採用したり、古いコメントや近隣のコメントで補ったりしない。

### 3.2. 描画と省略

- 原則としてコメント全体を表示する。概要だけの表示に切り替えて本文の条件を隠さない。
- [Documentation Markdown profile](../../docs/spec/documentation-markdown.md)の解析済み構造から、Hover用Markdownまたはplaintextを生成する。原文の直接転送やHTMLへの変換後の流用は行わない。
- 未採用の構文がエディタで画像・HTML・参照リンク等として再解釈されないようにテキストをエスケープする。コードはコードとして保持し、コードフェンス・リンク先・ラベルをそれぞれ正しく符号化する。
- 見出しは宣言より下位として表示し、相対階層を保つ。独立断片は個別に描画してから区切って配置する。型パラメーター項目の抽出にも、解析済み構造を使う。
- plaintextでは構造を読み取れる改行と字下げを使い、有効なリンクはラベルとURLを併記する。
- 表示上限では、完成したブロックの境界でコメントを省略し、その旨を表示する。リンク・コードブロックを途中で切らない。深度・処理量の上限では、不完全な解析結果を公開せず、コメント処理を中断した旨と確定済みの宣言情報を返す。
- シグネチャの契約部分、Copyの結果、effectとその根拠を、全体を示したように見せて切り詰めない。これらを保持した応答自体が上限に収まらなければ`null`とし、理由をサーバーログに記録する。

コメントの問題はコンパイラ診断や言語の受理結果を変えない。新しい文書lintは追加しない。内部障害はログに記録し、コメントだけの障害なら確定済みの表示を残す。文書なしとは取り違えない。

### 3.3. リンクの解決

既存のURL検査・論理パス解決を共通利用し、HTMLの出力先とは別に、エディタ向けの対応付けを行う。

| リンク | 初版の扱い |
| --- | --- |
| `http:`・`https:`・`mailto:` | 既存の形式検査を通ったURLをリンクとして出力 |
| `guide.md`・`guide.md#section`等 | 宣言元プロジェクトの論理ソース名から解決し、対応する絶対`file:` URIを生成 |
| 空のリンク先・`?q`・`#section`・`/guide.md`等 | 表示ページ・出力URLルートの対応付けを初版では持たないため、リンク化せずラベルを表示 |
| 生成ソース等で基準のない相対パス | 未解決としてラベルを表示 |
| `//host/path`、未許可のscheme、不正な宛先 | リンク化しない。通常リンクは装飾付きラベル、autolinkは山括弧を含む元の表記を残す |

パス・query・fragmentを分離し、パス成分を一度だけUTF-8復号する。プロジェクトルートを越える`..`、復号された区切り・制御文字、不正なエンコードを拒否する。URI化ではパスの`#`・`%`等をデータとして符号化し、query・fragmentとは混ぜない。

`file:`は、サーバーがソース相対リンクから生成した結果に限って許可する。コメントに直接書かれた任意の`file:`・`command:`等を許可せず、VS Codeの信頼済みMarkdownやコマンド実行を要求しない。

解決のためにリンク先ファイルの内容・存在やネットワークを調べない。クリック可能であることは、ファイルの存在や見出しへの移動成功の証明ではない。fragmentを保持し、実際の移動はクライアントの対応範囲として検証・記録する。コード名の自動リンク化、新しい`kimi:`記法、文書ビューアーは追加しない。

## 4. LSP応答と整合性

### 4.1. プロトコル

`initialize`で`hoverProvider: true`を宣言し、`textDocument/hover`へ`Hover | null`を返す。`contents`は`MarkupContent`とし、`textDocument.hover.contentFormat`の順序から最初に対応する形式を選ぶ。省略・空・対応形式なしの場合はplaintextを使う。Markdownの宣言コードには言語ID `kimi`を付ける。[LSP Hover](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/language/hover.md)と[MarkupContent](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/markupContent.md)に従う。

一般Hoverとeffect Hoverの独立した競合するproviderは作らない。エディタ拡張で意味情報を再生成しない。

### 4.2. 鮮度と設定間の一致

1. [§23.4](../../docs/spec/23-compiler-services.md#234-language-server-protocol)の入力スナップショット、依存入力、必須単位、contributors、失効・保持・採用・解放の規則を使う。
2. 要求時と送信直前に、文書の同期、現在の文書世代、必要なcontributorsと採用結果、その有効性を確認する。無効・held・未確立な結果や`Blocked`・`Faulted`から情報を返さない。対象のcontributorsがなければ`null`とする。
3. 複数のcontributorsがある場合は、全員が同じ対象について一致した情報を持つ場合だけ返す。一つだけ対象がない場合や、異なる宣言を指す場合も`null`とする。設定差の列挙や任意の一設定の採用は初版では行わない。
4. 一致は表示文字列だけで判定しない。宣言元とソース内容の識別、対象範囲、シグネチャ・具体化情報、Copy、effectと根拠、コメント断片と出典、解決したリンク先を比較する。Compilation間のオブジェクト参照やローカル連番を同一性としない。
5. 初回描画中に編集・設定結果の入替え・文書の閉鎖があれば、送信前に再確認して古い応答を捨てる。再利用可能性を確認できない要求には`null`を返し、その要求のための再チェック待ちや再試行はしない。

描画前はコメント断片の入力とリンク配置条件を比較し、その一致から同じ描画結果を保証できる場合は処理を共有する。文書versionだけに依存しない。依存先コメントの変更も、読み込んだソースの変更として失効させる。ディスク変更の検知限界は既存のLSP規則を引き継ぐ。

### 4.3. 編集途中・中断・資源制限

- チェック結果全体の`Accepted`を表示の必須条件にしない。別箇所にエラーがあっても、対象について確定した事実は表示する。未確定項目は省略し、Copy・effectの保証を補わない。
- 対象の決定自体ができなければ`null`。コメントの対応付け・処理だけができない場合は、その部分だけを省略または中断表示とする。
- Hover要求は同期的な再解析・再Bindingを開始せず、編集中の古い結果へフォールバックしない。現在のチェック待機時間は変更しない。
- 重い初回描画は状態管理ループを塞がない。並行処理数・待機数・入力量・解析深度・出力量・キャッシュ容量を有限にする。待機上限に達した新規の描画要求は`null`で完結させる。実装時に上限値を記録し、境界をテストする。
- Hover処理は要求の取消しとセッション終了に対応し、応答を重複させない。取消しはLSPの規則で完結させ、部分描画を返さない。チェック本体の中断規則は変更しない。
- 取消し・一時的な失敗を成功キャッシュとして保持しない。表示結果を経過時間だけで途中確定しない。入力上限など再現可能な制限結果は、理由付きで成功結果と区別する。

## 5. 実装構成

### 5.1. 責務とデータ

```text
既存のチェック
  → Binding・解析で確定した事実とコメント範囲を取得
  → Compilationを参照しない不変のHoverスナップショットを採用
  → 位置検索・設定間の一致確認
  → 必要なコメントだけを解析・描画
  → 状態管理側で再検証して応答
```

以下は内部モデルの役割であり、公開プロトコルやクラス名を追加する約束ではない。

| 情報 | 保持内容 |
| --- | --- |
| 文書の位置索引 | ソース範囲、対象宣言の参照、使用箇所の事実。同一位置の優先順位を確定済みにする |
| 宣言情報 | 種別、所属先、ソース由来の識別、ヘッダ、契約、コメント断片への参照 |
| 使用箇所の情報 | 確定した型・引数、Copy証明結果、effectと全根拠。宣言情報と分ける |
| コメント入力 | 不変な元テキストと範囲、対応付け状態、断片順、項目分類に必要な値、宣言元プロジェクト・論理パス |
| 描画キャッシュ | スナップショット、表示形式、リンク対応付け、上限を含む描画条件に結び付いた完成結果 |

`Compilation`・`Binding`・`Koto`・可変な`BindingSymbol`をLSP側に保持しない。`DocumentationComment`は宣言ノードを参照するため、そのまま結果へ渡さない。出典・項目分類に必要な値をチェック中に切り離し、Markdown構文木は要求時に生成する。分類用の値には全パラメーター名前空間と受け手の除外情報を含め、`self`という綴りだけで判定しない。

### 5.2. 既存の入口と追加作業

| 入口 | 作業 |
| --- | --- |
| `Checking/CheckContext.cs`、`SolutionAndProject/Project.cs` | LSP用の収集要求をCompilation生成時に渡し、ライブラリ・依存先を含むソース解析前に`CollectDocumentation`を有効化。普通のCLIコンパイルには追加しない |
| `Compiler/Parsing`、`Compiler/Binding` | 宣言名・使用箇所の正確な範囲を保持し、選択済み宣言・型・呼び出しを索引へ射影。足りない範囲はParserで保持し、文字列検索で推測しない |
| `Binding.Capabilities.cs`、`Binding.EffectHover.cs` | Copyの既存証明を利用。Callable表示を共通情報へ移し、Contract・requirement側のeffect検査情報も射影 |
| `Binding.Documentation.cs`、`Compiler/Documentation` | 宣言とコメントの対応を一度索引化し、全コメントの繰返し走査を避ける。切り離した入力、Hover向けMarkdown/plaintext、エディタ向けリンク配置を追加 |
| `Checking/CheckService.cs`、`CheckResult.cs` | Compilationの解放前に不変情報を生成。診断とHoverの結果を区別し、CLIの診断JSONを変更しない |
| `Lsp/LspSession.cs`、`Json.cs`、`LspJsonContext.cs`、`LspMessageReader.cs` | 形式交渉、位置検索、比較、非同期描画、`$/cancelRequest`、応答直前の検証を接続 |
| `src/kimi-ext` | 標準LanguageClient経由の表示・`kimi`コード・リンクを実機確認。意味解決用の独自Hoverは追加しない |

現在の`OnHover`は単一の状態管理ループ上で同期実行されるため、そこへ直接Markdown解析を追加しない。非同期処理は切り離した不変入力だけを読み、完了を状態管理側へ返す。共有キャッシュの成功結果は完成後に一度だけ公開し、一要求の取消しで他要求の利用を壊さない。

### 5.3. 費用と寿命

- 位置索引は文書別の整列済み範囲などで検索し、要求ごとに全AST・全宣言を走査しない。
- 同じ宣言・コメントを使用箇所ごとに複製しない。チェック時は範囲と確定事実を保持し、全文抽出・Markdown解析・描画は要求時に行う。
- 要求のなかったコメントの構文木を作らない。繰返しHoverでは同じ完成結果を再利用する。
- 初回・キャッシュ済み要求、編集、依存変更、文書閉鎖、単位の退役、セッション終了で、保持容量と解放を確認する。Compilationは保持しない。失効したスナップショットは新規要求に使わず、進行中ジョブの終了・取消しとキャッシュ退役に伴って解放し、保持量を有限にする。
- 収集無効時は既存の文書処理なしの費用を維持する。送信JSON等の必要な割り当てと、検索・再利用部分の割り当てを分けて測定する。
