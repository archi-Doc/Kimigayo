# 仕様変更案（最終版）：Option型の短縮表記、try式、明示的破棄と警告

## 1. 目的と適用範囲

`T?`、`try expr`、明示的破棄文 `_ = expr` を導入する。型・所有権・制御移動の既存規則を保ち、頻出する処理を短く、意図を明確に書けるようにする。

本案は、変更対象について **`SPEC.md`およびその参照先より優先する**。本案が変更しない規則は現行仕様に従う。本案の保存は、正式仕様の変更や実装完了を意味しない。

| 機能 | 意味 |
| --- | --- |
| `T?` | `::Kimi.Option<T>`と同一の型を表す糖衣構文 |
| `try expr` | Some／Okから1層だけ値を取得し、None／Errでは通常のreturnを行う式 |
| `_ = expr` | 式の結果を意図的に破棄する文 |
| try成功値の破棄警告 | tryの非Unit成功値を暗黙に捨てたことを通知する警告 |

文中の`T`、`U`、`E`は、Semantics・入れ子の型・Origin依存を含む完全な型を表す。例は独立しており、未定義の型・関数は説明用のAPIとする。

## 2. `T?`：Option型の短縮表記

### 2.1. 型の同一性

`T?`は常に、コンパイラが認識するKimiの`Option<T>`を表す。ローカルの名前、別名、同名のユーザー定義型によって意味は変わらない。

```text
T?   = ::Kimi.Option<T>
T??  = ::Kimi.Option<::Kimi.Option<T>>
```

`?`の適用は1回ごとに1層を追加し、平坦化しない。型引数の代入後も同じ規則に従う。`T?`と`Option<T>`はオーバーロード、制約、Copy／Owned、型Identity、レイアウトの判定で区別しない。

`T`には、`Option<T>`の型引数として有効な完全な型を指定する。独自の型形成条件は追加せず、借用・オブジェクトハンドルも既存規則に従って認める。

### 2.2. 構文と結合範囲

後置`?`はSemantics接頭辞より弱く、関数型の`->`より強く結合する。連続するSemantics接頭辞を含む直前の型全体を包み、型の内部をOption化するときは括弧で範囲を示す。関数型全体を包む場合も括弧を使う。連続する`??`は2個の`?`として解析し、専用の演算子にはしない。通常の空白・改行継続規則に従い、空白によって型の意味を変えない。

型構文の関係部分は次の形になる。`TypeAtom`には名前付き型、Unit、Tuple、固定配列、括弧で囲んだ型を含む。

```text
Type          := FunctionType | OptionalType
FunctionType  := FunctionParameters "->" Type
OptionalType  := SemanticsCore ("?")*
SemanticsCore := Semantics BorrowOrigin? "/" SemanticsCore | TypeAtom
```

`Type`の選択肢を解析する位置の`(...)`は、対応する`)`の次のトークンが`->`の場合に関数のパラメーターリストとして解析し、その内容を検査する。Semantics接頭辞の直後では、関数型全体を囲む括弧を引き続き要求する。空白・コメント・改行継続は既存規則に従う。`(A)? -> B`は不正であり、欠損可能な引数なら`(A?) -> B`、欠損可能な関数なら`((A) -> B)?`と書く。

| 表記 | 意味 |
| --- | --- |
| `ref/T?` | `Option<ref/T>` |
| `ref/(T?)` | `ref/Option<T>` |
| `obj/T?` | `Option<obj/T>` |
| `obj/(T?)` | `obj/Option<T>` |
| `ref/obj/T?` | `Option<ref/obj/T>` |
| `ref/(obj/T?)` | `ref/Option<obj/T>` |
| `ref/T??` | `Option<Option<ref/T>>` |
| `[N of T?]` | `[N of Option<T>]` |
| `[N of T]?` | `Option<[N of T]>` |
| `(T) -> U?` | `(T) -> Option<U>` |
| `((T) -> U)?` | `Option<(T) -> U>` |

`(ref/T)?`と`ref/T?`は同じ型である。`obj/Option<T>`はOptionを内容に持つオブジェクト、`Option<obj/T>`は欠損可能な所有ハンドルであり、異なる型である。前者をenumであることだけで不正にはしない。いずれも既存の対象型・所有権規則で適否を検査する。

通常の型式を受け付ける位置ではすべて使用できる。型注釈、戻り型、型引数、既存の型適合・変換先などに、表記だけを理由とする制限を設けない。一般の型式を受け付けない専用位置には追加せず、実行時の`x is Dog?`・`x is not Dog?`は不可とする。

`?`は完全な型の後置構文であり、`@Semantics`短縮形には付けられない。`x@ref?`・`x@owner?`は不可で、汎用Semanticsパラメーターにも同じ制限を適用する。`x@S?`の`S`は型として解決し、Semantics短縮形への再解釈は行わない。

```kimi
// x: i32。?は値を包まず、変換先の型だけをOptionにする。
x@i32?     // エラー：i32からOption<i32>への変換はない。
x@ref/i32? // エラー：変換先はOption<ref/i32>。借用とSome構築は行わない。
// saved: Option<ref{a}/i32>。
saved@ref{a}/i32? // 同じ完全な型の通常の取得。新しい借用ではない。
```

`?`は型のOption化に限定し、値の伝播は`try`に統一する。Case構築は既存の`.Some(...)`、`.None`、`Option<T>.Some(...)`などを使い、名前パスであるCase修飾子を任意の型式へ拡張する構文（`T?.Some(...)`など）は追加しない。

### 2.3. Originと既存の型規則

Origin注釈の結合先を構文で確定してからOptionへ展開し、既存の型形成・Origin省略・寿命規則を適用する。注釈を`?`の内外へ自動的に移さない。

```text
ref{a}/T?     = Option<ref{a}/T>
ref{a}/(T?)   = ref{a}/Option<T>
View<T>{v}?   = Option<View<T>{v}>
```

Origin binding setは名前付き型への接尾構文であるため、`T?{v}`は不可とする。外側のOptionのbinding setを命名する場合は`Option<T>{v}`と書く。内側の名前付き型の注釈は、上表のとおり`?`の前に置ける。

Optionが保持する借用・Origin・Loan依存をすべて維持する。表記を短くしても、寿命を延長したり依存を消したりしない。

ジェネリックなSemantics分解は展開後の完全な型に従う。例えば対`<s/T>`への引数が`ref{a}/i32?`なら、`s = owner`、`T = Option<ref{a}/i32>`となり、内側のOriginも保持する。tryはこのOptionから既存の借用payloadを取得するだけで、借用されたenumからの自動payload借用にはならない。

### 2.4. 構築と非変更事項

```kimi
let missing: i32? = .None
let present: i32? = .Some(42)
let nested: i32?? = .Some(.None)
let missingBorrow: ref{static}/i32? = .None
```

`null`をNoneとして使用できない。raw pointerの`null`は既存どおりであり、`unsafe/T? = Option<unsafe/T>`の`.None`と`.Some(null)`は異なる値である。

`T?`は、新しい暗黙包装・展開・変換、引数省略、自動初期化を追加しない。Option専用のレイアウトや割り当て保証も追加しない。

## 3. `try`式

### 3.1. 構文と適用対象

`try`を予約語とする。既存の前置演算子と同じ優先順位・右結合で解析し、オペランドは同じ論理式の中に必須とする。呼び出しに限らず、変数や括弧で囲んだ式にも適用できる。

本案では「try式」と、`tryGet`・`trySlice`・`tryInsert`などの「try接頭辞API」を区別する。予約は単語全体に適用するため、これらのAPI名は変わらない。API名が約束するのは個別に規定された回復可能な結果だけであり、呼び出し自体が失敗をreturnしたり、引数評価などのAbortをNone／Errへ変換したりするわけではない。

```kimi
try prepare() + 1       // (try prepare()) + 1
try try nested          // try (try nested)
(try prepare()).count   // 取り出した値のメンバー
try prepare().count     // try (prepare().count)
try savedResult
```

後置の呼び出し・メンバー選択などはtryより強く、`@`はtryより弱く結合する。変換してから取り出す場合は`try (expr@Target)`と書く。結合順位は評価順序を変更しない。

オペランドは、正規化後の外側が所有値としてのKimi `Option<T>`または`Result<T, E>`でなければならない。別名、括弧、冗長な`owner/`は既存規則で正規化する。同名または同じCase構造の独自enumには適用しない。

`Option<ref/T>`には適用できるが、`ref/Option<T>`、`uniq/Result<T, E>`、`obj/Option<T>`などの外側の借用・ハンドルは自動解除しない。型パラメータについても、定義側の既存の証拠で対象の型構造を確定できなければならない。

### 3.2. 評価と1層の取得

オペランドをValue Contextで一度だけ評価し、通常のCopy／Moveで取得する。そのCaseにより次の処理を行う。

| オペランド | 継続側 | 伝播側 | return先の型 |
| --- | --- | --- | --- |
| `Option<T>` | `.Some(value)`から`T`を取得 | `.None`をreturn | `Option<U>` |
| `Result<T, E>` | `.Ok(value)`から`T`を取得 | `.Err(error)`をreturn | `Result<U, F>`。`error`が通常の規則で`F`に適合すること |

`T`と`U`は一致する必要がない。伝播では元のenum全体を別の型へ転用せず、return先のenum型でNone／Errを構築する。既存の型適合・Origin短縮などは認めるが、try専用の変換探索やOption／Result間の変換は行わない。

正常結果は完全なpayload型`T`を持つ値であり、元のpayloadを指すPlaceではない。payloadが借用値なら、その既存の権限・依存を保持する。try自体は借用を生成しない。

```kimi
func prepareSize() -> Result<usize, PrepareError>
    let value = try prepare()
    return .Ok(value.count)
```

取得は現行§15.1.6のmatchと共通で、Placeなら全体をCopy／MoveしてSubject Placeを初期化し、既存の一時値なら余分な取得なしで受け渡す。

```kimi
// saved: Result<Resource, Error> はNon-Copy。
let value = try saved
// 成功して継続してもsaved全体はMoved。savedは再使用できない。
```

元のenumを消費せずに調べる場合は`match saved@ref`を使い、既存の共有読み取り・payload取得規則に従う。単に`match saved`へ書き換えても全体のMoveは避けられない。

取り出すのは常に1層だけである。

| 入力型 | tryの正常結果型 |
| --- | --- |
| `Option<Option<T>>` | `Option<T>` |
| `Result<Option<T>, E>` | `Option<T>` |
| `Option<Result<T, E>>` | `Result<T, E>` |

`Option<Option<T>>`の`.Some(.None)`は、内側のNoneを値として取り出して継続する。さらに伝播するなら別のtryを明示する。`try try expr`でも各tryを個別に検査し、OptionとResultの混在を自動解消しない。

### 3.3. return先と使用可能な場所

tryは、期待型なしでオペランド全体を取得し、Some／Okならpayloadを式の値とし、None／Errなら同じ位置の`return .None`／`return .Err(error)`を行うmatchに意味上対応する。これは文字列展開ではなく、二重取得や隠れたClosureを作らない。return先・境界と結果源の検査は既存規則に従い、オペランドへの期待型の逆伝播を禁止する境界は§3.4に従う。対象を先に決め、型が不適合でも外側の別の関数を探索しない。

- 匿名関数・Closure・ネストした関数は自身のreturn先を持つ。
- `do`、ループ、選択、`unsafe`はtry専用の伝播先を作らない。
- `defer`、既定引数式、検証メッセージなどから外への制御移動が禁止される場合、tryによる移動も禁止する。内部に宣言した別の関数の自身へのreturnは別に扱う。
- 戻り型が適合する`get`などでは使用できる。Applicationの`main`、`init`、`set`、`deinit`はUnitのreturn先しか持たないため、そのbodyからの伝播は不可。トップレベル実行bodyにはソース上のreturn先がなく、伝播できない。内部に宣言した別の関数は自身の規則で検査する。

失敗経路が実行されないと分かっていても、伝播先と型の検査を省略しない。未到達コード、既知のSome／Ok、最適化結果によって合法性を変えない。

成功結果のSome／Okへの自動包装は行わない。関数・getの正常結果は、通常どおり戻り型に適合させる。tryの存在だけで、戻り型省略時のUnitやbodyの結果規則を変えない。非Unitの戻り型を持つ単一項目bodyでは、tryの成功値がそのまま関数の正常結果になる。

```kimi
// save() -> Result<(), Error>。
func bad() -> Result<(), Error> => try save() // エラー：()はResultではない。
func wrapped() -> Result<(), Error> => .Ok(try save())
func forwarded() -> Result<(), Error> => save() // 成否をそのまま返す。
```

トップレベルの失敗処理は、戻り型を持つ関数へ処理をまとめ、呼び出し側で扱う。次の例ではErrorを表示する`report`を説明用APIとする。

```kimi
func run() -> Result<(), Error>
    try save() // save: () -> Result<(), Error>
    return .Ok(())

public func main()
    match run()
        .Ok(_) => ()
        .Err(let error) => report(error)
```

### 3.4. 型推論とNever

tryのオペランドは、**期待型なしのValue Context**で検査する。

1. 受け手、引数、明示的な型情報などから、オペランドの型と呼び出しを既存規則で解決する。
2. 解決したOption／Resultから成功payload型`T`を得る。try式に期待型があれば、この`T`との適合を既存規則で検査する。
3. 失敗側のreturnを検査する。後続の不適合でオペランドの推論・オーバーロード選択をやり直さない。

try式の期待型やreturn先の型を、オペランドの型引数・enumの種類・エラー型の推論へ逆伝播しない。型が不足・曖昧なら明示的な型引数や型付き中間値を要求する。

```kimi
// parse<T>() -> Result<T, ParseError>。引数などからTは決まらない。
let x: i64 = try parse()      // エラー：xの型からparseのTは推論しない。
let y: i64 = try parse<i64>() // 可：伝播先も適合する場合。
let pending: Result<i64, ParseError> = parse() // 通常の初期化では期待型を利用できる。
let z = try pending          // 可：オペランドの型は確定済み。
```

`try .None`や`try .Err(error)`も、enum型を決める期待型がないため不可。既知の失敗や結果の破棄を理由に型情報を省略しない。

§3.3の対応により、匿名関数の失敗returnは期待型を必要とする結果源であり、単独では戻り型候補を供給しない。明示的な戻り型、固定された期待シグネチャ、または独立に型が決まる他の結果源からreturn先を確定して検査し、決まらなければ注釈を求める。CaseはKimiの該当enumに固定する。結果源の収集は記述順に依存させず、成功側の自動包装や具体化でのbody再解釈は行わない。

```kimi
// getOpt() -> Option<i32>。fには外側からの期待シグネチャがない。
let f = func () => try getOpt() // エラー：正常結果から推論したi32へNoneを返せない。
let g = func () -> Option<i32> => .Some(try getOpt()) // 可：成功値も明示的に包む。
```

`Result<Never, E>`など、成功payload型がNeverのtryは正常値を生成しない。失敗側のreturn検査は行う。一方、オペランド自体がNeverで、Option／Resultの型構造を解決できない`try $abort(...)`などは型エラーとする。Neverを理由に対象型検査を免除しない。

### 3.5. 所有権、評価順序、cleanup

tryは既存の取得・Scope Exit規則を変更しない。

- Non-Copyのenumを取得すれば通常どおりMoveされる。元の変数を自動でNoneへ変更しない。
- 継続側はpayloadの責任を結果へ渡す。伝播側は返す値を確保してから、通常の順序で一時値・ローカル・deferを処理し、その完了後にreturn結果を届ける。
- 取得・移動したpayloadを元のenumから二重に破棄しない。保持するOrigin・Loanを消したり、ローカルへの借用をcleanup後へ逃がしたりしない。
- 呼び出し引数や集約値の構築途中で伝播した場合、残りの評価を省略し、取得済みの値を既存の中断・破棄順序で処理する。
- Abortは捕捉しない。オペランドが別の移動・発散・Abortを起こせばその動作に従い、cleanupが完了しなければ保留中のreturnも完了しない。

```kimi
consume(makeResource(), try prepare(), finish())
// prepareが失敗した場合、finishとconsumeは呼ばない。
// 取得済みの第1引数などは通常の中断規則でcleanupする。
```

## 4. 明示的破棄と名前の省略

### 4.1. 構文と名前

`_ = Expression`を専用の実行文とする。代入式ではなく、文を開始できる位置の予約トークン`_`と直後の`=`トークンで識別する。`==`は別トークンであり、名前解決による再解釈はしない。式としての入れ子・複合代入は不可。正常完了時にはUnitを供給し、右辺の継続・bodyには既存規則を適用する。

```kimi
_ = prepare()
if ready => _ = prepare()

consume(_ = prepare())  // エラー：式ではない
let x = (_ = prepare()) // エラー
_ += prepare()         // エラー
```

単独の`_`をNameではない予約トークンとする。識別子全体を読み取った後、綴りが正確に`_`の場合だけ予約扱いにする。`_value`などの名前、数値リテラル内の区切り`1_000`、コメント・文字列の内容には影響しない。`_`は構文で定めた指定の省略を示すが、省略対象と取得・破棄の作用は次の用途ごとに定義する。

| `_`を使用できる構文 | 役割・制限 |
| --- | --- |
| runtime matchのPattern | ワイルドカード |
| `#switch`の`#case _` | 最後のcatch-all。既存の配置・個数制限を維持 |
| 固定配列の要素型`[N of _]` | 初期化子のあるローカル型注釈だけで使える既存の推論指定 |
| `_ = expr` | 明示的破棄文 |
| `for`の束縛、またはそのTupleの要素 | 名前のない反復束縛。取得と寿命は名前付き束縛と同じ（§4.4） |

上記以外のソース構文で単独の`_`を使うことは構文エラーとする。`let _`、`var _`、匿名関数を含むパラメーター名、通常の宣言名・参照名には使えず、分解代入も追加しない。表の構文に該当しても、個別の配置制限や型推論の失敗は通常どおりエラーとする。

### 4.2. 評価と型検査

右辺を、型注釈のない`let`の初期化子と同じ、**期待型なしのValue Context**で検査する。名前・ローカル・第3の評価コンテキストは作らず、明示的破棄という意図を結果の破棄処理に記録する。

右辺を一度だけ評価し、通常のCopy／Moveで得た結果を文完了時の一時値cleanupで破棄する。寿命を延長しない。右辺が正常完了しなければ、結果の破棄や文の正常完了も発生しない。

```kimi
_ = resource // Non-CopyならMoveして破棄。元の値を残す構文ではない。
_ = .None    // 他に型情報がなければエラー。
_ = if condition => makeA() else => makeB()
// 分岐の値には、既存の共通結果型・適合規則が必要。
```

`expr`から`_ = expr`への変更は、警告だけを消す書換えではない。右辺がValue Contextになるため、選択の共通結果型やdoのUnit推論も検査する。ただし非Unitの値を要求するわけではなく、`_ = loop => exit`のようなUnitの結果も有効である。

### 4.3. 抑制する警告の範囲

明示的破棄は、**その結果を捨てたことに対する警告だけ**を抑制する。内部の別の破棄、型エラー、所有権エラー、その他の無関係な診断には影響しない。型検査・評価・Copy／Move・破棄は省略しない。

```kimi
_ = try prepare() // 失敗は伝播。成功値を明示的に破棄。
_ = prepare()     // Result全体を明示的に破棄。Errでも通常どおり継続。
_ = calculate()   // 通常の結果も明示的に破棄可能。
```

Result全体を意図的に無視することを認め、その結果の破棄警告を抑制する。エラーpayloadも通常の規則で破棄する。Abortを無視・捕捉する効果はない。

抑制は字句的な領域全体には適用しない。右辺内の別の文や関数bodyは独立して検査する。

```kimi
_ = do
    prepare() // 内部の暗黙破棄に対する警告は残る。
```

右辺のdo結果への抑制は、内部の`prepare()`の破棄には及ばない。意図しないUnit推論も、§5.4の優先順位で検査する。

### 4.4. `for`の名前のない束縛

`for`で束縛を書く位置、および既存のTuple束縛の各要素では、Nameの代わりに`_`を認める。一般のPatternやネストした分解構文へは拡張しない。名前を持つ束縛の重複は禁止し、`_`は何個でも指定できる。各`_`は独立した反復束縛であり、名前による参照・捕捉はできない。

```kimi
// n: isize、0 <= n。
for _ in (0..n).resolve(n) => tick()
for (key, _) in pairs => use(key)
for (_, _) in pairs => tick() // 各要素を取得する。Tupleの要素数検査は維持。
```

`0..n`自体はRangeであり反復できない。上例は既存のresolveでResolvedRangeを得る。名前の省略によってIterableの要件は変わらない。

束縛の形が取得・破棄の単位を決め、`_`はそれを変えない。`for _ in pairs`はTuple全体を1つの束縛として取得し、`for (_, _) in pairs`は各要素を左から右へ別々の束縛に取得する。前者のTuple要素も後者の束縛も末尾から破棄するため、これだけで要素の破棄順は変わらない（現行§16.2.1・§16.3.2）。

反復ごとのCopy／Moveは名前付き束縛と同じである。名前がないことを理由に取得を省略したり、body前に破棄したりしない。Result要素も束縛への取得であり、それだけでは暗黙破棄警告の対象にしない。

通常完了・continue・exit・returnでは、body内のローカルとdeferの後、名前付き／名前なしを含む束縛を逆順にcleanupする。次のnext呼び出し前にその反復のcleanupを完了し、外へ移動する場合は既存規則でiteratorもcleanupする。借用値の依存を保持し、借用先は破棄しない。Abort・発散は既存規則に従う。

これは反復束縛の名前だけを省く構文であり、`_ = expr`の文末破棄や、matchのワイルドカードによる取得省略とは異なる。通常の不要な初期化結果には`_ = expr`があるため、`let _`は追加しない。

## 5. 暗黙的な破棄への警告

### 5.1. 警告条件

既存のResult破棄警告を維持し、try成功値の破棄警告を追加する。

- **Resultの暗黙破棄**：KimiのResultをDiscard Contextで捨てる場合に警告する。成功型がUnitでも、Copy能力や実行時Caseによらず対象となる。
- **try成功値の暗黙破棄**：try式の結果自体がDiscard Contextにあり、正常結果がUnitと静的に証明できず、Neverでもない場合に警告する。
- Option全体の暗黙破棄には新しい型固有の警告を追加しない。既存の副作用のない値などの警告は別に適用する。

型が未解決・不正なら先に型エラーとして扱い、警告で代用しない。警告は合法なコードを禁止せず、実行・取得・破棄の意味を変えない。

### 5.2. Unitと使用・破棄の境界

`prepare()`は`Result<Data, E>`、`save()`は`Result<(), E>`を返すものとする。tryを含む例には適合するreturn先がある。

| 記述 | 動作 | この変更に関係する破棄警告 |
| --- | --- | --- |
| `prepare()` | 成否を含めて暗黙に破棄 | Result破棄 |
| `_ = prepare()` | 成否を含めて明示的に破棄 | なし |
| `try prepare()` | 失敗は伝播、Dataを暗黙に破棄 | try成功値の破棄 |
| `_ = try prepare()` | 失敗は伝播、Dataを明示的に破棄 | なし |
| `save()` | `Result<(), E>`全体を暗黙に破棄 | Result破棄 |
| `try save()` | 失敗は伝播、成功のUnitで継続 | なし |
| `_ = try save()` | 上記のUnitを明示的に破棄 | なし。`_ =`は省略可能 |

`Option<()>`から取得したUnitも警告対象外である。`Result<(), E>`自体はUnitではない。

既存のValue／Discard Contextの伝播だけを使い、値の由来を追跡しない。括弧はContextを変えず、Discard Contextの分岐bodyも通常どおり検査する。

```kimi
(try prepare())             // 警告
if ready => try prepare()   // 非Unitの成功値なら警告
consume(try prepare())      // tryの結果は引数として使用。try破棄警告なし
let value = try prepare()   // 初期化に使用。try破棄警告なし
(try getNumber()) + 1       // tryの結果は加算に使用。式全体は既存規則で検査
```

代入・引数・returnなどに使った後の不使用を、tryの警告として追跡しない。tryのオペランドは処理されているため、その外側のResultに未処理の破棄警告を出さない。ただし、取得したpayloadがさらにResultなら、その内側のResultの破棄警告が成立する。

### 5.3. ジェネリック定義

有効なジェネリック定義で成功型が型パラメータなどの場合、**定義時にUnitと証明できなければ警告する**。Neverと証明できる場合は除外する。ここでいう証明は既存の型正規化・制約の証拠によるもので、型の大きさや副作用の有無からUnitを推測しない。

```kimi
func process<T>(result: Result<T, Error>) -> Result<(), Error>
    try result // TがUnitとは証明できないため警告。
    return .Ok(())
```

意図的に捨てるなら`_ = try result`と書く。具体化した型、呼び出し元、最適化、実行経路によって、この定義側の診断を再判定したり重複報告したりしない。

### 5.4. 警告の優先順位

同じ値の同じ破棄箇所に複数の警告が成立するときは、次の上位1件だけを報告する。異なる箇所の警告は独立する。

1. 意図しないUnit推論。
2. Kimi Resultの破棄。tryで取得した内側のResultを含む。
3. 一般のtry成功値の破棄。
4. 既存の副作用のない値の破棄。

既存の警告の成立条件は、この優先順位だけを理由に広げない。明示的破棄の対象と内部の別の破棄を混同しない。例えば右辺内部の末尾式に成立した意図しないUnit推論は、外側の`_ =`では抑制しない。

### 5.5. 診断と修正案

try成功値の警告は「取り出した値を使用していない」と説明し、値の利用または`_ = try ...`を提案する。失敗を未処理だと説明しない。

Result破棄の診断では、次の順で適用可能な対処を案内する。

1. return先・所有権が適合するなら、tryで伝播し、成功値を使う。成功値も捨てる意図なら`_ = try ...`を示す。非Unitに対する裸のtryを、警告のない修正として提示しない。
2. matchで成否を処理する。
3. `_ = ...`で**エラーも含めて無視する**。

修正は自動適用せず、診断の対象となった破棄箇所に提示する。分岐内部の警告にはその分岐内の式への`_ =`を提案し、選択式全体を機械的に包まない。既存のbody形式・Context・型・所有権の適合を壊す案を有効なfix-itとして出さない。

`try X.m`などのメンバー列が原因のエラーでは、`try (X.m)`という結合を説明する。`X`がOption／Resultと分かる場合は`(try X).m`を候補として示せるが、payload上のメンバー存在・アクセス・伝播の適合が確認できない案を確定的な修正としない。診断のために無制限の別解探索は行わない。

関数（匿名関数を含む）・getで、正常結果またはtryの失敗returnが戻り型に適合しない場合は、失敗する経路と型を説明し、次の適用可能な候補を示す。

- 戻り型が未指定なら、意図したOption／Result型を注釈し、必要な成功経路を`.Some(...)`／`.Ok(...)`で明示的に包む。既に戻り型が決まっている場合も、成功値の包装を候補にできる。
- 正常結果がtry式そのもので、そのオペランドの完全な型が戻り型と同じなら、tryを外して成否をそのまま返す。

注釈だけで両経路が適合するとは限らない。tryの除去でも期待型の伝播境界が変わるため、型・呼び出しの解決、所有権、cleanupを含む修正後の適否を確認する。
